# QC 需求依据与最终类目覆盖对齐实施计划

2026 年 11 月 4 日，适用于 WebCollect 当前工作区。目标是使独立质检能说明本次使用了哪一版需求，并在正式交付全集缺少指定站点类目时拒绝定版。本次验收使用临时合成数据，生产状态保持 `STOPPED_BY_USER`。

## 1. 固定新工程的验收依据

- 逐字节比对当前 [需求澄清](../request/需求澄清记录.md)、[站点分类与轨迹口径](../request/站点分类与轨迹采集口径-20261102.md)、[原需求书](../request/web操作采集需求/需求书-Web浏览器自动化操作轨迹数据集.md)及附件 A/B。需求书和两份附件此前与安装资源一致，须修复的是 QC 仍绑定 10 月 28 日澄清、且缺少后续分类口径的问题。核对澄清引用的其他补充，凡实际决定本次 QC 行为的依据应能在安装包内核验。
- 以本地可安装的 QC 包为准，更新必要权威资源、来源标识、优先关系和 SHA-256。新澄清中的旧决定保留其时间与适用范围。同页不同目标由真实轨迹及四路去重判定；新工程停用“一页一次、三败停站”。控件语言跟随页面，简体中文叙述、原图审核和隐私要求继续执行。`wait`、`complete` 不计有效操作。
- 核查合约指纹、样本审核五项的独立版本、审核复用及封包调用链。需求资源变动可更新新合约指纹。仅当一项语义判据本身改变时，才调整该项规则版本并验证失效范围。历史收据按原绑定解释，保留旧次审核的 PASS、FAIL、待审与 UNKNOWN。已有 `NOT_SELECTED` 仍须有有效批次接纳收据才能计入合格。

入口见 [安装清单](../projects/quality-inspector/quality_inspector/contract-authority.json)、[合约指纹](../projects/quality-inspector/quality_inspector/contract.py)、[审核复用](../projects/quality-inspector/quality_inspector/semantic.py)。

## 2. 在正式全集检查必需类目

- 依据原需求书第 5 节与 11 月 2 日确认的覆盖规则，整理原文列出的 14 类与项目规范父类的对应关系。例如“医疗健康科普”对应“健康科普”，“图书影音榜单”对应“图书文化”。工程已有的额外分类如“知识文库”不自动成为客户必需的第 15 类。不根据页面用途或路径推测站点类目。
- 以 `inspect_set` 已解析的显式有效样本集合、版本选择和站点父类为分母。正式 `release.kind == 'formal'` 的 20 万条全集逐类检查，给出所需、已出现、缺席及对应样本数。缺一类即返回可定位的失败，单包定版和归档沿用既有的跨包报告绑定。别名只计一个父类，空值、未知或无法证实的类别不能补齐缺席项。
- 5,000 条质量批和累计集合仍分别核单类 ≤20%、短流程 ≤2% 与近重复涉及的唯一样本 ≤0.1%。小试、单样本、单个一万条成员包以及未声明正式全集的检查不单独要求全类齐备。保留单应用累计 500、最多三种视口、四路去重、20 包各 1 万条及其他现有门禁。

入口见 [累计检查](../projects/quality-inspector/quality_inspector/cumulative.py)、[正式交付配置](../projects/quality-inspector/quality_inspector/profiles.py)、[跨包绑定](../projects/quality-inspector/quality_inspector/delivery_scope.py)、[生产者父类](../projects/site-planner/site_planner/qualification.py)。

## 3. 离线验收与交接

| 验收面 | 必须有的证据 |
| --- | --- |
| 权威资源 | 源文件、安装资源、清单哈希一致。脱离仓库当前目录仍能加载。临时副本篡改或缺失时失败。 |
| 全集覆盖 | 五类各占 20% 时仍报缺失类目。14 个需求类目齐备时覆盖项通过。重复别名、无效版本、未知类目不能填缺。覆盖通过时，其他门禁仍可独立失败。 |
| 作用范围 | 5,000 条批次单类超过 20% 仍失败；缺少个别类目本身不会阻断小试或单个成员包。旧跨包报告或其他集合不能为当前正式全集定版。 |
| 既有语义与历史 | 用合成夹具覆盖同页不同目标、仍应拦截的重复、中文技术词和真实有效步。审核绑定按受影响项复用或失效；历史记录与未决状态保持原值。 |
| 正常入口 | 至少通过一个正式累计检查入口覆盖缺类反例，并验证封包消费该失败结果。全类正例可用纯内存分布与小型集成夹具组合，报告清楚夹具规模和实际经过的入口。 |

先记录工作区已有变更和本次涉及文件，再实现最小改动。用 [README 选定离线验证器](../README.md#离线验证) 跑涉及的测试模块及直接调用链，每次使用新证据目录，保留命令、测试数、失败和前后源码摘要，并执行 `git diff --check`。优先核对 `test_cumulative`、`test_profiles`、`test_semantic_reuse`、`test_delivery_release_binding` 及新增的定向反例；只使用由测试创建的临时数据。若共享工作区其他文件同步变动，应记录其范围，再用稳定源码完成最后一轮验证。

新会话负责代码、针对性用例、与改动直接相关的工程文档，以及验收结论。结论需给出实际修改位置、验证命令和结果、可复核的失败示例、证据位置和未验证边界。本轮不涉及消费者双基线实采、模板建设、真实 AI/真人审核或发布。凭据、既有运行产物和历史样本不作为测试输入。

## 4. 实施与离线验收结果（2026-11-04）

本计划的代码及相关工程文档已完成，最终定向离线验证 116 项全通过，源码和测试在验证前后摘要一致，`git diff --check` 通过。[具体改动、完整命令、正反例、失败修复与未验证边界](../verify_results/qc-alignment-20261104-audit/验收报告.md)；[最终源码绑定摘要](../verify_results/qc-alignment-20261104-r04/summary.json)。r01–r03 的失败日志保留。

金融类已按补充确认使用“金融股票交易”；仅有“金融股票交易等”描述时仍报缺类，不登记为别名。跨包同站明确等价的原文/父类合并统计，包内身份与原收据绑定继续逐项核验。实际 20 万条分布仅使用内存夹具，正常累计和下游封包使用小型临时合成包；没有真实采集、AI/真人审核或发布，生产保持停止。本次未提交或推送。

## 5. 第二次独立复核（2026-11-04）

重新对照需求和当前调用链，发现并修复三项问题：单包需求指纹缺失会跳过一致性比较、原单包 profile 变动未被封包重新核验、单包类目比例尚未合并明确别名。正式 14 类覆盖的作用范围未变，金融类末尾“等”仍不作为别名。机械分布政策进入合约指纹，五项样本审核版本保持；历史原件、FAIL、待审及 UNKNOWN 不改签。

最终隔离稳定源码 178 项全通过。当前工作区 70 个 QC 相关源码、测试及需求文件与快照一致、合约指纹一致；共享工作区其他会话造成的中间验证不稳定已单独留痕，没有回退其他改动。[独立复核报告、实际命令和修复前后反例](../verify_results/qc-independent-review-20261104-audit/独立复核报告.md) · [最终源码绑定摘要](../verify_results/qc-independent-review-20261104-r05/summary.json)。原 116 项验收记录保留为上一轮事实，不替代本次结论。生产未启动，无提交或推送。
