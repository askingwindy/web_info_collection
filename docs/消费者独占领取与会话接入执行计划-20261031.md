# 消费者执行计划 · 从独占领取到同会话交审

本计划交给维护消费者的工程 Agent。目标是在生产者离线的情况下，通过正式消费者入口从 SQLite 领取一个 V2 候选，在独立浏览器上下文中完成同一次轨迹的首次观察、身份绑定、ReAct 执行、封存和结果回写。该领域的交付物是可重入的消费链及证据。模型协议和质量判据见[规划采集 Agent 计划](规划采集Agent提示词与调用链执行计划-20261031.md)。可直接复制[消费者执行 prompt](消费者独占领取与会话接入执行Prompt-20261031.md)。

## 2. 唯一的默认 V2 执行路径

1. **从单机 worker 启动。** 一个进程即可顺序消费，需要并发时再启动同机进程，共读一个本地 SQLite 候选池。在领取前校验当前链路径与策略。新轮询用新的请求 ID，重放同一次领取沿用原 ID。有界试跑空池即退，持续模式按配置等待，达到原停止或预算上限即退出。
2. **领取后记录绑定，再打开页面。** 用已有领取事务和唯一约束冻结 claim，绑定原账、证据目录与 manifest。在现有 SQLite 事务中有条件地推进到“首次观察”，只有成功推进的进程打开浏览器。网络等待放在事务外。在途/UNKNOWN、站点 hold 和预算沿用现有检查。
3. **一次申请、一次入口导航、同一页面取得身份。** 由消费者拥有这次隔离的 BrowserContext、Page 和会话 ID，启动心跳。在原访问账预留这次导航，落请求身份，打开入口并取得同步的 PNG、树、捕获收据、实际落地 URL 和文档身份。验证整体应用/允许别名、页面公开性、地址范围及锚点，复用 `single_record.identity` 的证据规则。此时可以记录真实访问和失败，尚未登记正式 attempt 或执行业务动作。在预检与随后使用页面之间重新检查受影响状态，页面改变就获取新的同步观察。
4. **先冻结身份，再登记正式尝试。** 把实际锚点、整体应用、页角色、冻结目标及 claim 引用写入新计划，由原 RuntimeStore 执行身份、唯一性、并发和预算门禁。登记后通过 `attempt_id` 关联 claim 和此前的访问。执行入口必须能接收已经打开的 Page/上下文和首观察引用，让 `ReactSession` 接着使用。保持普通独立 URL 和旧 V1 入口原有的自建页面方式。这里不能第二次 `goto`、第二次打开入口、事后修改已冻结的任务或用搜索摘要伪造身份。身份不可证就停止并按阶段记账。
5. **每个新尝试一份新会话。** 不同尝试隔离页面、cookie、模型对话、观察 ID 与工具历史。同一尝试内保持这份浏览器状态和 GLM 历史，允许在授权范围内跟随真实点击打开的页。V2 entry 的 `requested_goal=null`，可选来源建议只作线索。V2 target 保留调用方原字段及参数。Agent 依据当前观察建立或调整 `working_goal`。旧 V1 原目标按旧协议解释。
6. **完成后按原收据回写。** 每次尝试保留原始执行及终态。未决、失败、仅原始封存、离线派生、生产保存分开记录。只有原生产库已提交 `collected_pending_review`，且 `saved_sample.json`、样本/取证文件 SHA 与同一 claim/attempt 均通过核验，才提交唯一有效的 candidate result 并置消费 `succeeded`。独立 QC 决定另行回写。上下文在成功、失败或取消时结束。

阶段可以用现有绑定和事件表达。第一处改动是把 `single_record.identity` 中的整体应用复用、真实锚点核验和页面身份构造抽给 V2 单会话使用，保留 V1 对旧观察合同的检查。第二处是让 V2 执行器接管已有上下文，明确谁负责关闭它。需要新增字段时显式版本化，保持旧库只读可解释。V2 来源在领取时冻结，给模型的工作输入应剔除租约 token、账本内部路径和无关候选元数据。

入口来源的 `category_hint` 可以未知。`_entry_hints` 的“综合”是显示回退值，正式集合需要有依据的整体应用类目，不能拿显示回退填满分类配额。

## 3. 中断、并发与交接

| 故障点 | worker 或对账器必须做到 |
| --- | --- |
| 领取后未打开页面，或已有同 ID 重放 | 检查原阶段和零派发证据，结束、重新对账或等待持有者。两个调用不得各自打开页面。 |
| 心跳失败、租约过期，或在动作派发前失去所有权 | 复用现有心跳停止后续派发，在结果提交时由原事务核验持有者。已在途的结果留在原账，动作和站点检查沿用现有执行入口。 |
| 会话被取消或进程中断 | 可捕获取消时封存已发生部分，标 `interrupted/UNKNOWN` 后传播取消。取消异步等待未必取消了线程内的 HTTP 请求，迟到响应仍须绑定原请求。硬崩溃按原派发日志恢复为未决。不能伪造末帧、拼接两段执行或重新发送在途动作。 |
| RuntimeStore 已保存，池尚未回写 | 用 `finish_or_reconcile` 核验原收据，幂等补池状态。重复对账时新增浏览器、模型、编号和样本数均为 0。 |
| 意外退出留有 queued/running 的计划或决策作业 | 核对原作业、请求、访问、尝试和 hold。重试检查须涵盖 `react-decision`。确认未派发的残留按版本化决定关闭或复用，保持原作业记录。 |

消费者负责入口、身份、租约和池回写。规划侧负责页面内的决策、工具、后加工和 QC。由领取候选的进程直接调用现有 Python 执行函数，传入 claim/attempt、Page、首观察、目标和原账，再按返回的收据回写。用假页面和假网关通过正常 CLI 联调。

## 4. 验收

| 层次 | 判据 |
| --- | --- |
| 离线工程 | 在全新临时池与账本中，从真实 CLI 参数解析走到模拟消费。两个独立进程争同一候选只产生一个有效 claim、一次入口导航、一份会话、至多一次有效保存。领取两个不同候选产生两个不同上下文。覆盖 V1 兼容、V2 entry/target、空池重放、身份拒绝、丢租约、保存后崩溃、原账 UNKNOWN、跨站别名/越界和三次真实失败的 hold。使用无网络测试替身计数，尤其断言成功对账零重采。 |
| 有界真实试跑，另行授权 | 从显式 V2 候选经正常入口取得身份，至少一条有 `claim → attempt → raw → saved → 实际独立 QC` 的完整引用，另报告所有失败及分母。单条证据、坐标、原件、动作、去重命中和终态照常检查。小集合的短流程、类目和近重复比例只报诊断。试跑样本不能据此记正式接纳。 |
| 正式 5,000 条批次 | 消费者交付可复核的唯一待审集合与索引。冻结本批及跨批有效集合后才计算分布、判重并接纳。短流程 ≤2%（本批最多 100 条），近重复涉及的唯一样本 ≤0.1%（最多 5 条），单一站点类目 ≤20%（最多 1,000 条），全集视口 ≤3 种，四路未裁决 0。任务类型、动作和步数区间报告实际分布。具体分子、严格去重与独立抽检按[规划侧验收](规划采集Agent提示词与调用链执行计划-20261031.md#正式批次)执行。 |

完成报告分别列领取、正式尝试、采集、待审、实际 AI 审核通过、批次接纳、发布、客户验收及目标缺额。现阶段可验收离线工程，历史真实报告和池内待处理项不授予续跑权限。
