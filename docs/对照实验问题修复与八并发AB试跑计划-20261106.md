## 2 工程代码修复

### R1 目标绑定与无进展循环

主要位置：`projects/code/webcollect/banded_plan.py`、`model_gateway.py`、`react_session.py`。

- 逐条复用中国青年网、EleAdmin、国家图书馆的原观察和响应，解释目标为何没有绑定。已有 node、href、命中证据而文字缺省或分散时，使用当前工程的唯一身份与可见证据绑定；真正冲突和歧义仍返回具体缺证。不能直接跳过标签及可见性核对。
- 新协议将“查看当前原图”和“继续原计划”分为明确的选择语义；例如原图选项使用 `request_original_image`。prompt、tool/schema、gateway、Controller 和保存引用同步更新。旧冻结协议中的 `original` 保留原义，不把历史回包重新解释为执行动作。
- 同一观察、目标和失败原因下重复请求原图而没有新增信息，计入已有无进展预算；原图已经提供后不无限提供同一选项。复用当前计数和停止机制，不另建循环控制框架。
- 反馈明确当前缺少的证据、是否执行过动作、原图是否已提供、可以重规划或停止。目标暂未绑定时，不给一个实际无法执行的“继续”选项。

验收：原件回放能够定位绑定结果，重复同帧原图不会耗尽 25 次调用；修复后真实目标的执行与保存由第二阶段验证，提前停止空转本身不算目标完成。

### R2 计划长度与剩余步骤接入

主要位置：`banded_plan.validate_plan`、Controller 重规划、任务协议及保存派生。

计划声明的长度档位由实际步骤列表确定；最终 short_flow 只由最终保存区间的有效业务动作数确定。不能因 Agent 的 `band` 声明与步骤数量不一致拒绝本可确定归一化的计划，也不能要求凑足原计划步数。

剩余计划须保持原目标、参数及未完成事项，可根据真实执行结果调整路径长度。消除“原计划长度减已执行条数”对自然修正的机械限制，继续遵守真实动作、时间和每会话 25 次 GLM 派发预算。已经完成的动作不能重放，明确业务约束不能删减；业务歧义返回具体反馈，不截断或猜造步骤。

验收：覆盖原长度冲突、合理增加或减少剩余步骤、已执行步骤不重放、目标不改写；1–4 个有效动作标短流程、≥5 普通、0 步不成样本。

### R3 动态区域与几何异常

主要位置：`browser.py`、`snapshot.js`、`action_stability.py` 和既有动态区域模块。

依据原拒绝帧、DOM、比较区域和诊断，贯通首访、派发前、动作后、终态与保存回算的无关动态区域规则。公告、广告和动态图片的允许变化贯穿全轨迹；原 PNG、树及失败不修改。

对与任务无关的旋转、装饰或局部不支持元素，保留异常说明并限制其影响范围；不让单个无关元素使整个页面观察失败。目标本身或遮挡关系无法核实时仍须补证或如实阻塞。复用已有几何证明和局部保护，不全局放宽像素阈值，不伪造可点击坐标。

验收：无关变化不阻断有据目标；目标移动、值变化、真实遮挡和必要图片未就绪仍被正确识别。

### R4 生产者复验与误剔除

主要位置：`projects/site-planner/site_planner/inventory_recheck.py`，关联 `candidate_discovery.py` 和消费者入口处置。

- 浏览器导航、HTTP 响应、页面观察分别保留结果。取证同步、局部几何、浏览器进程异常和一次超时不直接变成永久死页。
- 明确 Table2 入口自身 403 时沿既定规则废弃该页面；可用入口中途跳到 403 时由消费者真实返回并继续原目标。不得扩大为整站停用。
- 针对本次 HTTP 入口拦截核查实际导航链和浏览器配置。有已验证的合法落地才规范化；不全量盲改 HTTP 为 HTTPS，不绕过网站访问限制。
- 冒烟复用消费者的浏览器上下文参数和相关观察能力，说明它实际覆盖的是导航、DOM 观察还是完整图树同步，不能用一次 DOM 成功代表整条采集可用。
- `--dry-run` 包括 smoke 分支均不写生产数据库、复验表、strike、候选状态或事件；如需建立辅助表，在临时测试库或正式写入路径处理。
- 剔除时在原短事务内再次核对 pending 且无 claim，保留原候选与追加事件。已有碰撞预检、应用上限只验证相关链路，不扩大为全量库存清洗。

验收：暂时与宿主异常不会误剔除；确认入口 403、真实失效及并发领取的边界正确；dry-run 前后数据库无变化。

### R5 八并发单次实验入口

复用 `candidate_consumer.consume(..., effort_profile=...)`、原 CandidatePool、BatchLedger、RuntimeStore、当前链以及现有结果回写。增加一个轻量本机实验入口，负责冻结名单、启动 8 个进程、等待收尾和汇总；不另建调度服务或八套账本。

当前 Python API 已能传递 effort profile；不能假定 CLI 已有同名开关。实现后将真实支持的准备、运行、状态命令和 I/O 写入交接，禁止文档先编造可执行参数。旧实验驱动只能参考：不得沿用其每组 50 页循环、补位脚本、共享时间窗归因以及过时的独立账本注释。

共享作业账须支持 8 个顶层采集链同时工作，模型子作业沿用已有父作业槽位，不另占一份顶层名额。基础测试只在临时账验证并发配置；第二阶段才在原工程绑定上做必要的、可审计的并发上限调整，保存调整前后配置与事件。历史请求、账号绑定、用量及 UNKNOWN 不改，不靠增加账本绕过限制。

每个 worker 绑定一个 candidate ID、版本、目标、组别、worker ID、唯一 request prefix 和独立输出目录。一次领取、至多一次新的正式采集执行，完成即退出；不可领取、入口失败、模型失败、UNKNOWN 均不领取第二个候选。进程重启只能读原状态和核对原收据，不能再发一次采集。

### R6 报告与保存检查

模型请求按 `group → worker → candidate → claim → attempt/job → request` 关联。首轮、分支与重规划分别记录实际出站 effort；已预留但未派发不算真实调用，UNKNOWN 用量不算零。补齐失败阶段与原始原因，避免用 `失败:None` 或 `失败:claimed` 代替诊断。

正式保存后回读原 Runtime、候选投影、保存收据和样本摘要；原目标完成、可信前缀和 short_flow 各自列出。既有程序检查及 QC 交接保留。本轮真实 A/B 范围为 8 次采集及其程序检查、交接，不自动启动独立 AI QC、历史 10 条重审、人工审核或发布；未实际运行 QC 时明确 `QC_NOT_RUN`，不能由此选出质量胜者。
