## 下一轮的步数分布与停止条件

按同一质量批及跨批累计、去重后有接纳收据的有效样本统计。每条按实际可核验的原子动作数归入一档。下表用 5,000 条有效样本说明满额时的目标。

| 步数档 | 内部规划目标 | 5,000 条中的参考数 | 首轮选题与收尾 |
|---|---:|---:|---|
| 恰好 5 步 | 80% | 4,000 | 选自然连贯的五步片段。第 5 步效果与真实末帧已核验，由宿主直接 finish |
| 至少 6 步 | 19% | 950 | 现行尝试上限内选自然需要 6–8 步的路径。首轮写明第 6 步及以后的业务用途与可观察末态，到预定终点即收口 |

在已发布的 Table2 候选中，宿主根据各档缺口安排候选，在首帧和 DOM 上核对路径是否自然成立，并在第一次业务派发前记下计划档。比如五步百科路径是“点搜索框 → 输入人名 → 回车显示结果 → 打开词条 → 返回结果列表”。长档若有明确对比目标，可以继续打开第二个词条，核对其正文。若第五步已经完成全部有据事项，按真实五步结束，长档缺额由后续合适候选承担。`wait`、取证和 `finish/complete` 计零个有效步。片段结束、业务目标达成、异常标记分别记录。[已有的片段末态口径](../request/轨迹采集口径补充-20261030.md)

分别在首轮规划、正式保存待审、批次接纳三个阶段记录各档的分子与分母。调度同时看在途计划和近期实际转化率，最终分布只读接纳收据。一批 50 个候选并不要求凑出半条 short_flow。停机时 27 个实际访问产生 11 份保存，恰好五步 2 份（18.2%）、至少六步 2 份（18.2%，均为八步上限标记）、短流程 7 份（63.6%），尚无该轮独立 QC 结论。下一轮应先筛出有足够可见操作机会的路径，对于只能产生短流程的页面单列原因与消耗。1% 是本次内部预留，原质量批短流程 ≤2% 的验收口径单独核算。[逐样本收据与步数](../verify_results/consumer-agent-fifty-round2-parent-20261103-r01/user-stop/statistics.json) · [质量批口径](../request/需求澄清记录.md)

计数和停止检查放在每次真实原子派发的效果核验之后，包括复合工具内部。到该档终点时，由宿主保存末帧并结束，额外规划调用为零。若操作的预期结果异步出现，在原操作上等候和核验。若第 5 次尝试失败，只证实了前 4 步，则沿用异常收尾规则，完整可信的前缀保存为带原因的短流程，外部效果未决时保留原件待核。长档也受现行 8 次业务尝试上限约束。

## 哪些观察可以合并

1. **整页观察参数交给宿主。** 整页刷新允许无参数，定向刷新使用明确控件 ID。旧版只读 observe 的 `"null"` 在安全可判定时标准化为整页请求，限制同观测上的同错反复求模。把当前轮短引用在允许使用的意向字段内解析成绑定的完整观察 ID，错轮/错 attempt 仍拒绝。HTTP 11 提交的是本轮真实短引用，旧规则只在 finish 支持该短引用，拒绝后给了泛化的 HTML 建议。应返回精确的绑定修正。[原错误反馈](../results/candidate-project-20261101-r01/collections/reset-20261102-20s200p/consumer/consumer-agent-fifty-round2-20261103-r01/ee1d4810-6973-429f-bd6a-ede7accba13d/execution/capture/evidence/S000075_sample_000002/raw/0063-model-intent.json)
2. **查找控件和命中探针合并。** HTTP 5+6、17+18 各自是在一个文档内找同名“部门”并建立点击证据。宿主从完整索引按文本、角色、相邻标题查找，唯一匹配时直接完成定向命中探测，一次返回可执行句柄、证据和文档版本。多义才交给模型。下一次真实点击仍在派发前重新核对目标。重载后 e_37 已变成 e_35，应重新绑定。两组原轮的已知输入共 95,198 token，这里计的是合并候选的开销，并非可以全部省去。
3. **代码回答“筛选已选中、结果区域变了吗”。** 在用户触发的控件关联区域内有限等待重绘，比较已选项、可见行键、首末行或字段、小段原文及区域截图。区分暂时未出现、页面显式空态、已出现和无法验证。HTTP 12–14 的切片止于第 12,000 字符以内，而这次目标容器从约第 19,855 字符开始。实存 HTML 可直接检出“政策文件”区域从 0 条到 10 条带标题链接。末屏肉眼可见 5 条。HTML 中另有行不能算作用户已看见。通用实现先按标题、容器关系和可见范围定位，这个站的 CSS 仅供回放对照。[第一次点击后，列表区空白](../results/candidate-project-20261101-r01/collections/reset-20261102-20s200p/consumer/consumer-agent-fifty-round2-20261103-r01/ee1d4810-6973-429f-bd6a-ede7accba13d/execution/capture/evidence/S000075_sample_000002/raw/observation-006.png) · [恢复后的“全部”列表](../results/candidate-project-20261101-r01/collections/reset-20261102-20s200p/consumer/consumer-agent-fifty-round2-20261103-r01/ee1d4810-6973-429f-bd6a-ede7accba13d/execution/capture/evidence/S000075_sample_000002/raw/observation-010.png) · [末帧“部门”列表](../results/candidate-project-20261101-r01/collections/reset-20261102-20s200p/consumer/consumer-agent-fifty-round2-20261103-r01/ee1d4810-6973-429f-bd6a-ede7accba13d/execution/capture/evidence/S000075_sample_000002/raw/observation-013.png)
4. **保留模型真正要决定的分支。** 入口是错误页时，宿主能判定页面异常、当前 URL、已观察入口是否可用，并提供有界恢复选项。恢复后选哪个业务目标、多个同名控件如何取舍、视觉与树冲突时如何解释由模型决定。所有执行、等待和取证写回原轨迹，未知外部效果保留原请求身份。

**ReAct 与 `tools` 的关系。** ReAct 通过新观察更新决策，本文设计在有分支时保留这一反馈循环。服务端原生工具调用另有请求协议。当前工程使用 `glm-5.3-flash` 的 `/api/paas/v4/chat/completions`。冻结网关的 `call_tool` 在发送前要求非空工具表，并在每次原生调用中设置 `payload.tools`。智谱文档把工具表定义为本次可调用的函数，其多轮示例在第二次请求中再次传入工具。同一浏览器、attempt ID 或缓存命中都不能据以推定服务端会在新请求恢复首轮的工具表。[冻结网关](../verify_results/consumer-fifty-round2-implementation-v2-20261103-r01/checkout/projects/code/webcollect/model_gateway.py) · [智谱原生工具调用](https://docs.bigmodel.cn/cn/guide/capabilities/function-calling) · [Chat Completions 请求字段](https://docs.z.ai/api-reference/llm/chat-completion) · [ReAct 原论文](https://arxiv.org/abs/2210.03629)

**推荐的新接口。** 首轮只声明一个提交路径的函数，连同简短动作词表生成可校验的计划。后续视觉判断走普通消息，宿主给出本轮允许的选项，例如“1 执行已绑定的下一步、2 重新定位、3 结束”，模型在普通文本中返回如 `{"choice":2}` 的小对象，宿主解析并校验其归属。后续 HTTP 可以完全省略 `tools`，也不依赖模型凭 plan ID 猜回首轮内容。它收到的是当前步骤及选项的实际含义。这需要新建有版本的普通回包解析路径，并保留原请求身份、用量、25 次派发上限和未决隔离。若后续仍选择原生 `tool_calls`，就在需要调用的那一轮发送可用的最小工具集。多模态下普通文本返回的合法率、纠错成本需要以后单独实测。

### 规划采集 Agent 的修改建议

- **Goal。** 保留固定的 `requested_goal`，为空时由可信首帧形成 `working_goal`。第 3 条需要同时核实筛选状态和业务列表。第 8 条要按章节记录多个事实。建议把每个待核事实、允许的页面或区域、可见证据条件随工作目标冻结。只有指定出处才算该项已满足，其他页看到的证据另列。合法片段可以因步数档或预算结束，结束状态和事实覆盖分别报告。
- **Prompt。** 首轮根据当前观察列语义目标、实际动作、预期变化和停止条件。区分页面恢复、业务操作和取证。可见选项有进一步入口时，计划可以包含滚动、点击进入详情、继续阅读或返回，但须符合本次目标。跨文档重新绑定控件。后续把尚缺的事实及已见出处交给模型，只在同名歧义、图像辨读或重新选路时询问。
- **模型看到的工具。** 继续用首轮 `submit_plan`，后续用绑定本次 attempt 和观察的有限选项。现版每步有一个 `expected`，`finish_when` 也是单个谓词。建议在新版本中增加可选的多项事实清单，每项包括待核字段、页面、区域、可见判据，例如“创立年份／简介章节／正文／有明确创立年份的可见句子”。目标可指明左栏目录或正文。后续只传未决项、候选控件和必要的局部图，复用已有节点选择、看原图、重规划和结束分支。[现行计划协议](../projects/code/webcollect/banded_plan.py)
- **宿主实现。** 在原会话中运行定位、命中复查、真实点击或滚动、有限等候、截图与树取证。每项事实绑定页面、观察 ID、可见原文或图像区域，区分代码核实和模型读图。接口引用由宿主校验。跨页核对在同一次尝试中汇总历史有效帧，收尾、导出和 QC 交接都携带缺项。另开单一标签页需补来源点击、opener、实际落地、新页首帧及后续页面归属。现行新候选协议遇到新标签页会保留已派发记录并报 `tab_switch` 能力缺失。首轮有两条真实阻塞可供复验。[新候选执行器](../projects/code/webcollect/react_session.py) · [两个新标签页阻塞原例](../verify_results/consumer-agent-fifty-parent-20261103-r01/五十候选采集与独立审核复盘.md)

| 原基线 | HTTP / 有用量 | 已知输入 / 输出 token | 每个有回执请求的平均输入 | 正式保存 |

| 第 8 条 | 13 / 13 | 259,905 / 30,379 | 19,993 | 5 步待审，简介页年份未核实 |

1. **先回放原件。** 旧、新协议用同一组原始帧和目标核对十个动作、两个同名链接、首次筛选空白与末帧五行、首页有年份与简介页缺年份。增加真实滚动与无位移滚动、同标签页跳转与单新标签页的对照夹具。核对动作数、截图与树、实际落地和事实出处。每次无需模型即可完成的代码步骤产生 0 笔模型 HTTP。离线只统计可合并位置、消息大小和分支正确性。
2. **再做有界真测。** 恢复消费者实测后，从当前 Table2 选可派发的同类留出候选。预先冻结 ID、版本、入口、原目标和等价的核对要求，保留困难样本和失败费用。旧批只读。第 3 条同类终态沿用 ≤10 次 HTTP、有回执平均输入 ≤12,000 token 的目标，要求同帧能复核“部门”选中和政策条目可见。第 8 条同类多章节任务建议首轮以 ≤8 次 HTTP 作对照目标，核对实际跨页、发生的滚动和字段出处。这是拟议门槛，尚无新版实测值。
3. **质量与效率一起报。** 核对每步原子效果、原始图树连续性、可见终态、缺证项、正式保存收据及同一样本的独立 AI 质检。第 3 条如以更少实际操作取得同一终态，照实报短流程。验证五步质量另用自然有五步的任务，统计每个达到至少五个已核实操作且独立 AI 通过的样本所花的 HTTP、已知 token 和实际运行时间，失败消耗计入分摊。缺少此类通过样本时均摊值为未定义。创立年份仅在其他页面可见时，指定章节的目标记部分核实，片段是否合格仍按原质量规则判定。[原独立审核交接与停止状态](../verify_results/consumer-agent-fifty-round2-parent-20261103-r01/user-stop/停止时复盘.md)
