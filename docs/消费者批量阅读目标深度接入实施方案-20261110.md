# 消费者批量阅读目标深度接入实施方案（2026-11-10）

来源：`delivery/202611100008` 维基样本 `S000002_sample_000023` 仅 click→scroll 2 步完成，用户指出"wiki 除了滚动还可以点击，这个也没有规划"。本文回答"怎么解决"，与《结果终态规划与完成判定修复方案-20261110.md》并列，可同批实施；QC 空失败字段归一化仍是独立附带项。

## 一、先定性：这次 wiki 不是执行能力缺失，是输入目标没有深度

### 1. 这次样本走的是普通 V11 浅目标，不是阅读契约链

- `S000002_sample_000023`：`session_objective=NOT_CONFIGURED`，`plan_protocol=webcollect-banded-conditional-plan-11`，目标仅"打开该词条落地页并阅读其正文内容"，`planned_steps=2`，`goal_evidence` 3/3 VERIFIED。
- 没有具体阅读问题、没有跨页核实需求、没有 minimum_effective_steps 与 band 要求。消费者按目标最小完备规划，2 步完成是该目标下的正确执行；要求它自行加点击等于让执行层替任务生成补目标，且违背"不为长度补动作"。

### 2. 滚动+点击+返回已在直接阅读链上真实做到（已有资产，不重造）

- 冻结基线 `wiki-reading-high-high-20261109-r1`（glm-5.3-flash，first_plan/branch=high）：样本 `S000001_sample_000011` 实际序列为滚动→点击"本影"→返回→三次续读，6 有效步、非短流程、`collected_pending_review`；后续修复轮样本 `S000001_sample_000012` 首轮直接点击"月球"，6 有效步、阅读契约 VERIFIED，正文引用已含完整内联词。
- 规格来源：`webcollect-goal-evidence-2` 阅读契约 + `direct_entry` + `session_objective`（具体阅读问题：日月地相对位置及满月条件）+ minimum 5 / preferred_band=long。
- 结论：执行链不需要新发明"点击/返回"能力，缺的是**批量生产者的阅读候选也带上这种目标规格**。

### 3. 已有共识直接沿用

- 《消费者阅读规划动作混合与同页目标多样化实施方案-20261109》（A+B，待实施）：删除 V11"长阅读由多段滚动自然组成"默认表述；有相关链接证据时首轮自然含目的性点击、跨页后 back 续读；同页目标多样化（方向 B）。
- 重规划分寸（20261109 冻结文档 P2 与剩余优化）：首轮充分使用已见链接证据；滚动/切页后目标失效只修订失效的剩余部分，**不引入每次 scroll 都重新规划的硬流程**；url 条件填当前可见完整 href、标题条件用 visible_text，减少无谓 replan。
- 接线已存在：`task_generation.py` 878–880 行，`react_candidate['session_objective']` 经 `session_objective.apply()` 绑定——生成侧补上 objective 即可，无需新执行框架。

## 二、方案（三层，各司其职）

### A. 生产者：阅读类候选必须生成有深度的目标（核心）

定位 react 生成链的阅读目标提示词/模板，补规则：

1. **必带阅读问题**：阅读类候选目标不得停留在"打开并阅读正文"，必须提出需要正文证据才能回答的具体问题（如"该人物与乌埃诺银行事件的关联、辞职与国会弹劾程序的时间线"），经既有 `session_objective.apply()` 绑定。
2. **深度分档**：同页多目标按"纯正文可答 / 需目录或内链定位章节 / 需查阅关联词条后返回续读"分档；至少一类设计为"答案需跨词条核实"，让 click+back+续读由任务需求自然产生。同页各目标阅读问题须实质差异（route4 SimHash ≤3 会命中同义改写）。
3. **长度规格**：阅读类候选沿用 minimum_effective_steps=5、preferred_band=long 的既有规格，使"2 步打开即完"不再满足候选目标——约束来自"回答问题所需证据"，不是为凑步。
4. **动作不写入任务**：滚动/点击/返回的组合与顺序仍由消费侧规划 Agent 按页面证据自由决定；生成侧只决定目标差异。

### B. 消费侧：实施 A+B 方案方向 A（提示词纠偏）

- 普通 V11 阅读提示去滚动默认形态，有相关链接证据时自然混合 scroll/click/back；纯滚动仅在页面确无目标相关可读链接时合理。
- 保留分寸：不强制每条轨迹含 click/back，不把路线当模板，不为步数添加无关动作；不在宿主新增单一动作类型计划拒绝门禁。
- direct-article-1 既有"跨页后下一业务动作必须 back"不变。

### C. 重规划与谓词小项（按已定位问题修，不新设流程）

- 首轮用足当前帧可见链接候选；失效后只 replan 剩余部分。
- 修"词条名填入完整 URL 条件"这一已实证问题：url 谓词用当前可见完整 href，标题用 visible_text；不放宽点击/导航验证。
- replan 输出收窄提示保持现状，不新增泛化重试层。

## 三、不做的事

- 不强制每条阅读样本含 click/back，不以动作混合为由放宽单步原子效果校验、VERIFIED 门槛或四路判重阈值。
- 不做每次滚动都重规划的硬流程；不靠无意义滚动或随机动作制造差异。
- 原样本 `S000002_sample_000023`、r02 全滚动样本 `S000001_sample_000002` 保持原状：不回写、不改写、不重跑；新目标走新 candidate、新 attempt、新账。
- 短流程 2% / 类目 20% 交付阈值不因本方案调整；分布达标靠目标深度与类目供给的真实改善。

## 四、验收口径

基准只取当前工程生产者 Table2 已发布有效网页或经正规 baseline_import 登记的研发变体；真实 GLM 自主规划，不由脚本代选固定序列。

1. **离线集成**（沿用 A+B 既定夹具口径）：有相关链接证据时首轮自然含目的性点击、跨页含 back；无相关链接纯滚动仍接受；凑步无关点击、无效滚动、错误返回仍拒绝；direct-article-1 回归不变。
2. **真实 GLM 新变体**：以培尼亚词条类候选制作"需进入乌埃诺银行词条核实关联后返回续读"的阅读变体，隔离研发工程正规登记（production_counted=false），跑一次真实会话。报告实际 scroll/click/back 组成、各步前后证据、有效步、目标 VERIFIED、`collected_pending_review`、密封 SHA256 回读一致；对照含 r02 全滚动样本的研究集合报告 route2/route4 判重结果。
3. **月食冻结基线回归**：沿用冻结 model-profile（high/high）与原目标复跑一次，确认动作混合不塌缩、契约 VERIFIED；更换目标或档位另建冻结编号。
4. **批量观察**：从后续正常批量账观察动作用途、短流程占比与去重结果，不额外建验收批次；分别报告尝试、有效步、待审保存、QC 状态，不把单条基线通过写成整体交付结论。

## 五、实施顺序

与终态修复同批：集中完成生产者生成规则 + V11 提示词 + url 谓词小项修改 → 新目录一次离线集成 → 真实 GLM 新变体与月食回归各一次 → 失败只修实际断点。同步维护 README、工程说明、设计说明中阅读目标规格与重规划分寸；历史冻结目录、原样本与原账不改。
