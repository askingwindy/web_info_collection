## 可信观察

`agent_observation.action_availability` 是新观察、动态编译和 `browser.prepare_action` 的共用判据。快照新增 document identity（去 fragment 的 URL 与 performance.timeOrigin），观察绑定当前 URL、文档、视口、scroll、完整原 PNG、原状态、同步 capture 收据、控件值/焦点/selection、控件库存和动作判据。保留 `PROVEN / UNAVAILABLE / INSUFFICIENT` 三态，缺少证据不等于没有路径。

文字库存、bbox、visible=true 和无障碍名称都不能证明可读。新协议只采用 `snapshot.js` 现有 target probe 的可读标签来源：绘制文字、关联标签、原生可见值/placeholder 等；同时要求当前完整视口、命中、启用/可编辑/焦点条件。可读证据来自保守 DOM 绘制/遮挡检测与同步 PNG 绑定，仍须独立视觉审核，不宣称 OCR 或人工已看图。

首次观察保留未探测控件，标为证据不足，并列出补充观察入口。模型可以 `observe(control_id)`，程序按原 selector 重新完整 capture 该目标；捕获不点击、不自动滚动。需要滚动、点击、展开时必须提出实际动作，进入原始动作记录和计步。源证据缺少同步收据保留 UNKNOWN，运行时要求新捕获证明。

## 状态控制与保存

每轮：保存当前观察 → 模型 `plan / observe / finish / no_path` → 程序编译与预算检查 → 保存决策和 dispatch intent → 原执行前复核 → 原执行器 → 原图/树/动作与结果 → 新观察核实效果 → 后续决策。

短段当前支持一个 `set_value` 展开为最多三个稳定原子步骤（聚焦、必要全选、输入/清空）。每个原子步骤仍重新捕获并校验。模型决策后的最后派发帧另行完整 capture/复核；只有文档、视口、值和焦点仍匹配时才复用决策，状态变化则在预算内回到候选决策。全选等快捷键也绑定当前焦点目标，不能丢失其 selector 后误用空 target。原值为空不全选，已相同的值不产生动作，替换前必须实证焦点和完整选区。输入后标签按新 placeholder/当前值重新取得。导航、滚动、普通点击后重新决策；短段 URL、文档 epoch 或滚动位置改变立即失效，不能借“此前已滚动”继续用旧目标。未实现跨状态预排多目标短段。

默认硬上限：8 次动作派发、32 次完整观察、24 次决策、8 次候选修订、20 次决策模型调用；只能收紧。上限按最坏诚实路径成本核定：每个动作最多 3 次观察（决策前新观察、目标补充观察、派发前 rebind）与 2 次决策/模型调用（显式 observe→plan），8 动作加结束分别需 25 次观察、17 次决策/调用。有效完成要求 5–8 次已结束且无执行错误的动作，wait/complete 不计步。无变化动作或没有移动视口的滚动终结为 `NO_EFFECTIVE_ACTION`；不会为了不足5步补无效操作。实际资源和模型 token/费用仍受原 BatchLedger 与 RuntimeStore 限额约束。

`evidence/<sample>/controller/` 保存独占创建的 boundary、完整观察 PNG/JSON/capture、model intent、原决策、dispatch intent、执行结果伴随引用和终结事件。动作执行前落盘/fsync；原始已执行记录不改写。`agent_audit` 在终态与 capture audit 中重验原任务、原决策、图与状态绑定。动态计划不写回旧 frozen plan。已存在 boundary 的控制器不能重放；中断保留，新尝试仍由 RuntimeStore 另登记、另编号，不拼接。

## 真实反馈与防重

`planning-feedback-<outcome>.json` 是原 attempt 的伴随证据，在 finish 时纳入原账引用；包含每步 operation、目标、实际状态、错误、原 raw 与图片 SHA、去重对象和失败诊断。失败样本的引用指向原隔离目录。成功仍只写 `collected_pending_review`。预提交反馈与提交冲突后的拒绝反馈各写新文件，只有最终 finish 绑定的记录进入下一轮；不覆盖前者。

站级上下文自动读取原生产库同整体应用的 attempts、已绑定反馈、`m4_reviews` 与 `m4_quality_admissions` 的原 QC 报告；报告经过原绑定门禁，不能用规划文字签发审核。生成结果保留原模型响应、具体拒绝规格及编译原因、成功任务详情，滚动轮次消费这些原件。模型输入携带实际状态和原图附件，文件路径只是追溯字段。同状态同目标的已知执行失败会被程序提前拦截；反馈也进入下一轮选择。

空结果保留模型原文，标为模型报告未核实；新协议区分 `NO_FEASIBLE_PATH / MISSING_OBSERVATION / ENGINEERING_ERROR / UNRESOLVED_REQUEST`。生成数量不能替代这些原因。原模型作业未决、在途或中断尝试阻断新规划；UNKNOWN 原账不得重发。决策请求失败按实际请求阶段分级：发送前本地预检错误（图片/输入超限、schema 校验）可证明零预留零发送，保留本地原因终态 `failed`，不制造远端 UNKNOWN；请求已结算的明确失败同样终态 `failed` 并保留原请求与用量证据，映射 `MODEL_FAULT`；仅发送后结果未知或无法证明是否发送才维持 UNKNOWN hold，沿用原整站账，不能重置失败账。

生成前查询原 `m4_exact_images` 起点占用；每个新观察再对原精确图片索引检查首帧/中间帧。完整轨迹仍经过原提交时原子精确冲突检查及独立 QC 四路去重。不同首帧不是整条合格证明，不预测单页固定产能，不删除准备/失败帧绕过重复。上下文图片过多时原 gateway 图像上限会停止，不能静默删除失败证据继续。

## 第二轮闭环修复（controller v2，2026-10-30）

基线 `2623ed4` 之上修复评审反例暴露的四个闭环缺陷，控制器协议升为 `webcollect-fragment-controller-2`。旧 `-1` 版受控任务从未派发生产（本轮前仅离线夹具），新代码按新版本验证；离线旧夹具计划需重新生成，不改动任何生产账。四项修复：

1. **目标语义一致性**：决策与派发之间按动作相关投影（selector/索引/标签角色、element 角色、可读标签来源与文本、value/checked/focus/selection 状态）核对目标。结构或标签含义变化时原候选失效、回到新决策，不再自动绑定新标签后沿用旧决定；仅目标自身已执行输入动作可解释的 placeholder↔当前值互换与值/焦点/选区变化放行，无关控件变化既不放行目标漂移、也不触发整页拒绝。
2. **观察/决策/结束预算匹配**：消除补充观察后的立即重复整页捕获（补充观察本身即新鲜，直接在其上再决策）；计划编译遇仅缺目标探测的 `INSUFFICIENT` 时自动补充观察一次，不再把缺证拒绝退回模型换一次等价决策；新动作开始前按"每原子步骤 rebind+结束后观察+结束决策"预留完成余量，预算确实不足时诚实终态并保留全部已执行证据。
3. **当前轨迹执行记忆入模**：每次决策 prompt 携带 `current_trajectory`：已执行动作、目标、实际参数、决策预期（expected）与实际观察结果（observed：变化字段、目标事后值、观察原件引用）及进度/剩余意图；与历史尝试 `feedback` 分列；只传有界引用不复制历史图片。
4. **决策请求失败分级**：见上文映射段；本地预检零发送不再产生远端 UNKNOWN hold，`site_context` 仅将 queued/running/review_required 作业列为未决。

验证：新增正式回归 `test_agent_review_fixes`（43 项，覆盖两个评审反例语义、5/6/8 步预算内完成、预算不足诚实终态、轨迹记忆防重复、三级失败分类），连同 `test_agent_loop`（20 项）、`test_collect_runtime` 经选定离线验证器在新目录全量 PASS（83 项）；原始评审反例文件复跑通过。证据：`verify_results/agent-loop-fix-20261030-r01/`（含 tests.log、summary.json、review-counterexample-rerun.log）。真实页面吞吐、动态重绘、模型遵守协议及 token 成本仍未验。
