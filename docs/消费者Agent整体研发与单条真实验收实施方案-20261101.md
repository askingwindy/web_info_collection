### 分类与导航契约

分类与执行结果使用独立状态。合法来源、实际 URL／主机和候选版本必须可以验证，分类可以待确认。消费者不承担补分类职责，后续元数据／交付检查保留待确认状态及其原因。显式按类别选择的原名单仍保留其冻结范围，但普通消费不得隐式要求分类存在；不改写历史拒绝。

导航、目录和聚合页可以采集浏览、筛选、查看详情、返回和比较分支等连续片段。例如“点击分类 → 点击 A → 返回 → 点击 B → 返回”，由 Agent 逐轮依据观察选择，不能硬编码为凑步脚本。原始目标非空时不能改掉对象和参数；只有 URL 时从真实页面建立工作目标。不存在必须完成交易、提交或网站完整业务的额外条件。

复用现有路径／操作证据结构，必要时增加协议版本，绑定来源 observation、控制项、触发动作、目标链接及实际落地。返回后核验当前状态和新控件引用，`verify_path` 与后加工使用同一规则。第三方介绍页归发布站，真实进入外站后记录外站；不扩充应用别名把两个网站强行合并。公网地址及原访问校验继续有效。首版必须完成同标签往返；未实现的新标签能力如实返回并标记优化，不篡改页面或伪造返回。

快速丢弃和待优化继续复用原候选处置机制。缺少工具、可修复取证或目标／提示问题记录具体原因和证据，等待修复版本；确实不可访问或无可采路径按既有策略处置。分类缺失不进入丢弃或待优化，复杂程度不依据一次分类失败判断；不重新引入默认 5 轮停机或其他累计额度。

## 单条真实验收的执行方式

### 1. 使用已有工程与合法输入

本机当前工程入口为 `results/candidate-project-20261101-r01/scope.json`。交接时读到的 pool 为该工程 `state/candidate-pool.sqlite3`，registry 为 `state/production-registry.sqlite3`，当前链为 `chain/manifest.json`，消费者配置为 `state/consumer-config.json`。执行前重新读取 scope 中路径和绑定，沿用其中消费者原账、生产库、编号和历史集合，不凭本文件快照覆盖原配置。`results/delivery/LATEST.md` 指向旧正式交付，不替代本工程当前链。

优先选择原 100 条冻结名单之外、尚未被消费且可独占领取的一个真实生产者候选。核对原 producer batch、response、发布行、候选版本、来源 URL 及引用摘要，记录是否存在分类，但不要求分类通过。优先具有自然多步浏览或导航路径，不通过手工改目标／来源或预设点击序列制造可通过样本。原 39 条问题、61 条未访状态和封存 Muxtly 不自动重跑。

在新的验收记录目录冻结选择清单及来源引用。复用现有固定名单／单候选能力，按当前 CLI 的 `--help`、`--dry-run` 与源码确定真实参数；不要直接运行会消费整批的默认入口。可以增加明确的单条选择接线，但不能为验收绕过标准消费调用链。只读取不含凭据的配置元数据；真实调用由产品已有加载流程在进程内使用凭据，不人工输出 YAML／密钥。

### 2. 运行真实消费并处理实际问题

真实过程必须是消费者独占领取 → 首帧 → GLM 原生工具循环 → 浏览器实际执行与同步取证 → raw 关闭 → 整条加工 → 保存收据 → 原账与候选回写。不能让 Codex 手工浏览后伪装为消费者结果，也不能用模拟响应或旧样本作为实测证据。

运行前完成本轮工程检查并记录源码摘要，真实运行期间避免修改正在使用的代码。发生已确定的实现失败后，先让该次执行安全终结并保留原件，再修复、局部验证和按修复版本恢复；每次复验重新记录源码绑定。不得仅为绕过 25 次上限创建新 session，不重发 UNKNOWN，不覆盖失败编号，也不拼接不同 attempt 的轨迹。

输入确实不可消费时记录具体原因，按照相同合法性要求选择替代输入，并在验收报告保留所有选择、尝试及失败，继续围绕一条保存目标串行执行。没有可用合法库存或存在无法解除的原账阻断时，说明实际缺口；不得启动无范围的生产者、伪造入池记录或创建新账回避。完成一条真实保存后停止本次真实运行。

### 3. 核对落盘结果

保存完成后以已有核验入口／只读回读确认原 raw、PNG、树、动作、终态、加工输出和保存收据的文件及摘要。核对 candidate ID、claim、attempt、样本编号与运行库状态一致，展示实际阶段目标、操作数、最终可见事实、真实 GLM 派发数和停止原因。只出现 `raw_execution` 或命令退出码为 0，不能代表正式保存完成。

正常样本优先达到至少 5 个有效操作；短流程须满足已有声明与可核验原因要求，不为达标凑步。真实验收状态最多记为 `collected_pending_review`。运行程序结构检查并核对关键截图／终态；真实独立 QC、人工审核和发布的未执行状态如实记录，不能借工程模拟或研发检查写成独立 QC PASS。本次采集保存验收不替代生产交付终审标准，也不自动处理历史资料 QC UNKNOWN。
