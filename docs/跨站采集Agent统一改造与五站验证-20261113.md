# 跨站采集 Agent 统一改造与五站验证

## 本轮授权与目标

2026-11-13 用户授权按照本会话设计实施：研发使用 `gpt-6.1-sol / low`；完成研发后派发 `gpt-6.1-sol / high` 独立代码走查，修复代码缺陷和逻辑漏洞；修复完成后进行五个不同站点、每站三个不同页面、并发五个进程的真实采集及结果分析。

最终目标是同一消费者在不同站点完成原业务目标、自然至少五个有效动作、正式保存和导出；独立 QC、人审与客户验收分别记录。采集不是成功率承诺，保留固定样本的全部失败分母。

用户新增约束：禁止版本控制、减少过度校验、注意上下文和事实唯一性。本轮直接修改当前实现，不创建实现/协议代际、旧实现兼容分支、Git 分支或提交；保留已有 Git 历史及历史证据。只删除重复或错误适用的校验，保留目标、实际动作、真实证据、UNKNOWN、独占领取与正式保存的必要边界。

## 实施范围

1. 统一结果取证：正文、控件可见值、表格/状态等载体与操作因果、阶段时效分开；候选结果、进展、完成、末帧、封存核验使用共同事实入口。补齐文本 textarea 结果与文本转换，拒绝输入回显、旧结果和不可见内容。
2. 业务目标与假设分开：原目标、字段/范围、阶段依赖、current/historical 和末帧义务继续冻结；由实际动作/观察确定载体和触发机制，不能通过修改机制降低业务义务。首轮仍提交自然完整至少五步路线，不增加先试做后换目标。
3. 精简上下文：一个权威事实投影；明确能力支持、明确不支持、尚未观察到；机械来源与绑定由宿主负责，模型负责业务语义、路线、首次理由及证据选择。保持未来语义目标与剩余路线修订。
4. 减少错误校验和误导反馈：区分可编辑、值可读、聚焦、几何/遮挡等实际条件；报告缺项与派发状态。宿主能力缺口不反复诱导模型点击/提交；UNKNOWN 不重发。
5. 保持正常消费者、RuntimeStore、candidate_results、导出和 QC 接线；无新存储或调度框架。已有未提交修改完整保留。

## 执行与验收顺序

先完成代码与全部接线，再更新并运行受影响核心用例，维护总量不超过 50 个独立执行项，最后更新文档。离线集成须覆盖正常保存回写导出，不只派生文件。研发结束才启动 high 独立走查；发现的确定缺陷二次修复并局部复验。

真实阶段优先从 prod Table2 选择有合法来源、pending、从未领取且未消费的候选；五站各三条，冻结名单后不换失败页面、不补位、不重发未决请求。启动前源码固定，运行中不修改。以现有配置、账户池与正式消费者入口执行，采集 GLM 沿用 high/high；5 为同时运行进程上限。未知费用不补零。若库存或来源闭包不足，先说明真实阻断，不复制不合法历史来源。

真实结果按站点报告：选定、领取、正式 attempt、首轮接受、有效动作数、原目标完成、正式保存、导出、独立 QC、模型请求/UNKNOWN/token。独立结构/内容审核只对实际成功样本执行，零样本则如实 NOT_RUN。工程故障按当前停派合同收口，所有未派发项保留分母；不自动扩批。
