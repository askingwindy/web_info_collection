## 代码设计

新增 `webcollect.single_record`，提供可独立执行、可检查点恢复的窄入口；复用三个既有程序，不另造采集器或QC。

| 阶段 | 调用/输入 | 输出与门禁 |
| --- | --- | --- |
| 冻结 | 共享池精确URI、原chain manifest、原生产policy、独立BatchLedger配置 | immutable run.json；拒绝非池内候选/错链/已有不同输入；保留原失败和消耗 |
| 来源 | `site_planner.pipeline.probe`、`qualification.qualify_catalog` | 新PNG/同步树/控件库存、资格和有效期；只读，不分配编号；能力有问题转待审/拒绝 |
| 规划 | `task_generation.generate` + 原页身份；注册策略或GLM根据实际库存生成，非表单走显式DOM工作流提案 | 1个任务、自然5–10必要动作、真实目标与可见终态；不做完整演练、不手改生成计划 |
| 采集 | 原 `task_generation.execute`，只发布1个任务 | 原registry/campaign中新attempt/新编号；失败完整保存，成功最多pending；不拼接/重用失败编号 |
| QC | `qc_handoff`、`cumulative`、`delivery_pipeline.prepare/run/status` | 包外收据、有效集合、跨包去重报告、GLM原帧/语义审核和用量；QC_NOT_RUN不是完成 |
| 汇总 | 只读状态/原账 | attempted / collected / pending / QC-pass / published / deficit、每阶段用量、UNKNOWN和后续入口 |

接口先支持来源、规划/采集、质检独立阶段，阶段结果按原输入与内容摘要绑定；成功阶段复用，失败/UNKNOWN不自动重发。结果目录处于原current-chain-r01允许根内，QC与模型账处于客户包外。运行输入和回执不得存凭据。
