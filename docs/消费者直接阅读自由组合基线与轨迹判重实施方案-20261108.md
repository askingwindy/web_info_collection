## 1. 当前决定

1. 后续真实主基线改为**直接打开「月食」词条并阅读**，不再把站内搜索作为 A/B 的前置能力。

## 2. 为什么这样调整

真实记录表明，搜索路线的绑定、聚焦、输入和派发前取证问题已逐层修复，但完整搜索阅读链始终未在不受进程超时影响的情况下走完。最新 r02 的直接终止原因还是 Bash 300 秒限制，而不是可据此推断“搜索永远不可用”。

与此同时，通用需求允许百科目录点击、正文滚动、相关链接查阅和返回等自然浏览轨迹，不要求每条都经过搜索。将搜索从主路线解耦可以扩大可采集页面范围，但不能据此宣称原搜索基线已通过。

### 3.2 合法自由组合示例

下表只说明动作空间，**不是给模型的固定路线模板**：

| 当前真实页面证据 | 可选择的自然动作 |
| --- | --- |
| 正文尚未读完 | 向下滚动，暴露与目标相关的新正文 |
| 可见目录指向未读章节 | 点击目录，核对同页视口/章节位置变化 |
| 正文链接与当前阅读问题有关 | 点击链接，核验新文档身份及实际正文 |
| 需要回到之前词条继续阅读 | back，核验 URL、标题和正文身份 |
| 返回后仍有其他相关链接 | 点击另一链接，形成有独立查阅目的的新跨页段 |
| 关联页仍需向下阅读 | 在证据契约允许时滚动阅读新正文，不机械立即返回 |
| 当前目标已有充分正文证据 | 正常收尾，不为达到步数继续无关操作 |

约束保持不变：

- 每次 scroll 必须有真实视口变化并暴露新的相关正文；到底、原地或机械重复滚动不计有效步。
- 每次 click 必须有独立查阅目的和可核验效果；同页目录不冒充跨文档，关联页不冒充原词条正文。
- 每次 back 必须核验返回页面身份；返回本身按真实动作计步，静态阅读不额外计步。
- wait、observe、截图、宿主检索和 complete 不计有效步。
- 最少 5 个已验证有效动作；自然不足则如实 short_flow，不为凑数添加无关动作。
- 真实目标仍须 `VERIFIED`，不能用“已经走满 5 步”替代正文回答证据。

## 4. 自由组合与轨迹判重的关系

### 4.1 规划自由度有帮助，但不是去重豁免

允许自由组合主要降低以下风险：

- 多条轨迹机械使用同一个动作序列；
- 所有阅读样本都被固定模板压成相同长度和相同路线；
- 模型为了套模板执行无关点击或无效往返。

但最终是否重复，必须由实际保存样本的任务文本、动作序列、页面状态和图像证据判定。仅把 `scroll×2 → click → back` 改成 `scroll → click → back → scroll`，不能自动证明两条样本具有实质差异。

### 4.2 既有四路判定不修改

| 路线 | 当前口径 | 对自由组合的实际影响 |
| --- | --- | --- |
| 截图 SHA256 完全相同 | 不同样本共享任一相同截图即命中；当前实现无普通跨样本共享豁免 | **相同静态首帧的独立重跑即使动作不同也可能失败**，自由组合不能解决 |
| 动作序列相同 | 逐步 `action_type + target_text + page_name` 全序列完全相同 | 真实目标、链接和顺序差异有帮助；只改叙述没有帮助 |
| 首末帧 dHash 相近 | 首帧与末帧的汉明距离同时 ≤4 | 需要真实开始/结束页面状态差异，不能靠裁切或改图 |
| 任务文本 SimHash 相近 | 任务指令汉明距离 ≤3 | 只换“月食”等关键词或改写少量文字不够，任务目标需有实质差异 |

需求约定近重复率 ≤0.1%；当前本地 QC 还保留更严格的零命中门禁和未裁决不为零即不放行。不能为扩大自由组合产量而放宽阈值、删除历史对照或添加“动作顺序不同”的语义豁免。

### 4.3 对后续生产的直接约束

1. **不要把同一静态首帧的多次独立执行当作多条可交付样本。** 即便后续动作不同，共享首帧也会触发截图重复。
2. 同页多条可以研究和候选规划，但正式有效集合必须经四路检测；同页不等于同样本，也不等于自动不重复。
3. 同一连续真实执行的切段共享边界是单独口径，不能拿独立重跑的相同首帧冒充切段边界。
4. 不同词条、不同关键词或不同动作数量只是输入差异，仍需结合任务、路径、页面状态和结果判定实质差异。
5. A/B 研究样本用于比较 effort 和机制，不因采集成功就自动成为两条可交付的不同样本；判重仍要单独报告。
6. 给规划器提供历史线索时，优先提供已有任务身份和动作序列摘要，避免明显同路线重规划；不得发送或复制原图来“规避”判重，也不得用规划期摘要替代正式四路 QC。

## 5. 动作相关最小证据与最小工程范围

### 5.1 简化原则

当前“区域外零像素差”是工程策略，不是客户需求。普通浏览器动作不再要求整页像素或 DOM 静止，也不再把无关动态浮层、公告、SVG、图片的复杂区域认证作为派发前提。

新任务应显式绑定新的执行/证据版本；V11 及历史任务的旧协议、旧收据和旧失败保持原解释，不能回写。新版本只改变执行取证策略，不改变动作空间、有效步、保存、QC或判重口径。

核心原则是：

> 不证明“整个页面没有变化”，只证明“当前动作目标没有跑偏，动作后的预期结果真实成立”。

### 5.2 普通动作前置只保留目标级检查

- click：目标身份唯一、当前可见、坐标和 hit-test 命中、未被遮挡；目标含义与当前计划一致。
- type：输入目标唯一且可编辑，焦点/全选等前置状态成立；输入后核对真实值，不检查建议浮层全局稳定性。
- hotkey/提交：当前焦点、值或按钮目标符合计划，只派发一次，然后等待动作特定结果。
- scroll：记录当前文档和滚动位置，执行后核对真实位移及新的相关正文。
- back：执行后核对 URL、标题和正文身份，不要求返回页所有动态区域恢复原像素。

与当前动作无关的搜索建议、公告、广告、图片、SVG 和间歇性重绘可以变化。只有它们实际遮挡目标、改变目标身份或属于本动作预期结果时才纳入检查；点击某条搜索建议时，该建议本身当然仍是受保护目标。

### 5.3 动作后只核验本动作预期

- 聚焦看 focused；输入看 value；提交看 search_results 或 document_changed；普通链接看实际落地；scroll 看位置与新正文；back 看原页面身份。
- 等待的是有界动作预期谓词，不是“两次整页截图完全一致”。
- 每一步仍保存动作前真实 PNG+同步 UI 树，以及动作后真实 PNG+同步 UI 树；不能补拍、合成或拼接不同状态。
- 已派发但没有后观察或预期无法核验时仍记效果未决，不推断成功/失败、不盲目重复动作。
- postprocess、capture audit、保存回算与在线执行共用同一动作级证据语义，不能只放松派发后又被旧全页稳态审计拒绝。

### 5.4 保留的非执行阶段检查

原始 PNG/DOM、目标命中、动作后效果、未决不重发、有效步数、目标 VERIFIED、单次正式保存和四路 QC 判重继续保留。四路判重属于保存/QC阶段，不阻塞普通浏览器动作。

### 5.5 最小工程范围

1. 新增直接词条基线文件和隔离研发工程，固定 candidate/objective/版本/SHA256。
2. 为新任务实现上述动作相关最小证据版本，优先调整现有 collect/browser 取证策略，复用当前 capture 和执行器；不再为普通动态浮层追加复杂类别认证。
3. 复用现有 `claim → first observation → V11 plan → React session → postprocess → RuntimeStore` 正式链，并同步执行、后加工和保存审计口径。
4. 提供单次、有界的长会话研发驱动，覆盖首帧、规划、全部动作、后加工、提交和只读回读；建议总上限 20–30 分钟，实际配置在实现报告中说明。
5. 长会话在 Kimi Work 内优先使用支持足够超时的单次 Python Blueprint Automation code execution，或在本机终端前台运行；不再通过 300 秒 Bash 前台调用，不使用 nohup、尾 `&`、setsid、disown 等遗留进程。
6. 记录实际动作序列、页面身份、有效步、搜索动作数、目标证据和重复判定输入；不因自由组合新增另一套动作有效性算法。
7. 复用现有 QC 四路判重，不修改阈值、hash、历史集合或有效样本接纳规则。
8. 不实施旧 r02 的废弃结算改造，不重写自由组合规划器，不删除历史动态区域实现；新策略只绑定新任务。

## 6. 验收

### 6.1 离线集成

至少覆盖：

- 直接词条入口在普通 `goal-evidence-2 + V11` 下，不使用搜索即可规划并执行 ≥5 个有效动作。
- 多种合法组合均可保存：同页多段滚动、目录点击、相关链接跨页、back 后续读、关联页滚动、第二次独立目的点击；测试分别构造，不把某一种写成唯一模板。
- 搜索框聚焦、输入、提交期间，建议浮层持续增删、SVG 重绘和公告轮换时仍可派发并取得 focused/value/search_results；这些无关变化不再触发全页稳态拒绝。
- 目标移动、身份不一致、被遮挡、hit-test 失败仍零派发；点击建议目标时目标本身仍受保护。
- 已派发但缺少后观察仍效果未决且不重复派发；动作前后 PNG/UI 树各自同步，不能用旧帧补新状态。
- 无效滚动、无目的重复点击、错误返回、关联页正文冒充原词条、搜索动作混入直接基线均不能获得本基线通过结论。
- 5 步与 VERIFIED 分开：走满 5 步但正文关系无证据仍 UNVERIFIED；自然不足 5 步不伪造普通流程。
- 动作序列不同但共享相同首帧的两个独立样本仍触发 route1；相同动作序列触发 route2；首末帧和任务文本阈值不因规划自由组合而改变。
- 长会话只提交一次；超时仍按原 interrupted/UNKNOWN 规则，不拼接、不遗留后台浏览器。
- 旧协议回放仍按旧证据版本解释，不用新策略改签历史失败。

### 6.2 真实直接阅读基线

集成通过后，在隔离工程中运行一次真实 GLM 会话，必须同时满足：

- candidate/objective 来自新冻结直接词条基线，`production_counted=false`；
- 真实 GLM 自主规划，实际搜索聚焦/输入/提交动作数为 0；
- 至少 5 个逐步有前后证据的有效动作，动作路线由模型按页面选择，不由驱动脚本代选固定序列；
- 页面存在无关动态变化时，动作级检查仍能工作；目标失效或未决仍如实停止；
- 发生真实向下阅读，正文证据支持“月食时月球与地球的位置关系”；
- `session_objective.status=VERIFIED`，正常完成，不是 trusted prefix；
- `disk saved=1`，新 Runtime attempt=`collected_pending_review`，单次提交，密封 SHA256 与只读回读一致；
- 报告实际动作序列、各步效果、GLM succeeded/invalid/UNKNOWN、自然耗时和保存状态；
- 对本次研究集合执行适用四路判重，命中或未决如实报告，不把研发保存数直接算交付产量。

分别报告动作派发数、后观察完整数、效果未决数、有效步数和正式保存数；不能用保存率提高替代交付质量判断。

### 6.3 单样本交付质量门禁

真实基线保存成功后，对**同一份保存字节**执行现有正式机械检查和独立 AI QC：

- 使用 quality-inspector 的正规研发/单样本审核链和显式审核计划，本条 AI 覆盖率 100%；规划 Agent 的自评不能替代独立 QC。
- 机械检查覆盖格式、图树同步、路径、字段、动作、有效步及适用四路判重；独立 AI 逐帧检查视觉对齐、终态语义、语言、隐私和实质差异。
- 审核绑定 sample ID、annotation、全部原图/树及规则版本的 SHA256，审核输出与模型账写在被检查数据包之外。
- `NOT_SELECTED`、未运行、invalid、UNKNOWN、待复核或 FAIL 都不是 PASS；需要真人升级且没有真实人工记录时保持未决，Agent 不得代签。
- 只有机械检查和独立 AI QC 均实际 PASS，才允许建议启动后续 A/B。单条 PASS 不证明整体交付质量，A/B 仍须继续比较独立 QC 通过率和效果未决率。
- 人工审核、发布和客户验收未实际执行时分别保持 NOT_RUN，不因单样本 AI PASS 改写。

原搜索基线保留未通过事实。真实直接阅读基线或单样本 QC 未全部通过前，不启动 A/B。
