## 宿主代码和页面检查

正式 `produce-entries` → `grounded_entries.produce` → 原发布/检查入口继续使用工程绑定的生产者 SQLite。`entry_access.shared_job` 在 `BEGIN IMMEDIATE` 内维护 `producer_page_checks` 唯一索引，键为工程、传输编码后的实际请求 URI、检查用途、公开匿名 GET 访问条件、应用别名登记路径和策略版本。索引引用原 `jobs`，不另建请求账；派发仍通过原 `BatchLedger.claim` 的短事务、attempt 和 visit 预约。

入口检查和首页/目录证据读取使用不同用途及策略，不能拿状态码收据代替 HTML。已存在的旧批作业首先保持本批原绑定；新批在发 GET 前索引原公开检查作业，引用原证据哈希。相同条件的确定 403/404 不随批号、重启或进程换号再发。来源批次与原 URL 写追加 `producer_page_check_reference` 事件，可由 job/result/visit 连接到检查状态、失败原因和原收据。来源站点、第一方 HTML、页面选择及未选中行继续沿用 Table1 的 application scopes 和 Table2 来源事件。

在途或已尝试未结算的原作业阻断替代派发；已落盘 HELD 收据仍是 HELD，不变成通过。新检查没有回收编号、删除失败或改写原请求。访问失败按 URI 记录，403/404 不推断整站不可用；现有未决保护保持。候选独占和目标身份仍由原候选契约决定：相同 GET 的不同合法目标可独立入池；业务参数保留，哈希路由候选身份保留，HTTP GET 不携带片段，因此可共享页面检查收据。

定向复核使用 `check_entry(..., recheck=...)` 的显式证据参数，不自动安排或重试：

- 403/404：原请求已确定结算，`condition=source_or_access_changed`，说明第一方来源修正或访问条件变化，提供 `reason` 和有效 `references`。
- 408/429/500/502/503/504：原请求已确定结算，`condition=temporary_fault_elapsed`，明确 `not_before` 已到，提供临时故障及等待依据的引用与原因。时间经过本身不允许复核 403/404。
- UNKNOWN/在途：先沿原账对账；证据或时间不构成新请求授权。

复核新建确定身份的原账作业，绑定 `recheck_of`、授权引用，追加 `producer_page_recheck`，同一授权重复调用只引用同一复核。原收据及默认检查指针保留；要使用复核结果须继续携带同一授权，不能默认用新成功覆盖旧拒收。本接口只允许公开 GET，不支持携带登录状态的检查。

## 宿主代码和类目查询

新入口支持 `produce-entries --category 在线工具`，可重复传类目。仅适用于 `entry-tools-3/4`，每批冻结一次计划，输出 1–2 个词并顺序执行；耗尽即结束并报缺额，不无限生成。显式 query/directions 优先，来源种子和既有目标先沿原路径执行；没有新增 category 字段的旧冻结批次配置保持原样，不触发新规划。

`producer_query_plan` 复用 `discovery_agent.model_decision` 的 `ai-search-plan` 和原 `PLAN_SCHEMA`。宿主先冻结输入，再发模型，冻结输出和引用；重启复用原 job/决定。历史输入包括工程搜索词及状态、累计查询结果（净新增和原始命中）、已发布行 NEW/重复/拒收分布、最近最多 32 条页面检查的失败及未决引用。本批反馈与历史反馈分开保存。模型未决阻断新规划，搜索 1113 通道保护在规划之前检查。

宿主执行原 `glm_search` 并用原 tool_requests 记账；结果继续经 Table1 第一方中文首页判类，Table2 第一方原文绑定选页、入口 GET、发布事务。规划词不充当站点分类或页面证据。默认规则选页，`--entry-selection model` 保留编号选页能力。

`source.site_origin.supply_kind` 按本单元进入 `site_context` 前冻结的事实分组，只统计实际产生本批 NEW 的不同应用：

## Agent 的 goal、prompt 和模型可见 I/O

查询规划 Agent 的 goal 是为目标类目发现此前未知且能产生第一方候选的中文应用。Prompt 要求功能型词、利用历史重复与失败反馈、避免重复，不返回 URL 或直接判断分类；原网页文本不具备指令权限。

查询规划阶段没有新增模型可调用工具，使用原结构化 JSON 输出：输入为冻结的类目/历史/反馈；输出 `{"queries":["功能型词"]}`，1–2 项，每项 1–70 字。搜索是宿主工具，模型不自行执行，也不接收伪造的执行成功。后续站点 Agent 看到独立 `submit_site_classification` 的首页原文编号及枚举；页面 Agent 在模型选页模式看到 `submit_entry_ids` 的冻结行号、页面类型及原文编号。其 goal/prompt、用途引文约束及旧冻结协议保持原实现。

工程验收看原账身份、并发零重复、输入输出冻结、正式入池及重启零派发。Agent 的离线验收只证明受控输出可沿正式链消费，不证明真实模型会发现有效新站。真实新站质量和首帧可用性另验。
