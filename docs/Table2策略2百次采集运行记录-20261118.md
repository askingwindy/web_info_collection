# Table2 策略2百次采集

本轮按 2026-11-18 用户授权，从当前正式工程 Table2 选择 100 个已发布、未领取且来源证据有效的候选，20 个消费者进程各处理 5 个。100 次指固定 100 个候选的消费尝试，不以保存数量补位。只使用策略2；规划准确度、模板选择和目标证据标准保持现状。

工程故障允许停派、等待自有进程退出、修复、验证后重启未执行部分。已有 claim、失败原件、模型 UNKNOWN 和 reserved 保留，重启不清账、不重发未决请求。正式库沿用原工程绑定；启动前使用已有备份/WAL准备入口，不创建替代账本。

本轮运行与选样原件放在 `results/table2-strategy2-100-20261118/`。Git 维护代码、纯离线验证脚本和本文的问题处理记录；数据库、原始请求、截图及日志沿既有忽略规则保留本地。QC、人审和发布不属于本轮采集。

## 启动前工程处理

- F01：为入口 HTTP/超时及登录拒绝保留业务分类，避免三页不可访问被错误归为同一程序缺陷并停轮。
- F02：消费者预留前 DNS 复用现有可终止解析进程，检查截止与停止；安全重试完成后再次检查预算。
- F03：普通领取不再扫描并修改无关历史过期 claim。
- F06：外围执行异常写入原始处置、异常类型和故障特征；已有封存收据纳入正式失败引用。
- F05/F08：终态必须有关闭证据；原账 UNKNOWN 若含 HTTP 响应证据，仍计入真实 HTTP 请求数。
- F09：准备、自检、账号探针、派发都进入同一退出/自动报表边界。
- 固定执行器支持现有 Table2 的多站100页，20×5分片；单独的双站基线冻结仍要求各50页。逐会话运行日志集中到本轮目录，供原生报表读取。

F04/A01 的跨根路径机制不在本轮改造范围；沿用无 workspace marker 的正式工程与原绝对路径。F07 模板路由属于本轮明确不调整的准确度问题。上述修复不宣称 S1–S6 整体审核关闭。
