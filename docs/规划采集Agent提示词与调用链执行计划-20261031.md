# 规划采集 Agent 执行计划 · 提示词、GLM 调用链与交付判据

目标是让一个已独占领取的候选在同一浏览器上下文内形成有证据的连续轨迹，并产出能独立审核的样本。运行环境是单机，可有同机多进程。Agent 在领取进程内直接运行，复用现有网关、本地账本和证据目录。候选、页面身份及租约由[消费者计划](消费者独占领取与会话接入执行计划-20261031.md)负责。下文分析现状并给出待验证的提示词和调用建议。给新工程 Agent 的是另一份[执行 prompt](规划采集Agent提示词与调用链执行Prompt-20261031.md)。

## 1. 当前模型实际看见什么

当前每轮从 `ReactSession._prompt` 取宿主的固定指令、入口、目标、当前观察、工具说明、已执行轨迹、上次工具结果、近期失败原因和预算。网关构造新的 `system + user` 消息，把上述内容序列化到 user 文本并附当前 PNG。它向 GLM 注册一个 `react_decision` 包装函数，宿主再分发内部的 `observe/inspect/act/finish`。原图只读，host 校验目标、状态和动作后才派发。这些都是应复用的能力。[ReAct 循环](../projects/code/webcollect/react_session.py) · [观察投影](../projects/code/webcollect/agent_observation.py) · [实际请求构造](../projects/code/webcollect/model_gateway.py)

| 现状与证据 | 对决策或交付的影响 |
| --- | --- |
| 固定指令在每轮 user JSON 的 `system` 字段，既要求“只输出 JSON”又请求原生函数。工具用法同时存在于中文说明和外层 Schema。`tool_call.arguments` 在外层仅限 object，动作嵌套结构到宿主才细验。 | 模型可以返回语法正确、无法执行的动作，或给纯内容而没有工具调用。静态政策、页面文字、动态证据应分角色传入。 |

| 每轮带当前 PNG 是正确的。文本同时带完整控件列表及各动作的三态、HTML 开头、历史轨迹和静态说明。`compact_trajectory` 有预期和“是否变化”，缺少突出展示的具体前后差异。 | 模型很难从大量未探测控件里挑出下一步，也难判断刚才是否达成预期。应先传能做决策的控件与真实变化，保留覆盖范围和按需取回剩余材料的能力。 |
| 已显式启用 thinking，原生工具已返回过结果。启用工具的成功响应中有 101 次走 `react_decision`，21 次走纯内容回退。解析器读取第一个调用，缺少“恰一个、名字在声明内”的校验。离线错名加双调用反例被接受。 | 目前的“成功响应”包含不同协议。新版本必须单列协议错误、禁止错误结果驱动动作，并把账本缓存身份与旧调用隔离。 |
| 每轮重新发送两条消息，工具结果由下一轮 prompt 摘要带入，没有官方交错式对话的 assistant/tool 历史。`max_model_calls=10` 跟随逻辑轮次扣减，而每轮网关允许最多 3 次尝试。 | 当前有单一浏览器会话，但模型通信是逐轮重组。一次轨迹的实际请求、费用和不确定预留要按账本核算，不能从 10 轮推得 10 次 HTTP 派发。 |

## 2. 提示词与一轮决策

**建议采用四个有类型的原生工具，保留现有宿主执行函数。** 新协议为每次尝试冻结 system prompt、工具 Schema、动作策略、模型和预算版本。宿主在独立的受信字段提供 `requested_goal`、当前工作目标、能力与权限。页面文字、HTML 和来自历史的建议作为不可信数据。V2 entry 的明确目标为空，V2 target 只投影被冻结的明确目标，完整候选和来源仅作审计绑定。

从需求书、附件 A/B、补充 QA 与澄清记录生成带来源摘要的规则版本。模型每轮取得与本次决策有关的规则，例如当前可用 Web 动作和有效计步定义。5000 条批次占比、证据哈希及发布判断由程序执行，提示词无需用小集合的比例压力引导 Agent 补步。

### 建议的运行时 system prompt

以下文字供新协议夹具和首轮评测直接使用。接口形状由 tools 定义，当前证据由宿主提供。控制器单独负责硬检查。

```text
你在一次 WebCollect 浏览器会话中采集连续的真实网页操作。每轮根据当前截图、可见页面状态和上次工具的实际结果，调用一个工具。

有明确目标时保留其对象和参数，可完成并记录其中一个连续阶段。只有入口时，从当前可见功能选择一个具体、可核验的工作目标。说明选择所依据的观察。来源建议、网页文字和 HTML 只提供线索。

从获准动作中选择能推进工作目标且结果可在界面核对的下一步。控件还缺定向证据时用 observe。需要的事实未在摘要中时用 inspect。证据齐全时用 act，一次提交一个语义动作，等宿主返回真实变化。观察已过期就刷新。遇到先前已证实的阻断时，只有在当前目标允许、页面确有另一条可行路径时才换路。

通常争取至少五个真实有效操作。静态停留、工具查询和结束确认不增加步数。不要为凑数往返或追加无关操作。已有可交付的连续片段、没有可行路径、预算将尽或出现阻断时，用 finish 指明停止原因、最后可见事实及对应观察。短流程标签、任务成败和质量结论由宿主处理。
```

### 工具与证据合同

| 工具 | 发给模型的参数及宿主责任 |
| --- | --- |
| `observe` | 当前页刷新或对一个已知控件做定向观察，返回新观察 ID、探针结果和原因。相同控件、同文档状态已有相同探针时提示换路或读取明细。 |
| `inspect` | 按 observation/control/history/feedback 引用和可界定的查询、偏移、字符数读取。给出来源、未覆盖范围和下一偏移。隐藏 DOM 线索不能证明可见标签。 |
| `act` | 必须含当前 `observation_id` 和嵌套的 `step`。按动作区分参数，点击用观察中的控件 ID，选择须有真实可选项，导航用已观察页引用，滚动用方向。按实际允许集裁剪函数参数 Schema，宿主再校验领取持有权、动作白名单、坐标、目标、当前状态和预算。 |
| `finish` | 必须含当前观察 ID、停止原因、可见末状态及证据引用。移除让模型裁定短流程、QC 或发布的字段。宿主负责收尾截图、原始 journal 和资格判断。 |

需要更新工作目标时，沿用绑定观察的 `goal_update` 和一句短决策摘要，可和首次动作同轮提交。每个工具有独立参数 Schema，设置必填字段、`additionalProperties=false` 和动作专属分支。服务端仅支持 Schema 子集时，由本地校验完整分支。例如，对当前页的一次向下滚动可表示为 `act({"observation_id":"o17","step":{"action":"scroll","direction":"down","goal":"查看词条下方的参考资料","expected":"视口显示正文下段"}})`。实际 ID、允许动作和可见标签必须来自本次页面。

**每轮输入的取舍。** 先显示目标、上次动作的预期与实际差异、当前截图及页面名、相关已证明控件、需要补证的候选控件、当前可执行页面动作和剩余预算。动作集合取附件 B、任务权限、执行器能力和当前页面事实的交集。可探测但尚未证明的控件单列，保留原因、完整数量和 `inspect` 入口。宿主从真实证据提取值变化、焦点、滚动位置、文档或标题变化，给模型“发生了什么”。缩短重复说明、无关 HTML 前缀和本地路径。所有观察的原件、截图与引用保留。一次已知 WAF 命中可以降低同一分支的优先级，不封死整个应用或把阅读设成所有站点的首选。

## 3. GLM 调用、限流与请求预算

1. **开启新对话。** 每个新尝试固定已授权账户、模型/端点、prompt/schema 版本和预算。首次发送受信 system、冻结 tools、目标/观察与原始 PNG。选择 `tool_choice="auto"`、`thinking.type="enabled"`。宿主用 JSON Schema 校验 function arguments。GLM 的 JSON 模式不等同供应方严格 Schema，视觉路径不把 `response_format=json_schema` 当必需参数。[模型能力](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash) · [函数调用](https://docs.bigmodel.cn/cn/guide/capabilities/function-calling) · [结构化输出](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output) · [对话补全参数](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)
2. **一轮恰一个工具。** 检查响应完整、恰一个 tool call、有唯一 call ID、函数名在本轮声明内、参数可解析并通过该函数的 Schema，再交宿主执行。错名、多调用、纯内容、损坏 JSON 或平铺 act 参数均为协议失败，零浏览器动作。仅已确定结算的格式错误允许在原作业内有界纠正，有机器可读原因，计一次新请求。旧调用者的内容路径、缓存键、冻结版本和旧收据原样可读。
3. **把真实工具结果送回同一对话。** 保留上一条 assistant 工具调用，再发 `role=tool`、相同 `tool_call_id` 与宿主实际结果，按需补新的当前 PNG。交错式 thinking 所需的 `reasoning_content` 作为不透明协议字段按原顺序传回，只在受控调用链处理，不进入标注、提示词示例或普通报告。明确选择端点是否采用 `clear_thinking=false`。历史前缀、图片、工具 Schema 和输入预留按实际序列计费和核算。预算不足由宿主有证据地结束，不默默丢图、截断必须回传的协议字段或另开无账会话。[智谱思考模式](https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode)
4. **分开扣决策和真正的请求。** 建议只在新策略的实验组试 **12 轮决策、每尝试最多 24 次实际模型请求**，同时受原账、原时窗和已授权较低预算约束。预留最后一次决策及收尾观察，耗尽时即使没有模型 finish 也由宿主封存。每次 HTTP 派发前在原账事务中按 attempt 预留，跨进程和重启共用。已派发的无效响应、纠正、UNKNOWN 均占额度，命中既有缓存不新增派发，纯本地零发送失败单列。不得修改已冻结的 10 轮策略。观察次数、实际动作和时间另有上限，5 步是长度门槛，不是停止指令。
5. **按业务码和账户处理。** 当前网关每个会话选一个 key。单进程先串行发请求，沿用原账的派发间隔。多个本机进程共用同一账户时，在现有 SQLite 作业账的预留事务里，用非密钥账户标识按模型检查在途数和间隔。四本试验账的四次 HTTP 429 均为 1113，应暂停该账户并核对余额。1302 按账户退避，1305 按模型退避，额度窗口采用提供方给出的重置时间。下一次独立会话可选其他已配置且有额度的账户。原请求的身份、费用和 UNKNOWN 保留在原账，对账前不得换号重发，401/403 沿用原认证 hold。[错误码](https://docs.bigmodel.cn/cn/api/api-code) · [速率限制](https://docs.bigmodel.cn/cn/api/rate-limit)

用合成滚动夹具检查一次往返，下列顺序可直接在 mock 网关断言。

| 消息或事件 | 预期内容 |
| --- | --- |
| system，user | system 放稳定采集规则。user 放当前目标、观察 `o17`、允许滚动和当前 PNG。 |
| assistant | 一个 `tool_calls`，ID 为 `tc7`，函数为 `act`，参数绑定 `o17`。宿主保存原响应并校验。 |
| 宿主执行 | 租约有效，派发一次。由动作前后的滚动位置和同期截图取得 `o18`。若状态已过期则返回零派发，若派发后未知则停机待核。 |
| tool，下一轮 assistant | `role=tool, tool_call_id=tc7` 返回真实结果、是否派发、有效动作增量、`o18` 和可见差异。下一轮在同一对话中接收与 `o18` 绑定的原图，再决定下一步。 |

## 4. 计步、终态与保存

从封存原始动作重算。每个计入的原子操作要有唯一派发身份、实际执行成功、动作前同步 PNG/树、参数与目标，以及能由相邻状态验证的对应效果。同一派发重复引用只计一次。`set_value` 按实际执行的 click、hotkey、type 等逐个核验。静态阅读、`observe/inspect`、`wait/complete`、未派发、无效往返、零效果和 UNKNOWN 均不计步。没有证据解释的缺口，不得跳过后把两段拼成合格轨迹。后台动画或无关像素差不能单独证明目标动作有效。

| 实际有效动作 N | 后加工 |
| --- | --- |
| N = 0 | 只存原始终态、失败或无路径原因。 |
| 1 ≤ N ≤ 4 | 派生 `short_flow=true`。依据真实停止原因、末观察和已发生动作生成具体原因，可核验且满足单条规范才进入待审。模型漏报仍按实际长度处理，原因缺失、采集不完整或 UNKNOWN 留待核对/拒绝。 |
| N ≥ 5 | 常规长度，`short_flow` 为 false 或按现有 schema 省略。动作、目标、可见终态和重复门禁仍需分别通过。达到五步不自动结束，超过十步不自动切段。 |

分别记录宿主停止原因、业务是否达成和交付 `completion_status`。例如明确搜索目标遇到 WAF，末帧只能支持“请求被阻止”。仅当任务允许可控异常、证据完整且符合单条契约时才可派生 `controlled_exception`。否则留作失败。允许以可验证的中间状态收尾时，要如实描述该阶段。末步 `complete` 确认实际末帧，不能凭模型说法把业务失败写成 success。

先封 raw，再从原件派生新版本。交付样本仅含 `annotation.json`、连续命名的视口 PNG 和同名同步 DOM 树。坐标是截图像素整数，点击落在目标框内，元素 ID、文本和真值对应。单条分辨率固定，`final_state_image` 指向末步原图。控件真值、内部收据和 QC 在客户样本目录外，客户批次含 metadata、质检报告和 SHA256SUMS 等原要求资料。快捷键交付用 Windows 记法，保留执行原参。取消时封存已发生的部分，硬崩溃只按原日志对账。重加工写新位置和收据，不覆盖旧结果。生产成功最多为 `collected_pending_review`。[原始需求](../request/web操作采集需求/需求书-Web浏览器自动化操作轨迹数据集.md) · [动作与坐标](../request/web操作采集需求/附件B-动作空间与坐标系.md) · [有效操作口径](../request/轨迹采集口径补充-20261030.md)

## 5. 试跑和正式批次

### 有界试跑

- 逐条核查真实执行、字段、中文界面与标注、同步帧/坐标、可见末状态及四路重复。记录小集合的实际比例与命中对，允许对显式试跑集合中的单条独立审查、记 FAIL 或 PASS。可复用 `ai_worker.prepare` 的显式集合/样本绑定，为校准收据使用单独用途。现有 `delivery_pipeline.prepare` 要求正式跨包 PASS，保留其门禁。试跑审查不授予正式批次接纳、发布或客户验收。[独立审核准备](../projects/quality-inspector/quality_inspector/ai_worker.py) · [正式集合验证](../projects/quality-inspector/quality_inspector/delivery_scope.py)
- 工程端到端的真实验收要求至少一条实际采集、整条加工并经独立 QC 实审通过。为评价提示词，建议另取至少 3 个整体应用，覆盖阅读导航、表单输入、筛选/选择等不同动作族，所有候选样本实审。保留失败尝试和 UNKNOWN 的分母。试跑前须另定真实授权范围、尝试数、原账及费用上限，不能反复消费同一候选刷成功。
- 比较改动时先固定安全、计步和终态合同。用冻结的离线观察做成对协议回放，只证明提示词构造和工具分派。后续若获真实试跑授权，用按应用/动作族匹配的不同合法入口比较同一严格工具协议下的旧措辞和新提示词。保持账户等级、模型版本和预算可比。再单独比较 10 与 12 轮，避免同时改变多个变量。记录所有分支与分母，包括零派发、已派发 UNKNOWN 和处理中止。稀疏组只报告事实，不从一个网站估算量产成功率。
- 记录四级转化，分别为正式尝试、达到 5 个有效步、生产保存、独立 QC 通过。同时记录协议错误/重试、重复探针、越权建议、有效动作每步耗用的决策和请求、输入/缓存/输出/推理 token、耗时和每个实际 QC 通过样本的成本。推理已含在输出时不重复相加，缺失用量保留未知，零通过时单位成本未定义。比较必须先满足越界派发、UNKNOWN 自动重发、虚假成功均为零，再评估转化与成本。

### 正式批次

冻结本批 5,000 条去版本重复的有效成员，并绑定当前链历史。另外对累计有效集合检查。5,000 是质量批次窗口，物理 ZIP 大小按既有交付约定。候选、失败、撤回、UNKNOWN 和未决项不充当分母。批次不足时报告实际数和缺额。

| 指标 | 正式放行规则 |
| --- | --- |
| 短流程 | 本批 `short_count / 5000 ≤ 2%`，最多 100 条，累计也 ≤2%。 |
| 四路判重 | 任一步 PNG 的 SHA-256 相同、完整“动作类型＋控件文字＋页面名”序列相同、首末帧 dHash 距离均 ≤4、任务 SimHash 距离 ≤3。四路取并集，近重复涉及的本批唯一样本数除以本批数 ≤0.1%，最多 5 条。命中历史的当前样本也入分子，历史样本不得稀释本批分母。每路报候选对与裁决，未裁决为 0。现行正式门禁要求精确帧/全序列两路零命中。独立执行共同首页没有例外，本轮不做切段。 |
| 类目与视口 | 单一站点类目本批最多 1,000 条，累计 ≤20%。整体应用统一归类，中文可见文本 ≥70% 且导航与控件为中文。全集视口 ≤3 种。 |
| 其他分布 | 实际任务类型每条 1–3 个、取原 14 类。动作、有效步数区间、应用/任务族报告分布。无额外固定配额。将实际分类、版本、样本摘要和四路指纹按 `sample_id` 入索引，复用 QC 的确定性实现。规划时只用这些统计调节候选优先级，正式判定仍核验原件、冻结成员及规则版本。 |
| 审核接纳 | 程序检查 100%。稳定组 AI 抽 10% 向上取整，启动前 10、新组前 5 和风险样本必审，问题扩至 30% 或 100%。区分实际 AI PASS 和 `NOT_SELECTED` 且获得批次接纳。另报撤回、人工审核、发布与客户验收。客户每批随机 2% 真人抽检按原验收执行。 |

分类索引建议按样本 ID、派生版本/摘要和规则版本绑定整体应用、站点类目、实际任务类型、动作/步数分布、短流程及其原因。指纹引用每步 PNG 摘要、完整序列摘要、首末 dHash 和任务 SimHash。以冻结成员关系区分批内、命中历史和历史独有的配对。20 万规模复用现有精确哈希与汉明距离候选索引，无需逐对遍历所有历史样本。任务族相同可以作为规划提示，不能独立裁定一对样本重复。

当前 `_react_collection` 会把派生拒绝连同程序异常一起置为 program failure 并暂停 scope。建议给确定的精确帧冲突独立的拒绝原因，保留完整原件、命中对与原账记录。程序异常、提供方故障、站点真实失败和确定重复分别记账，已有 hold 仍按原规则生效。[当前派生与提交](../projects/code/webcollect/collect_runtime.py)

历史精确帧占用保持可追踪。试跑中的命中可留下原件和诊断，不能让两个相同静态帧进入正式集合。若要让已正式剔除的样本退出活跃占用，须另有明确版本化裁决、原成员与替换成员的绑定和原子重验。此次已确认的比例不授权释放既有占位或改写 v22 的审核记录。[四路实现](../projects/quality-inspector/quality_inspector/duplicates.py) · [累计门禁](../projects/quality-inspector/quality_inspector/cumulative.py) · [补充 QA](../request/qa) · [抽检与计数](QC抽检与批次合格计数方案-20261030.md)

## 6. 执行顺序与交付证据

| 顺序 | 改造与离线验收 |
| --- | --- |
| A1 · 捕获基线 | 以当时源码和旧收据为基线。用合成页面、mock GLM 固定复现错名、多调用、纯内容、act 参数平铺、权限冲突、空/明确目标和取消缺收据。保留旧协议用例。 |
| A2 · 工具与请求 | 改 `react_chooser/ModelGateway/BatchLedger` 新版本入口及调用身份，接入原生四工具、同会话历史、账户健康与真实派发计数。并发下第 25 次实际请求必须在派发前被拒。证明超时/429 后零盲目重发，缓存命中、错误回退和未知金额能分别统计。 |
| A3 · 提示词和观察 | 从同一动作合同生成可见 Schema、页面动作与宿主校验。验证禁用 back、过期观察、重复 focus、复合动作拆分、检查缺失证据后再决策。按真实变化组织上下文，比较每轮字节与 token，不预填节省率。 |
| A4 · 派生和交审 | 验证 0/1/4/5 步、反向滚动、wait/complete、零效果、派发后未知、WAF、控件真值、哈希不一致、派生中断。验证试跑单条可审、正式 100/101 短流程、5/6 个近重复涉及样本、1,000/1,001 类目、跨批重复、旧收据重用范围。审核语义变化升级受影响规则版本。 |
| A5 · 联调与校准 | 和消费者一起从正式 CLI 用临时库、假页面、假网关跑通 claim 到独立 QC 交接，输出数据边界及选定离线报告。真实采集、独立 AI 实审和正式 5,000 验收逐项标明是否实际验证。 |

将交接 prompt 发给执行 Agent 时，默认任务范围为离线工程。校准样本数、12/24 预算和对照方法均为建议，真实运行需另行明确授权。
