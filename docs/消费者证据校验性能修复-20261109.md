# 消费者证据校验性能修复

2026-11-09。用户已确认本轮集中实现；禁止集成测试和原件回放，修改后仅通过既有正常入口运行一条固定生产表基线，模型首轮和分支均 high。批量采集保持停止。本文中的性能数字为修复前证据，实际节省须以本轮运行收据为准。

## 必要设计

1. 新动作级证据只对点击、输入和绑定控件的热键比较目标框外扩 4 px 的像素。文档级动作、首屏和动作后观察不计算无用途的全图差分，显式记录像素未检查；完整原始 PNG、尺寸校验、摘要、DOM/身份/命中与业务效果检查保留。该证明字段变化显式升级动作级证据版本，旧版本按原义复验。历史全图规则仅优化空差异判空和变化边界扫描，保持完整证明与遍历顺序兼容。
2. 同一次顶层处理内复用同份密封证据的 anchor/frame 校验；复用依据包含证据实际字节摘要及规则，不能只用路径或对象身份。任务身份、claim、租约、到期和实际页面/轨迹状态每次仍检查。去掉计划发布的直接重复校验，发布和验证共用只读校验与收据计算；不建立跨进程或持久缓存。
3. 同次收尾只构建一次已核验原始记录，将结果传给前缀判断、投影与后处理。有效轨迹核验一次供派生使用。独立恢复/加工入口自行完整验证；复用期间原件变化必须拒绝，原 source 不被前缀投影反向修改。原 UNKNOWN、失败尾部、有效步数、目标状态、去重与保存规则不变。
4. 复用现有阶段计时，必要时补充小范围计时/调用计数用于本轮真实验证。不要引入新的调度、数据库同步或历史缓存改造。

## 实施和验证边界

保留当前未提交改动，集中改完后只做静态源码检查，不运行单测、集成测试或历史原件回放。真实验证只运行一次固定目标的研发会话，使用冻结 high/high，单会话最多 25 次真实 GLM 派发。失败不自动补位或追加第二条。

用户随后明确确认主区及旧研发 worktree 的 `results/`、`verify_results/` 已删除。本轮因此无法沿用原候选 claim/账本或复核历史计时；使用新独立研发工程，经正规 `baseline_import` 登记固定月食目标，不复建旧编号、旧请求或旧 PASS，不称为原会话恢复。原业务目标和档位保留，仅新输入的候选绑定和动作证据版本改为 v2；原冻结文件不修改。新工程仅有这条研发基线，不计生产新增，也不据其声称已对账旧 UNKNOWN。

选择已有同目标 high/high 记录作为对照，比较总耗时、启动、模型等待、取证、前缀/后处理和最终提交。动作数、模型调用数及页面变化一并报告。单次前后差异是实际观测差异，不证明全部由本轮改动造成，也不外推整批吞吐。原件不覆盖，新增验证证据写入新目录；保存最多为 collected_pending_review，QC、终审、发布另列。
