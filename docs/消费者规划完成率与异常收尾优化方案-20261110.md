## 1. 当前问题与结论

需要做小范围工程改造，并同步修改 Agent 看到的协议。仅继续增加提示词不足以解决当前问题；也无需另建规划框架、审核 Agent 或分布式服务。

优先解决：**普通任务自然达到 5 步且可完成、首轮协议填报负担、跨页检查项的真实来源绑定、正文引用抄写与身份错配**。另须在现有导出/计数/QC 集合选择中排除 `controlled_exception`，才能落实最新交付要求。主动停止后的可信保存仅用于保全内部执行记录；它不提高原目标完成率，不能再用于补交付数量。

## 2. controlled_exception 的含义与最新交付要求

### 旧格式、内部事实和新交付资格分别解释

1. **旧需求字段。** [附件 A](../request/web操作采集需求/附件A-字段说明.md)定义为“可控异常”；旧[需求书第 4 节](../request/web操作采集需求/需求书-Web浏览器自动化操作轨迹数据集.md#4-格式)曾允许 `success` 或 `controlled_exception`。**用户本次明确需求方已拒绝 controlled_exception，后续交付按新确认执行。** 此前仅据旧枚举推断“异常片段仍可交付”的结论不再适用；原需求文件作为历史原件保留，变更写入[需求澄清](../request/需求澄清记录.md)。
2. **当前消费者实现。** [postprocess.terminal_outcome](../projects/code/webcollect/postprocess.py)将可信前缀、部分有据异常收尾标为 controlled_exception，表达“保存范围可信，但完整原目标没有确认完成”。末步 complete 和每步 tool_result.status=success 是交付格式与已保存操作的状态，不代表全业务目标成功；排除的失败/未知尾部仍留原账。
3. **实现与要求的差距。** 当前[格式检查](../projects/quality-inspector/quality_inspector/format_checks.py)及 [AI QC 片段规则](../projects/quality-inspector/quality_inspector/ai_worker.py)仍可能接受可信异常片段；这种旧规则的 PASS 不能授予新交付资格。后续需在已有交付策略中明确排除异常，保持内部真实性审核与客户准入分开。`success` 也必须有原目标完成证据并通过适用 QC，不能只检查字符串。

旧批次明确选择“5–10 步可信交付候选；可包含原目标未完成片段”，只解释旧批次如何停止。最新确认覆盖未来交付中的这项许可：**新交付集合中的 controlled_exception 应为 0；内部保存和失败分母不能删除。** 旧收据、原件、编号、异常与 UNKNOWN 原样保留，不重标 success。历史片段口径见[原片段补充](../request/轨迹采集口径补充-20261030.md)，不再作为新交付准入依据。

### 怎么减少

- 将已经实际完成、仅被字段或来源绑定误拒的任务正确识别为完成；不改旧事实来“刷 success”。
- 对确实未完成的任务，在当前会话修正剩余动作、读取缺失正文或确认计算结果；只有原目标得到真实支持才申请完成。
- 新自由目标从当前页面能完成的具体任务中选择，避免把一次浏览扩成多个不相关问题；已固定目标不可因失败缩小。
- 主动 stop 的保存修复单独衡量“有用记录丢失率”，不当作降低异常率的措施。
- UNKNOWN、内容不存在、动作未产生效果等真实未完成继续如实标记并内部保存。交付排除它们只是满足要求，不代表采集质量改善；需同时报告异常/全部尝试及异常/全部保存结果。

### 规划必须 ≥5 是否可行

建议把它作为**普通新任务规划准入条件**，同时按最终真实动作验证。单靠 JSON 中列出五步不够；它可能包含空操作、遇到缺证提前停止，或实际上三步就已完成。原需求本来就要求普通交付 ≥5 步，加强规划能更早减少短流程，但不能代替执行和目标核验。

- 只对首次完整成功路径估算 5–10 个必要有效动作，不能将互斥分支、备用恢复动作相加凑五步。包含实际需要的聚焦、输入、提交、定位或查阅；读截图、引用、等待和 complete 不凑步。已有默认值正确就不重复选择。
- 先判断页面是否支持任务及其完整路径。若自由目标只有自然 1–4 步，优先选择该页确有用途的另一完整任务；找不到就记录不适合本轮普通长流程，不临时添加无关操作，也不把页面标为失效或改生产者原候选。
- 目标一旦冻结不再为满五步扩大或缩小。重规划只处理剩余问题：已完成 4 步、剩 1 步时只规划 1 步，累计事实不重置。
- 执行 3 步就已完成目标时立即结束，标 short_flow 并单列；执行 5 步仍未完成则继续原目标所需动作，不能提前标 success。累计 10 步仍未完成按现行工程策略结束并内部保留，不交付异常片段。
- 建议下一轮普通达标计数只纳入**实际 5–10 步、有原目标完成证据、正常保存的待审候选**；short_flow 不补这项普通目标，单列且仅在适用交付集合 ≤2% 的范围讨论少量例外。不能把“short_flow 少出现”解释成强制所有任务执行满五步。

这项要求可能减少可选任务供给，因此同时观察规划拒绝/跳过数、短流程产生率、完整目标完成率和正常完成候选/小时。避免用更复杂目标把短流程变成更多异常。

## 3. 工程最小改造提案

以下是拟议改造，字段示例不是现有接口。复用现有 Controller、ModelGateway、正文目录、postprocess 和 QC handoff；不另增服务或规划 Agent。

### A. 精简模型填报，工程补齐已知字段

当前已有 `plan_schema(wire=True)`、`bind_reply_scope`、分支字段继承和引用补齐能力。普通 Wiki 首轮尚未一致采用这些能力，GUIDANCE 仍让模型回填 attempt_id/observation_id。应统一入口，而非再加一套宽松解析。

| 字段/信息 | 拟议责任 |
| --- | --- |
| attempt_id、当前 observation_id、版本及绑定摘要 | 工程从发出该请求的上下文绑定，验证前补齐；模型若显式提供冲突值则拒绝，不能覆盖冲突 |
| Wiki 固定完成协议、finish_when 占位、统一恢复规则 | 工程配置；不再让模型抄写固定占位文字 |
| 计划 band、最终 effective_steps/short_flow | 计划档位按计划长度生成；最终计步和短流程始终以保存动作事实生成，两者不混用 |
| 原目标 | 有固定目标时直接继承；只有目标未具体化的新任务由模型选择一次，接受后冻结 |
| 原目标必要检查项、下一段路径、动作参数、实际答案 | 仍由模型表达，工程不臆造业务内容或替换目标 |
| 已知控件名称/href、正文来源元数据 | 从本轮提供的明确控件/证据引用解析；未见控件不使用旧 node 绑定 |

模型只看到一种首轮结构和与它一致的示例，分支只显示本次真正可选的结构。提示示例由同一 schema 约束，避免再次出现“提示要求空值，schema 禁止空值”。普通导航/滚动的动作预期采用已有实效证明，不让模型预猜跳转后必须出现的答案关键词。

保留完整原始响应，归一化只接受可确定等价的表达；损坏 JSON 不靠猜测补出动作。格式纠错沿用现有会话和无进展处理，不新设统一两次上限，也不增加每步模型调用。

**预期解决：** 必填身份抄错、重复协议字段、示例与 schema 冲突、将动作成功绑到预猜答案。**不能保证：** 每次 JSON 都有效、页面可达或目标已经回答。

### B. 先修跨页来源，再让引用选择证据编号

来源绑定与引用复制是两个问题，必须一起处理。

**来源绑定。** 原检查项明确要求当前页时绑定当前页；明确要求某个已知词条/章节时绑定对应真实页面；要求“点击进入的相关条目”时，将该检查项关联到原计划中的查阅动作，按该动作的真实 href、落地及重定向证据绑定。不能把未填 page 一律解释成入口页。若未来页面尚不可确定，先保持未绑定，在原查阅动作发生后完成一次有证据的解析；无法唯一关联就反馈缺项，不任意扩展到已访问的任何页面，也不更换原问题。显式章节约束继续保留。

**证据编号。** 对已经归档、已核验且属于可保存连续区间的正文目录，工程分配会话内稳定 evidence_id，保存其原观察、节点、原文、来源页/章节及引出它的动作。编号不因排序、返回页面或再次观察而重新指向其他内容；不同页面的相同文字不能混成同一来源。界面可见文字与对应交付帧仍可追溯，不用未执行页面或隐藏正文证明阅读。

在已有分支提示中，按每项原检查展示符合来源约束的证据编号及短原文预览，同时保留查阅所需上下文。Agent 选择编号并回答问题，工程解析完整来源，不再要求它复制整段原文、长观察编号、node、URL 和 operation_id。

示意输出：

```json
{
  "choice": "finish_reading",
  "check_answers": [
    {"check_id": "c1", "answer": "对原问题的回答", "evidence_ids": ["e07", "e12"]}
  ]
}
```

工程验证编号属于原会话和允许来源、每项必要检查有引用、明确要求的动作确已发生。合法引用仍不能自动证明答案语义正确。未知编号、错页/错节、未知动作后的证据继续拒绝；反馈应给出“c2 缺少目标条目正文”及可用候选，而不是只返回难理解的内部错误。无新证据时不要求模型重复重写同一引文。

**预期解决：** 323 的跨页默认入口误绑定、引用复制及多字段不一致、看过正文但无法提交合法引用。**不能解决：** 页面没读到、原问题不可回答、回答内容本身错误。

### C. 共用内部收尾判断，交付另行准入

`finish_reading`、主动 stop、动作上限和执行异常都进入现有原始封存/收尾函数，用同一份已验证事实判断保存范围；终止原因作为事实保留，不单独决定同一可信区间是否能保存。

| 证据情况 | 预期处理 |
| --- | --- |
| 原目标按相应协议完成，证据绑定成立 | success 候选；语义 QC 仍独立 |
| 原目标未完成，但有合法连续动作和可信历史末边界 | controlled_exception 内部记录，原目标和未完成原因不改写；不进客户目录、不计新交付目标 |
| 0 个有效动作、缺可信边界，或未决效果无法隔离到已证前缀之外 | 原始待核；不凭步数或 stop 标签强行导出 |

1–4 步仍标短流程，5–10 步也必须有原目标完成证据才能进入拟议的普通完成候选计数。未知尾部不拼接，保留原请求、原编号和费用。取消时先停止新领取，已有任务使用相同事实封存；有足够本地事实时提交终账，效果无法确定时保留未决，不能为清零 running/reserved 重发浏览器或模型请求。

**预期解决：** 主动 stop 与异常保存入口不一致、取消造成的本地结账遗漏。**不属于：** 原目标完成率优化或自动降低 controlled_exception 占比。

### D. 在现有导出、计数和 QC 交接落实新交付要求
