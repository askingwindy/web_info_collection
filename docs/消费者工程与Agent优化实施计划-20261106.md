## 1. 目标、证据与范围

本轮同时解决两件事：**让规划能够根据完整的必要状态继续执行原目标；让后续故障不再阻断已有可信区间的正式保存。** 两条链分别验收，不能用短片段保存代替原目标完成。

| 已核实的问题 | 可采信的结论 | 不应据此推断 |
| --- | --- | --- |
| 普通分支 42 次请求：0 次响应校验成功、10 次 invalid_response、32 次 UNKNOWN | 首轮与后续分支存在明显差异，优先修普通分支出站协议、上下文和调用参数 | 不能只修带特殊契约的手工基线，然后声称普通批量入口已修好 |
| 42 次有 usage 的响应中，reasoning 占输出 94.46%；8 次首轮触及输出上限，7 次正文为空 | 高 effort 占用输出预算是明确问题，先在真实派发点降档 | 输出大于输入本身不是故障标准；不预设降档后可救回多少页 |
| 10 次无效分支中，7 次返回完整计划、1 次缺 ID、2 次 JSON 外附说明 | 存在协议与解析接入问题，不能全部归因于模型不会规划 | 仅抽查计划也不足以证明所有规划质量正常 |
| 32 笔 UNKNOWN 位于 12 页，均约在分支 180 秒边界超时 | 先处理阶段配置、生成耗时与原请求核对 | 现有证据不能独立证明供应商整夜普遍不稳定 |
| 后续请求有当前图、部分 DOM、目标、checks、当前步骤和末动作，但没有紧凑执行历史、完整剩余计划及必要页面映射 | 输入不是空白，但复杂续规划所需信息不充分，须调整信息选择 | 不应靠重复全文历史、reasoning 或更长 schema 解决 |
| 10 条封存未决记录中，8 条有非空可信区间，2 条为 0 步 | 8 条具备进一步派生核验的基础 | 不是 8 条正式样本，更不是 10 条待审样本 |
| 可信前缀要求至少 6 步，现有恢复仅处理 ready 后加工失败 | 短前缀资格和首次正式加工/登记两处都要接通 | 单改 `MINIMUM=1` 不足以完成恢复 |

## 2. 统一职责与状态

Agent 判断目标、路线、下一步和回答是否有据；工程负责真实工具能力、唯一身份补全、派发、取证、事实计量、原账和正式保存。共享工具必须同时说明宿主实现与模型看到的输入/输出，不以修改 prompt 替代工程接入。

| 维度 | 判断依据 | 与其他维度的关系 |
| --- | --- | --- |
| 原目标是否完成 | 原问题、参数、明确动作义务及已观察到的结果 | 片段保存成功不自动变成目标完成 |
| 浏览器动作是否已确认 | 原操作、同步前后帧、真实效果与连续性 | 已知无效果计 0 步；缺证才是未决，不能由样本未保存反推 UNKNOWN |
| 模型结果与费用是否已结算 | 原请求响应、usage 或合法提供方核对证据 | 模型未决不自动否定此前已确认的网页动作；派生保存也不能清除 UNKNOWN |
| 区间能否保存 | 同一原执行内的连续有效区间、可信边界、加工及身份/去重校验 | 1–4 步标 short_flow，≥5 步普通，0 步不成样本；分类不代替质量和保存资格 |
| 审核与发布 | 正式保存、独立 QC、人工审核及发布各自收据 | 采集成功最多到 `collected_pending_review` |

复用现有字段、事件与收据；只补缺失的区分，不另建通用状态机平台。历史原始终态与失败保留，新派生明确标记自己的范围。

## 3. 工程代码优化

编号沿用复盘中的 E1–E5，新增 E6/E7。**P0 为 E1–E5；E6/E7 同轮集中实现，但不阻塞无需新浏览器动作的历史区间派生。** 若某子项确实不能完成，单列证据与未验证边界，不能把其余通过包装成整体通过。

### E1 / P0：统一普通分支协议，并补齐后续轮状态

位置：`banded_plan.py`、`model_gateway.py`、`react_session.py`、任务生成与对应契约接入。

1. 同一份 schema 生成模型可见协议与宿主校验。首轮沿用 `submit_plan`；普通分支给实际允许的 choice，继续执行与重规划分清，重规划只提交剩余步骤。普通任务不出现宿主不支持的 `citations/finish_reading` 承诺。
2. 先做确定性归一化和唯一作用域绑定，再校验。缺省 attempt/observation ID 可从唯一当前请求补全；显式错误 ID 必须拒绝。复用已有 `bind_reply_scope` 等能力，消除网关与 Controller 的先后分歧。
3. 支持已出现且可确定等价的单 JSON、围栏、字段别名和计划封装。只有当前允许 replan、目标/checks 没变、剩余步骤无歧义时，才转换返回的计划；不能重放已执行步骤。单结构外附说明独立留存；多结构冲突、截断、业务歧义不猜补，不从 reasoning 抽取可执行指令。
4. 对已结算的格式错误，在同一决策内最多补一次具体字段反馈，计入原 attempt 和调用限额。UNKNOWN 不进入格式纠正；不增加第二层传输重试。
5. 模型原回包、归一化结果、执行选择分别留存。新任务拟用 `webcollect-banded-conditional-plan-9`；旧 V1–V8 和原失败保留原义。若实施时版本已占用，沿用仓库实际版本规则，不原位改旧收据。

后续轮由现有 Controller、trajectory 和 observation 生成下列内容。字段名可复用现有结构，重点是实际出站信息完整且一致，不为此引入新摘要 Agent。

| 必需内容 | 如何组织 |
| --- | --- |
| 不可变任务 | requested_goal、适用的 session_objective、参数与必须完成的 checks；working_goal 的调整须仍服务原目标 |
| 已确认进度 | 紧凑的已执行动作、实际参数、实际效果和事实摘要；预计结果与已见结果分开，原引用可回查，不能只传文件路径 |
| 失败与未决 | 零效果/失败/未确认尝试单列；说明是否已经派发、是否允许再次派发，不能把未知动作当成未执行 |
| 剩余任务 | 当前步骤、尚未执行的剩余步骤、未满足事项、本次分支原因和剩余预算 |
| 当前证据 | 当前截图及与本步相关的 DOM，保留目标、焦点、值、选项、正文/附件/登录提示、重要链接 |
| 工具能力 | 当前允许的 choice/action、页内查找与站内搜索的真实支持状态；允许 open_url 时附已登记页面映射 |

裁剪先保留任务相关证据，明确标记被裁掉或未观察到的信息，并提供已有的定向观察入口。不要将“本轮未提供”写成“页面不存在”；不重复完整 reasoning、整段历史或多份 schema。

验收：普通候选的真实调用路径发送上述状态及一致的 schema；已知失败回包得到合理归一化或具体拒绝；下一步不重放、不改题，能贯通正常加工和保存。仅检查源码中存在字段不算验收。

### E2 / P0：在真实派发点使用 low/low

位置：`react_session._native_chooser`、`ModelGateway.call_tool/call_message/_call` 及 boundary/request 记录。

- 新协议首轮 low、分支 low，使用已有单次调用覆盖参数。`first_plan_reasoning_effort` / `branch_reasoning_effort` 目前是运行记录，不能仅在任务 JSON 里添加这两个字段。
- 保持原 BatchLedger 冻结配置和账号绑定；明确调用覆盖值进入请求身份、实际 payload 和运行报告。不能修改旧 frozen config 或新开账绕过 UNKNOWN。

### E4 / P0：统一原操作收尾，分开模型与浏览器未决

位置：`ReactSession`、gateway、`collect_runtime.py`、`candidate_consumer.finish_or_reconcile`、RuntimeStore 与 BatchLedger 既有入口。

共同顺序为：**保留原派发 → 确认原结果 → 分类有效/已知零效果或失败/仍未知 → 继续、重规划或封存 → 独立判断区间保存与费用结算。** 模型和浏览器共用处理顺序，核实所需的证据各自保留。

1. 修复 `_record_business_attempt` 仅第 5–8 次异常才专门收尾的分歧。枣庄第 3 次滚动已有 `KNOWN_NO_EFFECT`，不应因 `RAW_PENDING/force_pending` 再变成效果未知。已知无效果计 0 步、原尝试保留；若继续，验证后续观察连续性，不删除中间尝试来拼轨迹。
2. 只在原活会话封存前补取同一操作的结果，复用现有观察与时间预算；取证/等待计 0 步。已经封存的历史执行只能核查原件，不能新开网页补造旧动作后的证据。
3. 10 个 claim 与 32 笔 UNKNOWN 分开列明绑定和处置。6 条最终因模型超时停止的记录占 24 笔 UNKNOWN，其余 8 笔也必须保留并核对。
4. 对模型请求，只有原响应、用量或可用的提供方凭证才支持结算。本地 request ID 不等于供应商可查询任务 ID，也不证明重发幂等。没有证据就保留 UNKNOWN，不能按超时记零成本。
5. `finish_or_reconcile` 主要补投影已提交保存，不能当作清空全部失败的接口。沿正式入口追加核对结果，不直接 SQL 改成功，不把有实际 attempt 的任务送入零执行结算。

验收分别列出“已确认并处置、仍缺证据、记录冲突”。不以清空全部 UNKNOWN 为完成条件；原隔离继续按候选/任务生效，独立且已结算的基线可按既有规则验证。

### E5 / P0：接通可信短前缀的正式派生、保存与登记

位置：`trusted_prefix.py`、`postprocess.py`、`collect_runtime.py`、`runtime._derived_recovery`、候选结果投影及保存收据回读。

1. 新派生规则拟为 `webcollect-trusted-prefix-2`，接受至少 1 个有据有效动作；1–4 步 short_flow、≥5 步普通、0 步拒绝。V1 六步规则继续解释旧收据，不直接全局改常量后重解释历史。
2. 从同一原 attempt 开头取连续区间，终点为最后纳入动作的原可信 after 帧。可按业务意义选择更短前缀；不能跨越未知中间动作、拼接其他执行或纳入失败尾动作。
3. 派生规则、source attempt/原编号、原收据摘要、起止动作与观察、排除尾部、原目标绑定都进入派生收据。原 requested_goal/session_objective/working_goal、原终态、失败和截图不改。本文这批片段按 `original_goal_completed=false` 描述，不能包装成整个目标成功。
4. 派生任务说明只陈述区间实际发生的事，保留与原目标的来源关系。点击河北省不等于进入办理页，看到附件不等于阅读正文，聚焦不等于输入或计算完成。
5. 复用现有加工、capture audit、身份/去重校验和 `saved_sample.json`。补齐“原执行未完成，但选定区间完整”的首次加工与正式登记分支；原 ready/加工失败恢复分支保留，不伪造 `processing_failed`，不强求历史区间先有失败派生或版本≥2。
6. 保持一个原执行最多一个当前有效交付版本；相同原件、区间与规则重复执行应复用结果，不新增执行或编号。正式保存后核对 Runtime、候选结果和收据一致；若当前投影推进，原失败事件仍可回读，并标记为历史派生恢复。
7. 派生保存不能清除模型 UNKNOWN、费用预留、未知浏览器尾部或原任务的重发限制。尤其验证“保存已登记但原未知请求仍受保护”，不能因 claim 投影变化失去隔离。

枣庄零效果误分类归 E4。这些修复改善新执行，不自动把财经或其他旧拒绝帧升级为合格证据，也不是历史 8 条派生的前置条件。

### E7 / P1：取消原生查找禁令，按目标开放阅读路线

**已明确决定：删除“直接阅读禁止浏览器原生查找”的约定并落实到新执行链。** 不能只删文案，保留 `native_browser_find=False`、宿主拒绝或旧测试断言。旧冻结任务和收据仍按其原规则解释。

宿主实现与模型协议需一并完成：能力声明 → schema/prompt → 原生查找框的打开/输入/匹配/关闭 → 实际平台按键 → 效果证据 → 计步与派生保存。现有网页 DOM 输入和视口截图不天然覆盖浏览器原生查找框，应先在当前运行方式中验证并补齐这些接口。复用现有浏览器宿主，不另建浏览器框架。

模型按需选择目录、滚动、页内查找或网站搜索。`ctrl+f → 输入关键词 → 关闭或切换匹配` 只有每次实际派发且产生相应效果时才可能算 3 步；不强制 Enter，不把无效果按键算步数，不以查找凑长度。交付使用 Windows 快捷键记法，实际执行平台与参数另留原证据。不能用 DOM 检索或程序滚动伪装成原生快捷键；内部只读检索计 0 步。

其他直接阅读限制按以下方向收敛；这些属于新协议设计，不撤销旧任务明确要求：

| 限制类别 | 新协议建议 |
| --- | --- |
| 搜索、type、组合键、Enter/Escape 的通用禁令 | 按原目标、当前焦点和真实能力开放；区分页内查找、站内搜索和提交 |
| 只允许原生 a、仅正文链接、排除 button/summary | 允许服务原目标的目录、展开正文、关闭遮挡等已实现动作；来源标签与实际正文引用分开 |
| 相同 netloc、只允许同标签页 | 复用观察到的导航与页面绑定；多标签页只有宿主确实支持才声明可用，不新增任意 URL 权限 |
| 离开原词条下一步必须 back、最终必须回原页 | 保留在原 Wiki 等显式任务约束中，不能成为所有阅读任务的默认；是否返回由当前原目标决定 |
| 仅滚动后新增正文、唯一首屏 h1、固定正文 24 字、结束帧必须重现历史引文 | 分开已见阅读证据、新增内容和有效动作；用可核验页面/正文来源与历史引用，不为满足结构或终帧要求强加滚动 |
| 动作 checks 仅限 click/back；其余动作一律从 schema 移除 | 原目标的动作义务保留；路径选择按当前能力呈现，有业务需要才开放相关动作 |

始终保留原目标、实际来源、真实派发、原始证据与效果核验。关联页不能冒充原词条；目标限定单页时仍限定来源。完整原限制清单与出处见[原复盘第 9 节](消费者批量50页复盘与协议推理优化计划-20261106.md#9-直接阅读协议限制审查与约定调整)。

查找验收覆盖适合使用、无需使用、无匹配/无效果。若当前宿主最终不能可靠取证，交付复现和具体缺失接口，标记该能力未完成；不能只把 capability 改为 true 或默默省掉本子项。

### 首轮规划语义模板


```text

```
