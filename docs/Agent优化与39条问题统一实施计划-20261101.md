### 当前代码与历史问题的区别

工作区在真实验证结束后已有其他改动。当前规则以[额度限制清单](额度限制清单与取消说明-20261101.md)、实际源码及适用原账为准：新正式采集会话按原 attempt 最多派发 25 次真实 GLM 请求；批次累计 token 等只计量，旧冻结任务继续按原绑定解释。不能恢复本轮历史的 40 次访问上限、旧 24 次请求上限、默认连续无进展 5 轮停机或累计 token 停机阈值。

当前模型网关已移除导致本轮 3 条停止的旧文本预留检查，历史图片在超过单次容量时也已有发送侧处理。这不等于上下文精简完成：文本历史仍会增长，工具与目标字段仍需统一。W02 验收要证明真实请求内容受控，不能仅证明旧错误不再抛出。

真实验证期间有 3 个发现／分类辅助文件发生外部变动，消费者与 QC 核心摘要未变；[原摘要差异](../verify_results/consumer-qc-live100-20261101-r01/source-drift.json)保留。39 条可用于定位已发生的断点，不能作为单一稳定源码版本的真实增益比较基线。

单机实现继续复用现有 Python、本地文件、SQLite 短事务和唯一约束，不增设服务、独立后端或分布式协调。至少 5 个有效操作、short_flow 及累计占比不超过 2%、类目占比不超过 20%、独立审核、去重和交付门禁保持原义。不为凑步添加操作，不增加完整演练或独立准入前置。

分类缺失不说明页面不可消费。消费者不另调模型判断 URI 类别，不要求来源分类成立后才规划，也不把缺失值伪填为“综合”。来源分类及其证据原样保存；后续需要的标签补全与交付分布检查单列，分类待确认仍可保存为待审样本。这里的分类未知与模型请求、动作效果、传输的 UNKNOWN 分开表示，后者仍受原账约束。

导航页、目录页和聚合页是合法操作场景。只有 URL 时可依据当前可见功能建立浏览、筛选、详情比较等阶段目标；已有 `requested_goal` 时保留其对象与参数。允许点击、返回、再次点击等连续路径组合，每次依据真实工具返回决定下一步，不预先穷举或机械回放。无需完成网站全部业务；有效步数依据实际变化和连续证据，往返、滚动不自动获得合格资格。

## 三 Agent 契约设计与局部验收

### W01 动作工具与目标

动作目录区分“已启用”“已知但未支持”“本任务禁用”。首期启用仍是当前 10 种：`click`、`double_click`、`right_click`、`type`、`set_value`、`select`、`hotkey`、`scroll`、`open_url`、`back`。后续目录可登记悬停、焦点、单键、清空与选中文本、勾选和单选、拖拽、容器滚动、前进和刷新、标签页、frame、文件和浏览器对话框；本计划不要求实现这些执行器，也不因登记而授予能力。

动作名、额外参数、宿主允许条件和执行器映射使用一份现有模块内的登记定义，生成模型 Schema 与宿主校验，避免多处枚举漂移。只允许本任务启用集合与当前页面证据的交集。业务“搜索”“查看医生”“购买”表达目标，不变成无穷的站点专用动作。快捷键名称与组合受支持集合约束；文档示例用 Windows 的 `ctrl+a` 等记法，原执行参数照实保留。

控件使用当前观察提供的 ID，页面导航使用会话已获得的页面身份，不接受模型凭空构造控件、任意 URL、selector 或坐标来绕过证据。语义操作与底层动作映射保留原实际计数，不能把复合操作掩成一步。

提示词明确支持目录与导航任务。例如“浏览两个工具的介绍”可以形成“点击分类 → 点击 A → 返回列表 → 点击 B → 返回列表”的连续阶段；该序列仅说明能力，执行时逐轮观察、选择和验证。分类信息不能改变可调用动作或成为 `act` 前置条件；返回后的旧控件 ID 不可直接复用。移除以凑足 5 步为目的的固定操作配方，保留目标相关的导航组合。

四工具稳定为 `observe`、`inspect`、`act`、`finish`。首次以简表说明 ID、作用、选择条件、是否改变页面；单个工具说明控制在 120 字符内。系统和工具契约保留为稳定前缀，后续用户轮只发状态增量；实际每次 API 请求仍必须有可用的工具 Schema，不能因“首轮介绍过”而缺失定义。

| 字段 | 新协议长度上限 | 不得丢失的内容 |
| --- | ---: | --- |
| working_goal.description | 300 字符 | 当前阶段、对象、参数引用、可见完成条件 |
| goal_update.reason | 120 字符 | 当前观察支持的更新依据 |
| 单步 goal、expected | 各 120 字符 | 本步目的与待验证变化，不能冒充实际结果 |
| decision_summary | 80 字符 | 一句决策摘要 |
| finish.summary | 300 字符 | 实际已做、末帧事实和未完成部分 |

字符按字符串 Unicode 字符数计算，不等同 token；不设 200 字符下限，不为凑长度扩写。原始 `requested_goal` 原文及结构化参数不可截断或改写；长输入值独立保存并向模型传递需要的精确参数，不能只给无法读取的本地路径。工作目标仅在建立、阶段完成或新证据要求改变时更新，不在每步重写全文。

已有工作目标时，省略更新明确表示“不修改”；首次 `act` 必须已有目标，或同轮提交有观察依据的目标。只有明确的“无更新”可省略，不能补造缺失的动作、参数或完成条件。未知字段、动作或缺少关键参数仍拒绝且零派发。Schema 变化采用新 `decision_protocol`，旧协议按原定义读取、验证和恢复，不静默套用新限制。

离线验收：

- 从登记生成的模型动作枚举、宿主允许集合和执行器映射完全一致；未知动作、额外字段、伪造 ID、过期观察、非法快捷键均零浏览器派发。
- 300/301 字符、短目标、长原始目标和精确输入参数均有边界用例；长描述拒绝或返回纠正要求，不静默裁剪。
- 首次缺目标的动作被拒绝；已有目标的无更新不再因可省略字段产生错误；显式目标更新保持证据绑定。
- 相同页面和目标在来源分类存在、缺失或待确认时使用相同执行能力；导航目标可进入不同分支并返回，不被强制改写为交易、提交等完整业务。
- 旧冻结协议和原始记录可读；新动作目录中的未支持项不会进入可调用集合。

### W02 上下文与状态

原始 PNG、界面树、工具交互、请求、响应和失败完整保存在原执行位置。给模型的投影只含固定规则、不可变要求、当前阶段目标、当前截图、相关控件、宿主事实状态和必要的最近历史。状态由实际台账生成，不把模型自由总结当成执行事实。

先定义必须保留的事实字段，再调历史窗口：原始目标及精确参数、当前阶段及完成证据、当前 observation／页面身份、已访问分支与真实返回路径、已执行且不可盲目重复的动作、未决请求／动作和失败路径、原 attempt 的真实调用数。可以按证据引用查询长材料，但不能只留下模型无法读取的本地路径。用窗口切换后的语义一致性验证这些字段，不能仅验证请求体变小。

首版离线调参起点为最近 2–3 个已闭合工具轮次、当前截图 1 张、按需保留最近历史截图、相关控件最多 24 项、单次查询默认不超过 2000 字符。可以配置但必须有限；具体窗口在离线用例中确定。文本携带量按稳定估算方法或适用 tokenizer 记录 token，图片单独记录数量与估算来源，不能把 data URL 字节直接算作文本 token。厂商 usage 返回后记录实际值。

实施时为固定规则、当前观察、事实状态、历史和查询结果分别登记单请求携带上限，并给出合计文本 token 与图片容量的配置及测试值；不能仅限制历史轮数却允许单条材料无限长。网页、HTML 和反馈保持不可信材料标记，不能进入系统规则或改写授权、动作目录、预算与审核标准。

完整的旧历史归档并可查询；请求中仅在已闭合轮次边界压缩，保留成对 assistant/tool 消息与 tool_call_id。当前 pending 调用、UNKNOWN、原始目标约束、失败事实和当前证据不得被删掉或“总结成成功”。保留必要的提供方不透明协议字段；新投影不改写历史请求、既有缓存身份或原响应。

每轮观察和上次工具返回中的相同内容去重，避免在 user、历史与 tool result 三处重复携带完整观察。超出携带窗口时优先缩减旧材料，当前目标及精确参数不能丢；无法保留必要语义时明确报告容量不足，不能静默截断。这里的请求携带上限不构成新增的批次或会话累计 token 停机限制；25 次 GLM 派发上限保持。

离线验收：

- 用 25 次决策的固定尺寸观察、工具结果和长 HTML 夹具，证明超过窗口后历史文本、图片和请求体大小不再随总轮次线性增长；记录各轮估算 token、图片数与字节数。
- 同一状态无需重复携带相同整页材料；总控件超过 24 时仍有可达的搜索／分页路径，不虚报完整覆盖。
- 压缩前后原始文件摘要相同，保留事实、约束、动作顺序和失败；工具消息配对有效，原 token usage 不被改写。
- 网页或历史材料要求更换目标、增加工具、解除 UNKNOWN 或声明 QC PASS 的注入反例不能改变宿主边界。
- 验证当前截图不会被图片裁减移除；目标更新和关键参数在窗口切换后仍正确；旧缓存及 UNKNOWN 路径零重派。
- 与未精简基线在相同夹具上比较文本估算 token；上限、实际观察和差异写入验收报告，不能只以“不再抛旧预留错误”为通过条件。

### W03 查询纠错与输出容量

`inspect` 按用途生成参数分支：控件详情需真实控件 ID，控件搜索需查询词并返回 ID、简短标签、位置及三态，页面材料查询支持观察 ID 与分页，历史查询支持动作引用或范围。无关字段省略，避免所有字段都必填且依赖 null。字符串 `"null"` 不当作空值自动吞掉；返回明确参数错误，不继续重复检索。

工具错误返回稳定原因码、当前观察、实际匹配信息及可行的下一工具参数。缺探针只建议对已知控件定向观察；已有探针但缺可读标签时，不重复推荐同一探针。`PROVEN / UNAVAILABLE / INSUFFICIENT` 保持三态，不能把信息不足写成站点无能力。

已收到合法 usage 的格式失败，保留原失败后才允许已有有界格式纠正路径；纠正请求必须携带字段级错误，仍计入原 attempt 的 25 次派发。缺失 usage、传输 UNKNOWN、认证 hold 或动作效果未知均不能自动重发。相同观察与查询参数的重复失败返回原事实和替代建议，不重复浏览器取证；不恢复旧默认 5 轮停机。

规划采集当前 `reasoning_effort=max` 及提供方绑定保持，单次输出容量应与 reasoning 和工具参数共同消耗匹配，不能继续让 4096 的固定较小值掩盖配置容量。先验证使用配置支持的单次容量与有界纠正；不隐式降模型、换提供方或重解释旧请求。没有合法工具输出时零动作派发。

离线验收：

- 将本轮 9 个缺字段、1 个动作字段错误、5 个 length 结果抽象为无凭据的合成响应；验证精确错误原因、纠正反馈、实际发送计数及零误派发，不把无效回复修饰为成功。
- `"null"`、不存在的控件、未命中查询、分页边界、探针缺失及标签缺失分别走正确分支；模型能查询到摘要未展示但实际存在的控件。
- 全量 reasoning 输出、空 tool_calls、未知工具、多调用、非法参数和缺 usage 各有反例；UNKNOWN 后重启和换 worker 均零重发。
- 第 25 次可合法结束；第 26 次及超出的格式纠正被原账原子拦截，缓存与本地校验失败不占真实发送次数。

## 四 执行链修复与局部验收

### W04 取证与导航

当前 `candidate_navigation.extend` 通过 `same_application` 限制路径，导航页点击外站可能在落地后被拒绝。实施时将“可走的证据绑定导航路径”与“应用／主机身份是否相同”分开。新协议允许从当前观察中的真实链接或已记录点击进入与工作目标相关的公开页面，保存来源 observation、控件／href、触发动作、重定向及实际落地 URL，逐页记录主机身份。第三方介绍页保持发布站归属，不能因正文提到某工具就归到被介绍网站，也不能把整个跨站轨迹的页面全部标成入口应用。

导航范围进入新任务的冻结契约，并由在线执行、`verify_path`、后加工与保存回读共同验证。旧冻结任务继续核验原导航范围。保留已有公开 URL、协议和访问校验；模型臆造 URL、只有未呈现材料支持的链接、无触发证据的落地不进入路径。不能简单删除同应用检查后接受任意地址。

同标签的“进入分支 → 返回 → 进入另一分支”本轮必须支持。`back` 依真实会话历史执行，返回后重新同步观察，记录导航／筛选等状态实际是否恢复，再使用新控件引用。真实点击打开新标签时如宿主尚未支持接管，应返回明确的工具能力不足及候选优化记录，不通过修改链接、手工替换页面或伪造返回轨迹补齐；不将它误报成分类失败。完整多标签工具仍按 W01 的能力目录管理。

导航期间不存在 body 时等待当前文档就绪后重新观察，不能重发先前点击或导航；确实没有可观察文档时保留具体失败。对取证失败分别记录加载状态、结构差异、目标相关状态、像素变化及证据引用，避免所有问题只写“页面结构持续变化”。

对非轴对齐元素区分与目标、可读文字、遮挡是否相关。有完整证据证明无关时才允许局部处理，不能为了绕过错误直接丢弃变换元素或整类子树。截图保持原 PNG，不裁剪、涂改、冻结页面或隐藏广告来获得稳定证据。

像素相同不证明结构相同，DOM 相同也不证明像素同步。第 12 条的小范围像素变化、第 25 条的大范围变化和第 34 条的零像素但加载／结构变化作为三种反例，不能统一添加任意像素容差。允许变化的范围必须有明确的无关区域证明，关键文字、目标、输入值、标签、遮挡、焦点与终态继续保护。

离线验收：导航空 body 与文档切换有本机页面夹具；证明一次动作后仅重新取证。旋转装饰和旋转目标分别测试，后者证据不足仍拒绝。图树不同步、关键区域变化、加载未完成继续拒绝。可证明无关变化用例可通过，原 PNG 字节不变。真实原件仅只读用于核对诊断，不将失败轨迹重新加工成成功。

另用本机导航夹具覆盖目录／详情／返回／换分支、返回后的旧引用失效、目标分支打不开后返回、可见外链与实际跨主机落地、重定向链、伪造外链及新标签能力不足。公网 URL 判断与网络传输在用例中显式模拟，不能为夹具放宽产品校验。离线完整保存后回读路径与主机身份，证明第三方介绍页和被介绍网站分别归属；相同页面的自然返回不能仅因截图重复就阻断整条轨迹。

### W05 预检效果与终态

预检是风险和准备路径观察，不代替当前 Agent 的任务选择。有已证明的关闭控件和允许的路径时，由 Agent 通过正常 `act` 关闭遮挡，再同步取证；每个准备动作、效果和实际计数都保存。没有已证明路径、真实登录／验证码门槛或受保护内容时维持阻断。不能看到“广告”标签就擅自关闭或修改 DOM。

工作目标优先选择当前观察支持的自然业务阶段，不预先承诺尚未观察的流程。`finish` 提交完成条件及观察引用，宿主核对当前可见状态，分别保留预期、实际变化、已做阶段、未做部分和停止原因。静态阅读、inspect、observe、wait、complete 不凑有效步数；自然两步的真实片段仍如实标 short_flow，不能为提高通过率扩写无关操作。

导航场景以真实浏览、筛选或比较阶段描述结果，允许一次连续会话多次返回和切换分支。不能要求导航页先证明某个行业分类或具有表单／交易功能。原页面不可继续时，只有动作和请求结果已确定且存在真实返回路径，才可选择其他相关分支；失败事实继续留存。

对零效果区分派发前拒绝、已执行且无变化、已执行但效果未知。派发前拒绝可以补证；执行后不能自动补点或跳过该动作拼接轨迹。本轮第 35 条先有有效变化、后动作缺效果，不能只取前半段伪装整条完成。

离线验收：以可关闭／不可关闭遮挡、变化不相关／目标变化、当前阶段完成／仅模型自报完成构成正反例。验证准备动作按实际计数、未知效果不重发、原始失败不抹除；5 步边界、2 步 short_flow 与累计 2% 检查保持，最终描述不超出末帧证据。

### W06 分类解耦与结束竞态

删除消费者 `_entry_hints`／`category_proven` 触发的正式执行阻断，并排查领取、任务生成、能力记录、身份绑定、后加工、保存和 QC 交接是否仍隐含“先有合法分类才可继续”。不把同一门槛转移到 `claim_next`、首次观察或模型 prompt，也不新增消费者分类请求。来源分类及证据原样保留，缺失用独立分类待确认状态表示，不伪填“综合”，不标成请求 UNKNOWN，不因标签缺失写入 discard／optimize。

对新契约明确未分类值和状态如何贯穿上述链路，避免只删除一处 if 后在必填字段校验中再次失败；旧冻结记录仍可读，不覆盖历史分类与拒绝。最终交付需要分类时由后续元数据整理及交付 QC 核验，并如实报告待确认数量；不降低总体类目要求。来源合法性、候选版本和证据绑定、原领取独占与请求未决继续核验。`claim_next`、`producer_batch_drained` 及固定名单的可消费判断保持一致，不能出现队列仍有可消费项却持续 EMPTY 的等待。

固定名单模式逐项匹配 ID、版本和来源批次，实际来源或执行阻断记录具体未执行原因，分类缺失不跳过。不能跳到名单外补抽或改变分母。竞争领取仍由现有唯一约束保证；同页不同目标维持独立身份。来源 GET 成功不推定浏览器可达，405、403、404、登录、URL 身份校验和传输 UNKNOWN 分别记原因；已观察到的正常链接与跳转按 W04 处理，不能替换未决请求或绕过访问门槛。

候选确定结束后停止其 heartbeat，再完成浏览器资源清理；失租、取消、在途或 UNKNOWN 仍按原 fencing 处理。优先返回原确定断点，后续关闭／心跳异常单列，不覆盖首因。

离线验收：来源合法但分类缺失的候选可完成首次观察、ReAct、加工和保存待审，全链路零额外分类请求；有分类时原标签及证据不变。无效来源、伪造证据及未决请求继续按各自原因阻断。固定名单不替换、分类缺失不减少其分母，空队列／批次排空判断一致，两个同机竞争者只有一个持有者。设置超过 heartbeat 间隔的模拟浏览器关闭，验证确定失败不再被凭据异常覆盖；真正失租仍禁止提交。HTTP、登录及 URL 校验分别归因。

## 五 QC 与 token 口径

### W07 QC 包类型有效集合与状态

本轮程序 pipeline 曾因历史 Muxtly 的 raw capture 被当作客户包而阻断，另有本轮单样本被套用累计 1000 条 profile 的数量检查。这里既有交接路径问题，也有验证调度范围问题，不能全部归给样本质量。short_flow 比例、类目比例及资料待审是其他独立检查，不因修路径而自然通过。

通过原保存和客户导出收据定位客户包，验证完整文件哈希与原 sample 身份，不从 raw annotation 目录层级直接推断客户包。raw capture、完整客户包和比较证据的用途要明确；历史样本的差异比较继续保留。不能修改原 manifest、删除历史包或迁移路径来取得 PASS。

新 QC 冻结前显式绑定本轮样本总体、AI 100% 和人工 0 的验证策略、适用 profile、客户包集合及跨包报告。小规模验证的覆盖结果与累计交付规模分开呈现，累计 1000 等原门禁只在相应交付范围判定，不能通过给单样本另改宽松阈值放行。新集合写新收据；原失败和冻结交接不覆盖。是否可复用原 AI 结果依据样本字节、规则、模型与比较总体核验；第五项比较范围改变时不能直接沿用旧结论。

分别记录程序样本检查、独立 AI 视觉／语义、资料审核、包级检查、批次接纳、运行库终审与发布。现有包级 FAIL 或资料未决时，不能把样本 PASS 自动升级为 `reviewed_pass`。

离线验收：临时工程包含历史 raw、其有收据的客户导出包及本次客户包，证明选对包、有效集合完整、四路判重覆盖正确、原集合字节不变。模拟样本 PASS／包级 FAIL 时保持待审；AI 未选中不冒充已审，AI 与人工分列。路径或报表变化不自动重做 AI。语义规则若确有变化，只更新相关规则版本并验证局部失效。

真实资料 QC UNKNOWN 只作为问题证据，不调用它的 prepare/run/recovery，不读取凭据，不轮询提供方。离线用临时账模拟相同状态，验证同对象、别名、新 pipeline、重启及换 worker 均不能重派。QC 路径修复完成也不解除这一约束。

### W08 后续只统计 token

新增日志、汇总和完成报告只使用请求数、输入／输出 token、缓存命中 token、reasoning token、用量覆盖率、状态与耗时，不再计算或展示金额指标。旧数据库、冻结配置和历史金额字段原样保留，不删除、不填零、不迁移；缺少金额不能成为新 token 统计的未知结算判据。是否请求未决继续由原发送、响应和 usage 证据判断。

实施须覆盖配置、结算和汇总三个入口。当前 `BatchLedger` 仍有费率配置必填、结算金额计算及以 cost 非空推断覆盖率的路径；为新请求明确只用 token 的配置和结算语义，旧冻结配置仍按原字节核验。使用已标记的新语义处理金额缺失，不静默改变旧原账的解释，也不以迁移／清空账本启用新行为。增加“usage 完整、金额缺失”和新旧混合账用例，前者 token 覆盖应完整，不能转成未决请求。

以原请求 ID 去重，按角色、candidate、claim、attempt 关联；格式失败、零新增、缓存复用、发送前拒绝和 UNKNOWN 分列。缓存输入是输入 token 的子集，reasoning 若已包含输出则不重复累加。厂商没返回的字段保留 UNKNOWN，不凭字符估算补成实际值。请求前估算及图片容量另标来源，不与厂商实测混算。

## 六 GLM 会话密钥选择

### W09 每个新会话随机选一个密钥

工程凭据来源为 `token.yaml` 中的 `glm` 列表。每个新 GLM 会话在第一次实际请求前，从有效、去重且未被原账禁用的条目中均匀随机选一个；同一会话的后续决策及允许的格式纠正保持该密钥，不在每次请求重新随机。独立新会话可以抽到相同密钥，不要求轮询，也不承诺均分调用量。

规划采集以正式 `attempt_id` 作为会话身份，不以整个消费者进程或整批候选作为一个会话。不同候选的新 attempt 分别选择，同一 attempt 内按需创建／复用网关时不得重新抽取。发现和 QC 使用其各自明确的原作业会话边界，不能因共享同一个 worker 网关而误将多个独立会话永久绑定；适配前先核对各入口的实际生命周期，不改变其作业或审核身份。

当前 `model_credentials._glm_session_key` 已使用 `SystemRandom().choice`，`ModelGateway` 初始化时选定并保存在内存；规划采集也已有会话内复用 gateway 的路径。实施重点是确认该行为与业务会话边界一致，补齐必要的恢复绑定和用例，不重复实现另一套随机选择器。显式使用本工程 YAML 列表时应核对凭据来源优先级，避免环境变量意外覆盖列表；其他提供方和旧冻结来源继续按原绑定解释。

原账只记录不可逆的非明文账户身份与会话关联，不记录密钥、密钥片段、Authorization 或完整 YAML。进程恢复同一会话时，依原身份在运行时匹配原条目；列表顺序改变不能导致换钥，原密钥已移除或禁用则停止该会话，不重新随机。缓存命中、本地预检拒绝和原 UNKNOWN 阻断不触发新选择或发送。

发送顺序应为纯本地预检、核对原会话绑定／原账、仅新会话选择、复用原账短事务原子确定账户与请求预留、实际发送。已有绑定必须先恢复，不能先随机再碰到账户不匹配。随机选择可在进程内准备，但同一 attempt 的两个竞争者最终采用同一个持久绑定；不得在 SQLite 事务里进行网络请求。补充首次选择并发、绑定后发送前崩溃、网关重建和原请求未决的测试。

会话内请求失败不自动换钥；随机选择不能绕过认证 hold、原请求 UNKNOWN、同一 attempt 的 25 次调用上限或原执行范围。本轮真实 QC UNKNOWN 保持原请求与原账户身份，绝不因追加随机选择要求而启动恢复或重发。

离线验收：

- 只用临时 YAML 和虚构密钥，覆盖字符串列表、`api_key` 条目列表、单条、空列表、重复项及非法条目；随机输入只含核验后的可用集合，错误信息不含凭据。
- 注入可控随机选择器，验证不同新会话各选择一次，同一会话多轮及格式纠正始终使用同一条目；不以随机频次阈值构造不稳定测试。

## 八 单条真实采集保存验收

用户已授权整体研发后的单条真实验收。选择当前工程中来源与协议合法、证据完整、可独占领取且无适用未决阻断的一个生产者候选，优先选择具有自然多步导航／浏览能力的入口。分类可以缺失，不能用“补上正确分类”取得执行资格。合法输入必须有原始生产者来源、候选 ID／版本和发布证据，不能手写假候选、临时资格 PASS 或伪造 GET 结果。

复用当前 `candidate-project-2` 工程的 pool、registry、manifest 和消费者原账，新建本次验收记录及输出子目录，不初始化另一份生产账来绕过原历史。先核对候选和账户状态，再冻结本次候选及版本；不自动执行原 100 条名单或剩余 61 条，也不重采已封存 Muxtly。优先从原固定名单之外的合法库存选择，选择理由及排除项写入记录。

运行必须经过真实消费者领取、同一浏览器会话首帧观察、真实 GLM 工具决策、实际动作与同步取证、原始执行关闭、整条后加工、正式保存及候选／运行账回写。用产品入口完成，禁止由研发 Agent 手工替消费者点击完成验收，禁止直接写入成功状态或复制历史样本充数。每个会话最多 25 次真实 GLM 请求，第 25 次结果可以正常处理，第 26 次零派发且原始终态及候选原因可追踪。

发生已确定的实现失败时，保存完整失败、修复并通过相关离线检查，再依既有显式恢复机制和修复版本复验；不得仅换 attempt 来重置到限会话。模型／动作 UNKNOWN 或实际未解除的账户 hold 保持阻断，不能为达成一条保存而改名重发。若原候选确实不可消费，记录原因并按同样的来源核验选择替代候选，所有选择、失败及正式尝试累计列出；始终只围绕一条真实保存目标串行推进，不扩为批量生产。
