# 消费者阅读规划动作混合与同页目标多样化实施方案（A+B）

2026-11-09 · 状态：**方案待实施** · 依据：已保存真实基线样本 `S000001_sample_000002`（attempt ac180d94）实际动作序列原账

> 本轮只形成方案与 zcode 提示词。实施授权、真实 GLM 调用范围按用户后续确认为准；方案本身不启动真实调用、不改生产/QC 规则。

## 1. 问题与证据

### 1.1 现象

用户指出：wiki 月食页面的阅读规划全是滚动，与此前约定的"滚动+点击+返回自由组合"不符；阅读轨迹若塌缩为单一动作类型，轨迹重复率会过高。

核对原账属实。已正式保存的直接阅读基线样本（`results/candidate-project-wwiki-direct-20261108-r01`，`S000001_sample_000002`，`collected_pending_review`）5 个有效步全部为 `scroll down`，执行坐标均为 (640, 360)：

| 步 | 动作 | 模型自述目的 |
| --- | --- | --- |
| 1 | scroll down | 阅读月食类型段落 |
| 2 | scroll down | 阅读「没有月环食」一节 |
| 3 | scroll down | 阅读「月食过程」一节 |
| 4 | scroll down | 继续读过程与时间 |
| 5 | scroll down | 阅读「时间」与科学研究段 |

每一步本身有真实视口变化和新正文，按现行口径是合格有效步；问题不在单步质量，在**动作类型分布塌缩**。

### 1.2 成因

- `banded_plan.py` 普通阅读条款（约 153–154 行）写"长阅读由多段滚动自然组成"，把滚动描述为默认形态。
- V11 自由组合条款（约 185–193 行）写"自由组合、不强制跨页、不为步数添加无关动作"——允许混合，但没有任何机制让混合真实发生。
- 对模型而言，长词条纯滚动是拿到 ≥5 有效步的最低风险路径：点击需落地核验，back 需身份核验，滚动几乎不会失败。理性选择即全滚动。

### 1.3 判重后果

- route2 按 `action_type + target_text + page_name` 全序列比对；scroll 步 target 基本为空，同页两条 N 连滚样本序列必然全同，跨页纯滚动序列也高度相似。
- route1（共享首帧截图 SHA256）在同页多样本下本来就会命中，动作混合救不了它，需任务侧差异（见方向 B）。
- route4（任务文本 SimHash ≤3）要求同页多目标有实质文本差异，换关键词不够。

### 1.4 必须保持的分寸

既有方案明确约定"自由组合不等于要求每条轨迹包含全部动作"。本次修复的对象是**分布塌缩**，不是单样本构成：**不得强制每条阅读样本必须含 click/back**，否则会把可选路径变成新模板，逼出无目的点击，制造新的无效轨迹。四路判重阈值、每步原子效果校验、VERIFIED 门槛、short_flow 如实标记全部不动。

## 2. 方向 A：规划提示词纠偏（模型看到的协议）

### 2.1 改动点

`projects/code/webcollect/banded_plan.py`：

1. 普通阅读条款（约 153–154 行）：删除"长阅读由多段滚动自然组成"的默认形态表述，改为按页面证据选择——**当前页面证据中存在与目标相关的目录章节或正文链接时，首轮计划应自然包含至少一次有独立查阅目的的点击**；点击跨页落地后核验新文档身份，back 核验原页面身份再继续阅读。纯滚动序列只在页面确无目标相关可读链接时才是合理选择。
2. V11 自由组合条款（约 185–193 行）：补充分布指引——有相关链接证据时偏向"滚动段落 + 目的性点击 + （跨页时）back 续读"的自然混合；同时保留原文"不强制跨页、不把某一路线当模板、不为步数添加无关动作"。
3. `direct_entry` 条款（约 156–158 行）与 DIRECT_VERSION 条款保持各自既有约束；本方向只改通用 V11 阅读提示，不改 direct-article-1 的"跨页后下一业务动作必须 back"。

### 2.2 不做什么

- 不在宿主侧新增"单一动作类型计划拒绝/强制重规划"门禁（原方向 C，否决：侵入大，有"为组合而组合"的凑步风险，与自由组合约定冲突）。
- 不改动作 schema、有效步计数、原子效果校验、四路判重。
- 不要求模型在计划里自证"页面无相关链接"作为纯滚动的前置审批；是否混合由页面证据自然驱动，验收看实际序列与页面证据是否匹配。

## 3. 方向 B：同页目标多样化（任务生成侧）

同页不同目标本来就是既有边界允许的。让同页多条样本在**任务层**就有实质差异，同时拉开 route2 动作序列与 route4 任务文本。

### 3.1 基线路径（本轮可验证）

在 `request/consumer-baselines/` 新增同页不同目标的直接阅读变体，每个变体独立 objective、独立 SHA256、经正规 baseline_import 登记独立 candidate（不复用 r02 candidate/claim，不手插 SQLite）。变体的阅读问题要有实质差异，例如：

- 变体一（纯正文可答）：沿用现有"月食时月球与地球的位置关系"类问题，不动原基线文件。
- 变体二（必须查阅关联词条才能完整回答）：如对比类问题，答案需要进入「日食」等关联词条核对后返回——自然产生 click + back + 续读的混合轨迹。

变体目标文本不得只是换关键词或少量改写（route4 汉明距离 ≤3 会命中）。新变体沿用 `webcollect-goal-evidence-2` + `direct_entry` + `webcollect-action-scoped-evidence-1`，minimum 5、long。

### 3.2 生产路径（定位后实施）

生产侧阅读目标由任务生成给出（`task_generation.py` 的 react 生成链，`react_candidate['session_objective']` 经 `session_objective.apply()` 绑定）。实施时先定位生成阅读 objective 的具体提示词/模板位置，再补充多样化规则：

- 同一词条生成多条阅读任务时，各目标的阅读问题必须有实质差异（不同方面、不同关系、不同是否需跨页核实），不得同义改写。
- 至少一类目标设计为"答案需查阅关联词条"，使跨页混合轨迹由任务需求自然产生，而非提示词强求。
- 生成侧只决定目标差异；动作组合仍由消费侧规划 Agent 按页面证据自由决定，不把动作序列写进任务。

## 4. 对既有资产的处理

- r02 全滚动样本 `S000001_sample_000002` 保持原状：不回写、不改写、不删除；其 `collected_pending_review` 与 QC 未决状态不变，四路判重历史对照照常包含它。
- 原搜索基线、direct-article 旧协议、旧失败记录保持原解释。
- 新变体、新候选、新 attempt 走新账；单次规划采集会话 25 次真实 GLM 调用上限等既有额度规则不变。

## 5. 验收

### 5.1 离线集成

新验证目录，保留日志与失败原件：

- 夹具页面含目标相关目录章节和正文链接时，V11 首轮计划自然含 ≥1 次有独立查阅目的的点击；跨页计划含 back 且 back 后核验原页面身份。
- 夹具页面确无目标相关可读链接时，纯滚动计划仍可被接受（不强制混合）。
- 为凑混合的无关链接点击仍被现有"独立查阅目的 + 原子效果"校验拒绝；无效滚动、错误返回等旧反例保持拒绝。
- direct-article-1 协议行为不变（跨页后下一业务动作必须 back）。
- 受影响邻近链路回归通过；既有失败（如 `test_closing_policy_v2` 两例）逐例核对与 HEAD 一致，不借机改写。

### 5.2 真实 GLM 基线

集成通过后，按既有研发授权用**新变体目标**（方向 B 的跨页变体）在隔离研发工程跑一次真实会话：

- candidate/objective 来自新冻结基线文件，`production_counted=false`，正规登记路径。
- 真实 GLM 自主规划，不由脚本代选固定序列；报告实际动作序列组成（scroll/click/back 各几次）、各步前后证据、搜索动作数（应为 0）。
- ≥5 有效步、目标 VERIFIED、正常完成、`collected_pending_review`、单次提交、密封 SHA256 与只读回读一致，口径同前基线。
- 对本次研究集合执行适用四路判重，命中或未决如实报告；特别报告新样本与 r02 全滚动样本的 route2/route4 判定结果。
- 分别报告动作派发数、后观察完整数、效果未决数、有效步数和正式保存数。

### 5.3 不做的事

- 不修改四路判重阈值、hash、历史集合或接纳规则。
- 不因动作混合好看而放宽任何单步有效性校验或 VERIFIED 门槛。
- 不把单条真实基线通过写成整体交付质量结论；机械检查与独立 AI QC 门禁同前方案第 6.3 节，未实际 PASS 前不启动 A/B。
