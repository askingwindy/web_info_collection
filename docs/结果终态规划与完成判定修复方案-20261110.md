# 结果终态规划与完成判定修复方案（2026-11-10）

来源：`delivery/202611100008` 核验（1 FAIL、2 REVIEW_REQUIRED）中暴露的"4 步规划差一点达标"问题。
目标：让狗狗计算器这类"数字已改、结果未取"的轨迹在**执行阶段**走完最后一步，而不是事后 QC 判 FAIL；同时修复完成判定与结果摘要。原轨迹不可补拍，修复只作用于新执行。

## 一、问题证据（已核实）

### 狗狗计算器 S000001_sample_000066（FAIL）

- 任务目标要求"获得本次计算产生的 AKC 与 UCSD 两种换算结果"；实际 4 步（聚焦→全选→输入 7→点计算）后宿主结束。
- 结束机制：`completion_origin=host_plan_endpoint`，`planned_steps=4`，理由"已证实计划可见终点；自然提前完成不凑步"。
- 终点谓词 `finish_when=visible_text「相当于人类」（region 计算结果）`为首帧即成立的页面固有文字（`finish_when_established_on_first_frame=true`）。
- `goal_evidence.business_goal_status=PARTIAL`，"本次计算的换算结果区"UNVERIFIED，但导出 `completion_status=success`，`final_result` 仅抄页面介绍文字。

### 猫咪计算器 S000001_sample_000068（结果在图里，证据与摘要却漏）

- 末帧可见"28 岁（人类等效年龄）、年轻成猫"，但 `goal_evidence` 三项均 UNVERIFIED，`final_result` 选了 FAQ 解释文字，漏掉关键结果。

### 维基 S000002_sample_000023（对照组，机制正常）

- 目标"打开词条落地页并阅读正文"，2 步完成，`goal_evidence` 3/3 VERIFIED。阅读类自然短流程不应被本次修复误伤。

### 代码断点（三处）

1. `banded_plan.py` 约 1840–1856 行：`endpoint_now` 只要求 `proved(finish_when)`；首帧弱谓词保护（`endpoint_established_at_first_frame`）仅拦截"计划未走完的提前结束"（1852 行），**计划走完分支（1850–1851）直接 finish，不检查谓词是否首帧成立、证据是否由动作产生**。
2. 初次计划校验已有 `ENDPOINT_VISIBLE_ON_FIRST_FRAME` 拒绝与反馈（约 1288–1321 行），但模型修订后仍可能提交弱谓词并被接受，此后执行终点再无防线。
3. `postprocess.py` `terminal_outcome`（461–513 行）只看 stop_reason/unknown/blocked/flagged，**完全不看 `goal_evidence.business_goal_status`**；`final_result` 由可见文字描述函数生成，未优先采用已核验的结果字段。

## 二、Agent 规划侧优化（goal / prompt / 模型看到的协议）

模型看到的协议与宿主校验作为同一项改动同步更新。

1. **结果型任务的计划完备性**：目标含"获得/查看/读取…结果"时，计划必须以使结果区可见并读取结果收尾（如点计算后滚动到结果区）；`finish_when` 的文本谓词必须是**动作后才出现的结果内容**（本次计算的新数值），不得使用页面固有说明、栏目名、按钮文字、默认参数或示例文本。
2. **弱谓词修订不再放行**：首帧反馈已要求"终点绑定动作后的新结果证据"；修订后 `finish_when` 仍为首帧成立的泛文本时，宿主再次拒绝并点名应绑定的结果区内容，而非接受后仅靠提前结束保护。保留既有出口：原目标确属纯观察且首帧已完整回答的，可如实零动作结束（不构成样本），不得为产生样本添加无关动作。
3. **结束摘要声明结果**：complete/finish 时的结果声明须覆盖目标要求的结果字段，供宿主与证据回算对照；摘要不实由工程闸门兜底，不依赖模型自觉。

## 三、工程宿主侧优化（宿主实现）

### 1. 执行终点拦截（核心，救回"差一点"的轨迹）

位置：`banded_plan.py` finish 判定（约 1840–1856 行）。

- 将首帧弱谓词保护从"仅计划未走完"提升为**全程有效**：`finish_when` 首帧已成立、且已执行动作未产生新的结果证据时，`endpoint_now` 不成立——无论计划是否走完。此时走现有 `request` 通道给模型 `replan`（按实测补规划，如滚动读取结果）或 `stop`（如实结束）选项，并附当前结果区证据缺口说明。
- 结果证据缺口同时参考 `plan_evidence` 回算：声明了结果检查项且存在 UNVERIFIED 时，不得以"计划可见终点"结束。
- 豁免保持不变：契约化 `goal_evidence` 终点、`continue_reading` 阅读路径、纯观察零动作出口均不受影响；合法自然短流程（动作已产生终点证据）不受拦截。
- 由此补步的驱动是"结果证据缺失"，不是步数；不引入最小步数或自动凑步。

### 2. 保存完成判定闸门（兜底，防漏网）

位置：`postprocess.py` `terminal_outcome`。

- native 且启用 ending_policy 时，若 `terminal.goal_evidence` 声明了 checks 且存在 UNVERIFIED（即 `business_goal_status != 'VERIFIED'`），不得返回 `success`：按实返回 failed（说明哪项目标结果未核验）或既有 controlled_exception 路径。
- `checks` 为空 / `NOT_SPECIFIED` 不一刀切判失败，避免误伤无结果声明的阅读类样本。
- 与执行层拦截是同一语义的两道防线：执行层优先让轨迹补足证据，保存层保证漏网者不被标成功。

### 3. 结果摘要由工程生成

位置：`postprocess.py` `terminal_outcome` / `visible_result_description` 链路。

- `final_result` 优先引用 `goal_evidence` 中已 VERIFIED 的结果字段（如"28 岁（人类等效年龄）""生命阶段：年轻成猫"），拼装"输入→结果"摘要；不再从整屏可见文字中任取句子（FAQ、介绍文字）。
- 与 2026-11-05 既定原则一致：能由执行事实确定的字段由工程生成，不依赖 Agent 自由文本。

## 四、取舍与不做的事

- **不强制最小步数、不自动补滚动凑步**：违背"不为长度补动作"；补步必须由结果证据缺口驱动。
- **不只在 QC 端加严**：QC 事后判 FAIL 救不回轨迹，原 PNG/轨迹不可补拍；修复必须落在执行终点与保存闸门。
- **不一刀切禁止首帧成立谓词**：阅读类、纯观察任务有合法出口；拦截条件是"首帧成立 + 无动作新证据 + 声明结果项未核验"。
- **不为本次小包调整短流程 2% / 类目 20% 交付阈值**：分布问题由生产者任务生成深度解决（阅读类目标增加目录跳转、内链、参考资料等交互要求），另行立项，不在本方案内。

## 五、验收口径

基准只取当前工程生产者 Table2（`data_candidates`）已发布有效网页，固定候选与目标，真实 GLM 调用，以可见结果和正式保存收据验收；模拟响应与单测不作为最终验收。

1. **狗狗计算器（原失败基准）**：同一目标（默认小型、5→7、获得 AKC/UCSD 两种结果）重新执行，末帧可见两种换算数值，`goal_evidence` 全 VERIFIED，正式保存收据成功；步数允许自然增加（如滚动读取），不设目标步数。
2. **猫咪计算器**：`final_result` 包含"28 岁"等关键结果字段，证据全 VERIFIED。
3. **维基（回归）**：阅读类目标仍可 2 步自然完成，不被新闸门拦截；首帧成立的纯观察任务可零动作如实结束。
4. **负例**：构造首帧弱谓词计划（visible_text 用页面固有介绍文字），宿主必须拒绝或要求 replan，任何路径下不得导出 `completion_status=success`。
5. **负例**：`goal_evidence` 存在 UNVERIFIED 结果项的执行记录，后加工不得产出 success 样本。
