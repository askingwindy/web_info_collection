# 规划采集 agent 真实小批对照方案（待明确运行范围）

本方案只安排诊断，不恢复生产，不自动访问页面。执行前须明确候选页面的实际可用资格、原 hold/UNKNOWN 状态、原 manifest/账本绑定、模型版本/费率和本次授权额度；当前未做这些真实核验。任何已有 hold 的整体应用保持停止，不因对照新建 job/库/别名绕过。候选不适用时登记未运行及原因，不隐式换站。

## 页面、任务和分组

先选三个具名诊断单元；均以实际新观察中存在且可读的控件为准，不宣称当前网页仍具备下列条件。

| 单元 | 候选页面 | 固定片段目标与要检验的问题 |
| --- | --- | --- |
| T1 | `https://zjz.108ai.com/` | 使用当次观察的原生选择框切换一个非当前选项、修改输入、清空后再输入并查看当前状态；验证 native select 库存与编译展开。仅真实可行的5–8动作片段，禁止补无效步骤。 |
| T2 | `https://www.jyshare.com/front-end/9986/` | 在贷款计算界面修改两个可见条件，若目标在视口外则记录实际滚动后重取证；可在条件修改后结束，不要求贷款业务完整提交。验证滚动失效、当前值/placeholder和短段执行。 |
| T3 | `https://www.jyshare.com/crypto/hmacsha256/` | 使用公开合成字符串修改文本/显示选项并查看当前页面；密码型或不可读字段不得凭名称放行，必要时报告证据不足。验证可读标签边界和不可行路径拒绝。 |

T2/T3 属于同一个整体应用，共用原三次失败账。它们只是仓库已有路径对应的候选诊断页，历史可执行性与旧失败不证明现在可运行。若原 JYSHARE hold 仍在，这两个单元不执行；记录覆盖不足，不能重置原账获得完整矩阵。

A：同一明确版本 GLM、原 `fragment-model` 固定计划流程。B：同一 GLM、`agent-model` + 新循环（controller v2：目标语义一致性、无冗余观察、prompt 内当前轨迹记忆、决策请求失败分级；`MODEL_FAULT` 单列为模型侧明确失败，不与 UNKNOWN 混算）。C：Codex 通过同一 `choose(prompt)` JSON 接口产生决策，走同一观察、编译、browser.execute、collect_one 保存与 QC；不能用额外网页、隐藏 DOM、另一套浏览器工具或手工操作帮助 C。C 的模型名称/版本另记，A/B 对比用于隔离控制循环因素，B/C 不能解释为纯模型因果试验。

每单元每组最多2次诊断尝试，共 **18次正式尝试上限**。第一次失败未终结或存在 UNKNOWN 时，不运行第二次。已终结失败后的第二次另登记 sample/attempt，使用相同片段目标和上轮原证据反馈。编号不回收，轨迹不拼接。未执行的候选修订计重规划，不冒充新正式尝试。

## 比较条件与额度

- 同一天时间块，组序轮换：T1 A/B/C，T2 B/C/A，T3 C/A/B；第二轮反向。每组使用隔离且相同初始浏览器上下文，视口1280×720、缩放1、zh-CN/Asia/Shanghai、相同等待策略、同一原来源快照，记录每次实际起始文档/页面差异。初始状态不可比则报告不可比，不编辑 DOM 强行一致。
- 目标、起始来源、允许页面/动作与验收规则相同；每条5–8个实际有效动作；观察最多32，候选修订最多8，决策最多24，决策模型调用最多20（controller v2 按最坏诚实路径核定的上限）。A固定计划最多1次生成+1次明确编译反馈修订，B/C最多20次决策；所有组初始目标生成最多1次。A不使用未用额度换额外尝试。实际调用数分阶段报告。
- 最大模型请求数：每尝试初始规划1次+决策20次，共21次；A实际最多2次。全矩阵上限378次，B/C每次输出上限4096 token，A规划最多8192，输入/图片/思考 token 服从原已冻结 provider 限额。不得隐式更换GLM、跨provider补发或沿用不匹配费率。
- 本次建议硬费用上限每组人民币10元、合计30元（须在范围明确后写入原账实际支持的预算单位）；原账剩余额度更小则取较小值，不能新账补额度。Codex若无可信逐请求usage/金额则保持UNKNOWN、单列订阅/应用用量证据，不按零成本比较。额度不足不要求跑满18次。
- 总计18次是独立上限，不叠加成旧试点的新额度；原 RuntimeStore campaign 的尝试、在途、待审和整站失败上限共同收紧。模型和生产两套账分别保留原引用及request ID。

## 原账绑定和诊断去重

范围明确后在新的只写一次 experiment manifest 中保存：原 `current-chain-r01/manifest.json` path/SHA、专库绝对路径、原BatchLedger config/DB身份、整站失败guard、原精确去重集合/有效集合、来源capability/anchor原件、A/B/C版本与预算、每单元组序与允许输出根目录。该 experiment manifest 是旁路诊断索引，不能重建或修改 current-chain manifest。

起点/中间图命中已有生产样本，按原规则拒绝，不裁图/丢准备帧。A/B/C重复执行同一任务产生的跨组重复另列 `diagnostic_pair_duplicate`：完整保留并报告原QC拒绝，不把它们计成新增生产合格。为避免先跑组占满索引影响后跑组，所有组在相同冻结既有生产对照集合上给出“对既有生产集合的接纳”指标，另对整个实验总体给出含跨组重复的实际接纳；不得用前者覆盖后者，也不能将这18条自动导入生产有效集合。若现有当前链政策不能承载这种诊断比较，停在协议核对，不绕过提交门禁。

QC仍独立检查完整轨迹、原图/树、真实动作和四路重复；建议小批18次全部逐条机械+AI审核，另由实际人工盲看全部候选（同一要求适用于三组）。人工服务和真实模型QC须另外纳入这次最终明确的运行范围。人工PASS由真人导入；不预填结论。客户验收与本次诊断分开。

## 停止与统计

立即停止：任一 UNKNOWN/未决请求（核原账后才可决定后继）、整站达到原三次真实失败或已有hold、预算/时间耗尽、证据变更/缺失、程序错误、隐私/登录阻断、当前链/恢复绑定不匹配。相同状态同原因第二次复发不进行第三次尝试。每尝试墙钟建议上限5分钟，整次对照2小时；超时保留中断，不续接原轨迹。

每组给出以下原始分子/分母，并按单元配对展示；小样本不作量产外推：

1. 尝试数=真实started_at；另列未派发规划候选、程序拒绝、观测不足、未决请求、采集保存、待审、终审/批次接纳、发布和缺额。所有18次上限内的失败均进分母；未启动单元单列。
2. 批次接纳转化率=独立QC按同一政策接纳的有效片段数/正式尝试数；另列接纳/collected_pending_review。分别报告对冻结既有生产集合的诊断指标、包含组间重复的实验总体指标；生产新增量始终0，除非以后另有明确接纳授权且完整去重只计一次。
3. 同因失败复发率=已知上轮同因、已得到原反馈后仍复发的次数/获得同因反馈且实际再尝试的次数；根因键使用拒绝码+动作+目标角色+页面/值/视口状态，不用目录名区分。同图/同目标失败单列，缺原证据记UNKNOWN。
4. 人工介入=实际人工改变计划/参数/接管操作/解锁的次数及分钟数；只查看结果的审核时间另列。C的正常模型决策不算人工干预，Codex操作者额外帮忙算介入。
5. 时间=起始观察至正式终结墙钟，分解规划模型、补充观察、执行、保存、排队和独立QC；报每尝试及每接纳片段的中位数/范围，总耗时保留，不只报成功耗时。
6. 模型成本=原request usage、厂商版本与冻结费率计算，分初始规划/决策/QC，并列输入/缓存/思考/输出token、图数、失败预留和UNKNOWN。每尝试成本、每接纳片段成本分开；厂商实际扣费缺证据保持UNKNOWN。

最终产物：实验manifest、逐次attempt表、原账/请求引用、配对条件偏差表、每步观察/决策/原图、全部失败与重复对象、独立QC/实际人工记录、指标表。少跑或未决保持原样，不为完成矩阵自动加站、加轮或补产。
