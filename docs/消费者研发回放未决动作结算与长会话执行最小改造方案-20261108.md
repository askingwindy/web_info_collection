# 消费者研发回放未决动作结算与长会话执行最小改造方案

2026-11-08 · 状态：**已被同日《消费者直接阅读自由组合基线与轨迹判重实施方案》替代，不再作为当前实施提示词；本文保留历史分析，未实施** · 代码基线：`e615df0`

## 1. 结论与本轮范围

当前固定月食阅读基线仍有两个独立阻断：

1. r02 的 Enter 已派发、已执行，但缺少已验证的后观察；原 Runtime attempt 已中断、研发 claim 处于 reconcile，现有正规入口不允许为同一 candidate 新开研发回放。
2. r02 由受 300 秒前台上限约束的 Bash 调用启动，进程在完整会话结束前被杀。即使解除领取阻断，仍可能再次制造 interrupted attempt。

推荐做一次**研发回放专用、证据绑定、显式授权的最小改造**：

- 增加“已放弃且永不续跑的历史研发 attempt”结算口径；不证明 Enter 成功或无害，不修改原 attempt 的中断事实。
- 只凭该精确结算事件，允许同一 candidate 从首帧开始一次全新的独立研发 attempt；不续跑、不拼接、不回收编号。
- 复用现有 `consume → postprocess → RuntimeStore` 正式保存链，提供单次、有界、可持续运行的前台驱动，不再通过 300 秒 Bash 前台调用执行长会话。

不放宽生产领取、正式重试、模型 UNKNOWN、QC、人工审核或发布规则。本轮只形成设计与实施提示词，不修改代码，不结算 r02，不启动真实 GLM、A/B、QC 或生产。

### 2.3 三个现有阻断点

1. `CandidatePool.claim_research`：同 candidate 上处于 consuming/reconcile 的后续研发 claim 会阻断领取；`known_unstarted_historical_claim` 只豁免零 Runtime attempt、零模型请求的未启动研发失败，r02 不适用。
2. `guard_candidate_dispatch`：同 candidate 的 interrupted attempt 会阻断派发；`accounted_rejected_focus` 只接受特定 rejected attempt 及其完整结算事件，r02 不适用。
3. `retry()` / `unverified_original_actions`：已派发但无已验证后观察的动作保守阻断重试。该保护必须保留；本方案的新会话不是 retry，也不从旧动作之后继续。

`finish_or_reconcile(..., reconciliation=True)` 已实跑返回 `{state: reconcile, saved: false}`；没有完整保存就不能结 succeeded。现有公开入口没有适用于 r02 的结算路径。

## 3. 推荐契约：研发专用显式废弃，而非“ UNKNOWN 已清除”

### 3.1 语义

新增能力可命名为 `abandon_interrupted_research`，实现时可按现有命名风格微调，但语义不得改变：

> 在原进程与关联浏览器均已退出、租约已过期、没有已提交保存、模型请求均已确定结算的前提下，经用户对精确 candidate/claim/attempt 的明确授权，把一个历史研发 attempt 标记为“已放弃且永不续跑”，允许另开独立研发会话。

该结论**不表示**：

- Enter 没有生效、已经失败或已经成功；
- 原 attempt 可以改为 rejected/succeeded；
- 原两步可以并入新会话的 ≥5 步；
- 原模型请求、动作、访问、费用或失败记录可以删除；
- 生产 attempt 或模型 UNKNOWN 可以按同法放行；
- 样本已通过机械检查、AI QC、人工审核或发布。

### 3.2 必要输入与逐项拒绝条件

新入口必须要求并验证以下绑定，任何一项不满足都在写入前拒绝：

| 输入/事实 | 必须满足 |
| --- | --- |
| 身份 | candidate、research claim、Runtime attempt 三者互相绑定，candidate 版本、冻结目标与工程绑定一致 |
| 研发属性 | claim 含合法 `research_replay` descriptor，`production_counted=false`；普通生产 claim 一律拒绝 |
| 明确授权 | 独立授权文件明确列出 candidate_id、claim_id、attempt_id、冻结目标 SHA256、放弃语义和本次用途；不能只凭代码参数或方案文档推断授权 |
| 原状态 | Runtime 为 `interrupted / interrupted / lease_expired`；claim 为已过期 reconcile；其他状态不走本入口 |
| 租约 | claim 与 Runtime attempt 租约均已过期，旧 worker/token 不能再提交 |
| 进程 | 有原驱动进程已经退出的可核验收据，并核验其关联 Playwright/浏览器子进程均已退出；仅“主 Python 不在”不足够 |
| 保存 | `verified_saved` 为空，raw 中无 `saved_sample.json`，没有 `collected_pending_review` 或正式有效结果 |
| 模型账 | 绑定到该 claim/attempt 的请求清单完整，全部已有确定结果；存在 reserved/unknown 一律拒绝。首版可进一步限定全部 succeeded，避免扩大口径 |
| 访问账 | 绑定访问均已确定结算；存在 reserved_for_dispatch/unknown 一律拒绝 |
| 未决动作 | 通过现有 `unverified_original_actions` 生成完整清单，每项保留 path+SHA256；清单可以为空，但不得被忽略或改写 |
| 原始证据 | raw receipt、原始失败、未决动作、进程退出、模型/访问结算及冻结目标均通过现有 evidence 引用校验 |

r02 当前只具备部分前提。特别是：此前只核对过 `formal-consume-drive.py` 主进程不存在，**尚未形成覆盖所有关联浏览器子进程的完整退出证据**。因此实现完成不等于可以自动结算 r02；实际结算前仍需一次明确授权和真实进程核验。

### 3.3 追加式证据与状态迁移

建议新增证据协议 `webcollect-research-interrupted-abandonment-1`，至少包含：

- candidate_id、original_research_claim_id、attempt_id、sample_id；
- research descriptor、冻结目标和授权文件的 path+SHA256；
- 原 Runtime `status/failure_class/root_cause` 快照及“保持不变”声明；
- 进程与浏览器退出证据；
- 模型请求、访问及其确定状态；
- `unverified_original_actions` 原始清单；
- 无保存证明；
- `abandoned_forever=true`、`resume_allowed=false`、`production_counted=false`。

写入采用追加式、幂等设计：

1. Runtime 对同一 attempt 追加 `research_interrupted_abandoned` 事件，并把结算证据引用追加到 `evidence_json`；不得修改原 `status/failure_class/root_cause`、样本号、原事件或原 raw 文件。
2. 池账将对应研发 claim 从 reconcile 结为 `failed`，原因使用精确值 `research_interrupted_abandoned`，追加同类池事件并引用 Runtime 事件和结算证据；不得结为 succeeded，不新增有效 candidate result。
3. 同一 attempt+同一证据重复调用应返回原结算结果，不重复追加；同一 attempt 提交不同证据或不同授权必须拒绝。
4. 两个 SQLite 不引入跨库分布式事务。建议先写 Runtime、再写池账；派发门禁必须同时看到两侧精确事实。若中途失败，保持阻断并允许同一证据幂等续结，不能出现“半结算也放行”。

## 4. 三处门禁的最小改动

### 4.1 `CandidatePool.claim_research`

保留现有未启动研发豁免，新增独立的只读证明函数，例如 `abandoned_interrupted_research_claim`：

- 只认可第 3 节的完整双侧结算事件和证据；
- 重新核对 candidate、原研发 claim、attempt、目标、授权、研发 descriptor 及原账未变；
- 不调用或放宽 `known_unstarted_research_failure` 的适用条件；
- 将证明放入新 claim 的 `settled_history`，使新 claim 能追溯到被放弃的旧 attempt。

普通生产 claim、未过期 claim、模型 UNKNOWN、已有保存、证据篡改仍按原规则阻断。

### 4.2 `guard_candidate_dispatch`

在现有 attempt 冲突判断中，仅当同一 candidate 的旧 attempt 具备上述完整研发废弃证明时跳过该**历史 attempt 冲突**。`accounted_rejected_focus` 原逻辑不变。

放行不是全局白名单：

- 新会话仍须通过 `guard_request_scope`、站点失败门禁、未决模型/访问/规划 job 检查和当前工程绑定检查；
- r02 遗留 running collection、queued frozen-plan 原样保留，不手工改状态；实现后必须用真实只读 preflight 证明它们不会形成另一个未处理阻断，不能预先假定“废弃 attempt 后全链必然通过”；
- 只有已结算旧 attempt 被豁免，新 claim/新 attempt 一旦 running/interrupted/reconcile，后续领取和派发仍立即阻断；
- 生产任务即使复用该 guard，也因缺少合法 research descriptor 和研发授权而不能获得豁免。

### 4.3 `retry()` 与 `unverified_original_actions`

**不改其保守语义。** `unverified_original_actions` 仍必须报告 r02 Enter，`retry()` 仍不得把它当成可续跑或可替换的旧轨迹。

本方案走的是“废弃旧研发 attempt 后独立 claim_research”，不是 `retry()`：

- 新 claim、新 Runtime attempt、新 sample ID；
- 新浏览器、新首帧、新计划、新动作序列；
- 不继承旧页面、DOM observation ID、焦点、输入值、计划游标或动作计数；
- r02 的 2 个已验证步只保留在历史账中，不计入新会话的 5 步；
- r02 Enter 始终保留为未决动作，不在新账中“补验”。

## 5. 长会话执行入口

### 5.1 复用正式链，不实现断点续跑

提供一个单次研发驱动，串行完成：

1. 固定工程、目标与授权校验；
2. 正规 `claim_research`；
3. 首帧观察与真实 GLM 自主规划；
4. 同一 React 会话内连续执行、续租、目标判定；
5. 现有 postprocess；
6. 现有 RuntimeStore 单次提交与只读回读核验。

不拆分动作到多个进程，不把每段结果拼成一个样本，不新增另一套保存协议。25 次真实 GLM 上限、动作原子性、业务动作上限和原证据规则不变。

### 5.2 运行方式与超时

- 在 Kimi Work 内，优先使用**单次 Python Blueprint Automation 的 code execution**，配置足以覆盖完整会话的有界超时；若当前宿主执行能力不满足，则在本机终端直接前台运行同一驱动。
- 不再使用受 300 秒限制的 Bash 前台调用执行该长会话。
- 不使用 `nohup`、尾 `&`、`setsid`、`disown` 或其他遗留独立进程方式。
- 首版建议总上限 **20–30 分钟**，这是待实现时确认的工程建议，不是当前已确定业务值。超时应覆盖首帧、规划、全部动作、后加工、提交与回读，而不是只覆盖模型请求。
- 运行期间沿用现有租约续期；不切段、不跨会话恢复。真正超时或异常仍按现有规则记 interrupted/UNKNOWN，不能因新驱动而改写。
- 驱动启动时记录自身身份，正常/异常退出时在 `finally` 关闭浏览器并写退出收据；若被强杀，只能凭外部真实进程证据后续对账，不能伪造 `browser_closed=true`。

### 5.3 结算与新会话的先后顺序

严格顺序为：

`离线实现与测试 → 用户明确授权处置 r02 → 核验进程/浏览器退出 → 幂等废弃 r02 → 只读 preflight 通过 → 单次长会话新 attempt → 正式保存核验`

不能因为代码已具备能力就自动处置 r02，也不能先启动新会话再补旧账结算。

## 6. 替代方案与不采用原因

| 方案 | 不采用原因 |
| --- | --- |
| 所有 interrupted 都允许重试，或把“已派发无后观察”当成未执行 | 会把未决效果误判为无害，破坏证据保守性，并可能重复业务动作；生产和研发边界也会被一起放宽 |
| 从 r02 Enter 后跨会话续跑 | 会拼接中断轨迹、继承不可核验页面状态，违反当前 resume 设计；还要重建浏览器、观察、计划和编号关系，改造面显著更大 |
| 新建 candidate/工程绕开旧账，或手改 SQLite | 只是隐藏原阻断，不是正规结算；破坏固定基线身份与原账可追溯性 |
| 将 r02 改为 rejected/succeeded，或用零 GLM 探针补造后观察 | 与原始事实不符；探针发生在另一时间、另一页面会话，不能证明 r02 的动作结果 |

## 7. 验收设计

### 7.1 离线集成测试

新增聚焦测试文件，复用现有临时工程/账本夹具，至少覆盖：

1. 合法研发废弃结算成功，原 attempt 的 status/failure_class/root_cause、sample ID、raw、模型用量均不变。
2. 非研发 claim 拒绝；普通生产路径无豁免。
3. claim 或 attempt 未过期拒绝。
4. 主进程未退出、浏览器子进程未退出或退出证据不完整拒绝。
5. 模型 reserved/unknown、访问 unknown 拒绝，原 UNKNOWN 不重发。
6. 已有 `saved_sample.json` 或 `collected_pending_review` 拒绝。
7. 授权目标、candidate、claim、attempt 任一不匹配拒绝。
8. 伪造、缺文件、SHA 篡改、跨工程证据和描述符不一致拒绝。
9. Runtime 写入成功而池账尚未写入时仍阻断；使用同一证据可幂等续结，不重复事件。
10. 合法结算后只允许一个独立新研发 attempt；新 attempt 未结时后续领取仍阻断。
11. 新 attempt 从首帧开始，旧 2 步与 Enter 不带入新有效步数，旧 sample ID 不复用。
12. `unverified_original_actions` 仍报告原 Enter，`retry()` 原阻断不变。
13. 长会话驱动只调用一次正式保存；运行中超时仍产生 interrupted，不拼接、不后台遗留。
14. 邻近回归只跑受影响的 candidate consumer、candidate pool、request quarantine、runtime 与正式保存链；既有 HEAD 失败须对照说明，不写成新回归。

### 7.2 r02 结算后只读核验

在实际新会话前逐项核对：

- 原 r02 attempt 仍为 interrupted/lease_expired，Enter 仍在未决动作清单；
- r02 claim 仅为 failed/research_interrupted_abandoned，不是 succeeded；
- r01 已保存结果不变，r02 无有效结果；
- 新旧 claim/attempt/sample ID 全部不同；
- `claim_research` 与 `guard_candidate_dispatch` 仅对该精确历史事实放行；
- 全部模型/访问/站点/工程 preflight 通过，没有第二个被忽略的阻断；
- 全程 0 次新 GLM、0 次新浏览器动作，直至长会话正式启动。

### 7.3 真实固定基线验收

真实验收必须在一个全新研发 attempt 内同时满足：

- 真实 GLM 自主规划，目标字节与冻结 SHA256 不变；
- ≥5 个真实、逐步有证据的有效动作；
- 打开月食有关条目并发生向下阅读，正文证据支持月球与地球的位置关系；
- `session_objective.status=VERIFIED`；
- 正常完成，不是 trusted prefix，不是 interrupted；
- `disk saved=1`；
- 新 Runtime attempt 恰为 `collected_pending_review`，单次提交；
- 密封文件 SHA256 与只读回读一致，claim 正规结为 saved/succeeded，研发正式有效计数仍为 0；
- 请求数、succeeded/invalid/UNKNOWN、有效步、保存与目标状态分别报告。

机械检查、独立 AI QC、人工审核、发布和客户验收未实际运行时仍为 NOT_RUN，不能从 `collected_pending_review` 推断合格或发布。

**只有上述真实基线全部通过，才讨论启动 A/B；否则继续留证修复，不启动 A/B。**

## 8. zcode 实施清单

1. 在 `candidate_consumer.py` 增加研发废弃的证据构建/校验与幂等结算入口，复用 `_original_attempts`、`verified_saved`、`unverified_original_actions`、`verify_evidence`，不复制另一套动作判定。

4. 在 `guard_candidate_dispatch` 只接入该精确证明；保持 `request_quarantine.accounted_rejected_focus` 与 `unverified_original_actions` 原语义。

6. 增加聚焦离线集成测试及必要的邻近回归；测试目录新建，保留日志和失败原件。
