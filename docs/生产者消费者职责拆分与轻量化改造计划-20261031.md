# 生产者消费者职责拆分与轻量化改造计划

状态：2026-10-31，依据本轮代码分析与用户确认制定，待实施。本次只更新规划及工程入口，不修改源码、不启动搜索、模型、浏览器、采集或 QC。此前生产者和消费者的有界真实验证均已停止，剩余次数不自动结转为本计划的运行授权。

目标是让生产者持续提供来源可信、可追踪的入口库存，由消费者根据实际页面形成工作目标并执行。新路径允许只有 URL、没有具体业务目标；生产者提出的目标只是可核实的建议。来源忠实、原账、UNKNOWN、整站止损、原子领取和独立 QC 保持约束。

本计划补齐[规划采集 Agent 改造计划与验收](规划采集Agent改造计划与验收-20261031.md)的上游库存与适配边界；该计划及[执行 prompt](规划采集Agent改造执行Prompt-20261031.md)继续负责同会话工具循环、完整原始执行、整条加工及真实 QC 验收。不另建服务、规划 Agent、队列框架或在线切段系统。

## 1. 当前问题与改造依据

| 当前事实 | 判断 | 对应改造 |
| --- | --- | --- |
| 首轮因原模型 UNKNOWN 应用与止损投影衔接不足，在派发前停止 | 运行状态衔接问题，不是候选生成失败 | 共享运行时从原账检查作用域，投影滞后不能放行 |
| 第二轮两条把教程/导航文章绑定成文中外站工具；另有一条 `history_recorded` 条件不清 | 来源归属错误应拦截；精细参数要求增加了无页面依据的推测 | 保留来源一致性检查，允许不生成具体目标，将建议与事实分开 |
| 第三轮一条来源错误导致整批 0 条入库 | 单条错误被整批发布规则放大 | 新协议逐条校验、分别提交和留错；旧严格模式不改签 |
| 第四轮阅读查询被工具关键词误过滤，且离线失败仍启动真实运行 | 类型启发式误伤与执行失误 | 文章类型作为提示；派发仍须有当前源码的有效检查证据 |
| 当前候选要求结构化目标；消费者对拼接指令做逐字一致检查 | 摘要推测被当成不可改变的执行要求 | 新候选允许入口形式，区分明确要求、来源建议与现场工作目标 |

原件见[生产者真实报告](../verify_results/pilot1000-20261028-r01/producer-validation-20261031-r01/真实验证报告.md)及其中逐次记录。最后连续三批通过的是限定小批的来源 AI 核对与入库验收，不能推出页面可执行、消费者转化或轨迹 QC 通过。旧报告、失败、隔离和费用事实全部保留。

当前生产者没有浏览页面、截图或规划动作，执行链已经较轻；主要负担是摘要阶段的目标契约、整批门禁和逐批全池读取。当前消费者仍通过首次观察、任务生成及执行链运行；同会话 ReAct 是待实施方案，不能作为已有能力。

## 2. 职责与拦截位置

| 工作或判断 | 生产者及入库程序 | 消费者 | 后加工与独立 QC |
| --- | --- | --- | --- |
| 搜索、原始结果保存、入口 URL 及引用绑定 | 负责；不编网址、不将正文提及对象冒充来源应用 | 核对原领取与来源绑定 | 保留来源链 |
| 名称、父类、业务方向、文章或工具类型 | 形成提示，允许未知；无页面判断结论 | 根据实际页面补充判断，保留原提示 | 根据实际样本及有效集合核算类别 |
| 具体输入、单位、筛选、业务目标 | 可建议，不强制生成，不声称控件存在 | 现场核实；遵守明确要求，建立和更新工作目标 | 标注实际发生内容，不把建议写成已实现结果 |
| 可达性、登录、控件、遮挡、页面状态、导航及操作路径 | 不预判，不证明操作步数 | 在实际会话中判断、执行及保存失败 | 独立检查证据与交付合规 |
| 字段、URL/引用、编号、精确去重、入库幂等 | 程序负责；不要求模型自证 | 校验领取、版本、原件与执行身份 | 继续检查样本及累计重复指标 |
| 原始执行保存与可交付样本 | 不承担 | 保存完整原始执行；加工状态与保存状态分开 | 整条加工及独立审核，失败可据原件重加工 |

以下共享保护不随职责迁移放松：原请求 UNKNOWN 与在途检查、401/403 等认证阻断、原应用 hold、预算、租约 fencing、当前链及生产占用。生产者选择来源和发起自身请求前检查适用保护；消费者在领取后的请求及动作前再次核对原账。不能只依赖生产者当时的过滤结果。

已被 hold 的搜索命中可以保留在原始搜索及排除记录中，不发布为可消费项；不能借“只存入口”恢复访问。投影滞后时从原账保守阻断，不另造一套止损权威。未派发、字段错误和候选不适用不直接计成网站真实执行失败；实际失败沿用原执行 ID、类别和累计规则。

## 3. 新候选契约与旧协议兼容

新路径采用显式版本分支。拟使用 `webcollect-data-candidate-2`、`candidate-producer-3` 和 `webcollect-candidate-consumption-2`；这些是待实施版本名，不表示当前已支持。现有 producer V2 是原始回答严格模式，不能复用该名字改变它的语义。

新存储契约区分两种候选，共用原 SQLite 池、来源历史、原子领取和消费记录。

| 字段或对象 | 入口候选 `entry` | 明确目标候选 `target` |
| --- | --- | --- |
| `entry_url` 与来源引用 | 必需，由程序绑定真实搜索命中或显式来源 | 同左 |
| 名称、父类、业务、来源类型提示 | 可选；缺少判断不伪填确定结论 | 同左 |
| `requested_goal` | null | 调用方明确提供并冻结的原业务要求和参数 |
| `suggested_goal` | 可选，生产者根据摘要提出的建议 | 可选，不得覆盖明确要求 |
| `working_goal` | 不由生产者填写 | 不由生产者填写 |
| 身份 | 协议类型＋整体应用＋规范入口身份 | 协议类型＋整体应用＋冻结的结构化明确目标 |

`requested_goal` 的来源由可信调用参数决定，不接收模型自行声明的“用户要求”。生产者默认生成入口候选；用户明确给定目标时才走目标候选。`suggested_goal` 留在来源上下文，不增加第三个运行目标字段，也不把它直接复制为 `working_goal`。消费者运行仍只有只读 `requested_goal` 与依据观察形成的 `working_goal`。

来源 URL、来源角色和目标归属必须一致：A 站文章可以作为 A 站的内容入口，不可登记为 B 站工具。若明确声称为 B 站但只绑定 A 站来源，该条拒绝；若只是无法判断类型，可保留未知。正文外链不能偷偷替换入口；以后如需派生外链候选，必须有真实链接证据与独立来源关系，并遵守应用边界，本轮不自动增加该能力。

入口身份保留原 URL 和规范身份；不能通过 query、fragment、别名或换协议绕过原应用归属、原请求和生产占用。同一入口的建议改写不生成新入口；同一应用的真实不同入口仍可分别发现。精确去重不宣称语义去重，也不按生产者随意改写 `kind/entity` 创造新目标。单纯替换参数不用于补足入口库存。

兼容要求：

- 现有 `webcollect-data-candidate-1` 和严格生成协议原样读取；原目标、逐字指令、领取快照、去重键、版本、历史请求和收据仍按旧分支验证。不能将旧冻结目标重新解释成可丢弃建议。
- 新读取端显式识别两版 body，并支持新协议类型筛选。新消费者尚不可用时，入口候选只可列出，不能静默降级到旧生成链，更不能临时捏造目标让旧消费者通过。
- 优先复用 `data_candidates`、版本/来源/claim/event 表。新增协议能力及必要索引通过显式、事务化的扩展安装启用；普通打开、读取或启动不得自动迁移真实池。原历史 body、ID、状态与绑定不重写，不复制到新池绕过旧账。
- 原池扩展未启用时，新协议写入明确报兼容性错误；旧读取/领取行为保持兼容。安装失败回滚；已产生新协议数据后不自动降级或删除新记录。

## 4. 生产者改造

主要模块为 `candidate_discovery.py`、`candidate_pool.py`、`discovery_agent.py`；只读接口涉及 `site_pool_reader.py`。

1. 将入口库存设为新路径的默认产物。模型只需从给定来源选择入口、提供粗分类及可选建议，不要求为每个 URL 补齐精确业务参数、最终目标、动作或步数证明。入口 URL 和 ID 均由程序生成/绑定，不接受模型编造。
2. 保留来源和字段硬检查。文章/教程/推荐页启发式转为类型或排序提示，记录依据；不再仅凭关键词排除阅读入口。来源归属矛盾仍拒绝，错误或含义不明的可选目标建议单独记录问题，不自动修成“确定事实”；入口本身合规时可仅接纳入口。
3. 将响应外层解析和逐条业务校验分开。无法解析 JSON、响应外层损坏或来源输入整体失效时停止该批并保留原件；对可独立解析的条目分别记录接纳、重复、拒绝及原因。单条字段/来源错误不阻断其他已验证条目。模型网关不得继续用“整批每条业务 schema 全通过”作为获取可检查响应的唯一入口。
4. 数量约束改为有限上限和尽力供给，允许 0 至剩余上限，缺额如实 PARTIAL。精确五条仅保留在旧严格测试协议；常规运行不为凑满数量补目标、填空行或自动增加调用。超额返回保留完整原件，只发布授权上限内的条目并记录超额问题。
5. 发布与恢复逐条幂等。保存原始响应和绑定后，为每条生成稳定处理身份、校验结论及提交结果；跨池/账本中断只核对原缓存、原行和原消耗，不能重新请求。数据库、原件完整性、预算或账本错误属于批次阻断，不伪装成普通坏条目继续发布。
6. 无效、重复和超额返回不退还真实请求与费用；候选资源预算的实际消耗、授权发布上限和新增库存分别计数，不能只按成功入库计消耗后无限补足。新批次共享原 session/账本预算；UNKNOWN 不换 batch key 或作业身份重发。
7. 去掉逐批 `pool.rows()` 的全池实体/来源加载。按新候选身份及相关应用使用索引查询；模型上下文只含本批必要的有限提示，不发送全库目标。原输入冻结来源、配置、规则及本批相关去重依据，不复制全池去重键。当前条目、来源及领取时的证据仍须核验，不能用未经核对的文件缓存代替证据检查。

全库证据审计与生产批次查询分开；索引与上下文优化只减少无关读取，不改变历史完整性要求。并发插入的唯一约束仍是最终精确去重依据，不能只依赖冻结时刻的已有列表。

## 5. 消费者适配与保存语义

主要模块为 `candidate_contract.py`、`candidate_consumer.py`、`candidate_navigation.py`，以及主计划中的 `agent_controller.py`、`workflow_planning.py`、`collect.py`、`collect_runtime.py` 和保存/加工模块。

- 新入口通过薄适配进入主计划的同会话 URL 工具循环。领取和原账核验在首次请求之前完成；不新增一次独立浏览器观察、前置目标规划请求或完整演练。
- 初始 `working_goal` 为空。生产者建议是带来源的不可信上下文；Agent 观察实际页面后建立方向。没有明确要求时，可因页面证据放弃建议、选择其他授权内方向，并记录原因；有明确要求时不得偷偷替换要求或忽略参数。
- 新协议不比较生成的自然语言指令是否逐字相同；验证原领取快照、明确要求及其参数摘要、应用/权限范围、观察与事件链。旧协议继续原逐字验证，不能删除旧校验作为兼容措施。
- 可达性、登录、控件、单位选项、有效操作与结束原因按实际观察判断。交付采用“有效操作 ≥5，或 short_flow 并说明原因”，短流程累计 ≤2%；无 5–8 或 8/10 步强制停止，不为凑数执行无关动作，也不增加完整业务完成门槛。
- 原始执行保存和样本加工分开。完整原件已保存但加工失败时，记录原件与加工失败，不能直接标为候选 `succeeded`。达到成功所需的新样本保存/交接收据及其与 RuntimeStore、原 claim 的核验，由主计划 P2 一并实现。
- 不因改为入口候选而在同一 claim 中悄悄重复执行，或放弃原目标候选另领入口重发。已有在途、UNKNOWN、保存收据和生产占用跨协议可见；又不额外增加“同 URL 永久只能一条”的交付限制。

候选消费成功仍只表示已有可核实的保存待审结果。原始执行已保存、加工成功、待审、独立 QC 通过、批次接纳、人工审核、发布与客户验收分别报告。后加工重试只读取原件，不重放浏览器或重发原模型 UNKNOWN。

## 6. 实施顺序与依赖

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| C0 契约与兼容 | 两种新候选、可信目标来源、版本分支、显式扩展、身份和统计；保留旧链 | 新旧协议共存、原快照不变、未安装不写入、原锁及 hold 用例通过 |
| C1 轻量生产者 | 可选目标、文章类型提示、逐条入库、部分成功、原响应恢复、定向查询 | 混合批次、预算、来源归属、并发去重、零浏览器与零消费用例通过 |
| C2 同会话消费接入 | 将新候选适配到主计划 P0/P1 的真实工具循环，区分要求与建议 | 同会话观察/操作、目标更新和权限/租约检查通过；不再依赖旧前置目标生成 |
| C3 保存及审核交接 | 接入主计划 P2/P3 的原始保存、整条加工、收据与 QC | 原件保存但加工失败不假成功；保存恢复不重放；独立 QC 可读取实际样本 |
| C4 联合验收 | 主计划 P4 工程检查与获授权的有界真实闭环 | 来源、消费、样本及 QC 分别有真实证据；不足时如实保留未完成 |

C0/C1 可以先完成离线工程改造；C2 必须与现有同会话 Agent 改造合流，不能临时再实现第二套控制循环。新默认入口和 consumer 协议只有在兼容及保存链验证后才一起启用；冻结的旧 run/config 仍路由旧分支。1000 条吞吐与长期稳定性在小批闭环之后评估，不作为自动扩大真实运行的理由。

## 7. 选定离线验收

复用 `tests/test_candidate_inventory.py`、`tests/test_candidate_consumption.py`，补充新协议用例；再按实际改动选择 `site_pool_reader`、任务适配、控制循环及保存链的直接受影响模块。公共契约变化需要覆盖上述直接调用链，但不默认跑全量历史回归。通过 README 的选定离线验证器执行，每次新建验证目录并保留源码摘要、日志与失败。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 只有真实 URL，无具体目标或类目判断 | 新入口可入库，未知如实保留；旧泛化目标仍被旧协议拒绝 |
| 普通文章、换算教程、推荐导航 | 可作为自身内容入口；类型提示不会冒充可操作工具 |
| A 站来源却声称是 B 站工具 | 对应条目拒绝；不替换 URL，不妨碍同批独立有效条目 |
| 一批含有效、重复、坏来源、坏建议和空白字段 | 逐条留结论，合规入口可提交；不编造缺额或回改原响应 |
| 整批 JSON/外层失败，数据库或证据错误 | 保留原件和已知请求结算；停止发布，不把故障当候选不适用 |
| 0/不足/超额返回与批次消耗 | 报告缺额或超额，新增量与消耗分开；无隐形补调用 |
| 部分提交后进程退出，再恢复原响应 | 不重复行、费用或候选消耗；不新增模型/搜索请求 |
| 同入口不同建议、重复事件、并发写入 | 身份稳定，来源追加，唯一约束有效；不按措辞增加库存 |
| V1/V2 候选共存，旧 claim 已领取，新扩展安装中断 | 原快照、版本、状态及收据不变；安装回滚；新协议不落入旧执行分支 |
| 当前应用/其他作用域 UNKNOWN、无作用域 UNKNOWN、认证 hold、整站三次失败及投影滞后 | 沿原规则区分作用域；受阻范围零新发送，已证实不相关的范围按原策略处理；成功缓存仍可核对 |
| URL-only 与明确目标分别进入消费者 | 前者现场形成工作目标，后者保留要求；建议不被当系统指令 |
| 新协议改写叙述、调整建议，旧协议改写指令 | 新路径核验结构与事件；旧绑定不能被放松 |
| 原始执行保存成功、加工失败、投影失败、租约过期 | 各状态分列；成功须核验正式收据；恢复只对原件与原账，不重放 |
| 多批扩展到 1000 条合成入口 | 新增/重放正确；只触及本批相关候选和来源、上下文有上限；不读取全池证据、不启动浏览器或消费者 |

查询检查应验证查询范围及证据读取次数随本批相关数据增长，耗时与输入大小另行记录；不能靠机器相关的固定毫秒阈值宣称性能通过。离线 1000 条只验证库存、边界及恢复能力，不折算真实库存吞吐或轨迹产量。

## 8. 后续真实验收与计数

当前不运行真实验收。实际实施时复用用户已有、仍覆盖本次协议及范围的授权；已耗尽或停止的旧验证不自动恢复。真实范围、批数/尝试上限、原链/账、模型与 QC 预算和停止条件需要在派发前绑定，不能靠本计划中的数字自动建立新额度。

生产者可沿用每批上限 5、连续多批的观测方式，检查入口忠实、可选建议不冒充事实、入库与消耗正确、无浏览器和无隐形纠正。记录原始返回数、新入口、重复、拒绝、被 hold、缺额、来源 AI 核对及实际用量；来源 AI 核对是验证证据，不作为每条生产入库必须另请 Agent/人工审核的常驻前置。

新协议允许部分成功，不能沿用旧“严格原始五条全合格”的标签宣称同一标准通过；若再次做严格五条稳定性对照，应另列原始错误率与完全无纠正批次。入口数量、明确目标数量、来源核对通过数与可执行样本数各有分母。

联合验收须至少有一条新入口经改造后的消费者完成真实执行与整条加工，实际样本符合需求并通过独立 QC；这同时满足主计划的真实功能验收，不要求再采一条重复证明。该样本必须实际受审，不能以 NOT_SELECTED、旧样本、待审或夹具 PASS 替代。遇原 UNKNOWN/认证/整站止损则停止依赖运行并保留证据，不为取得 PASS 绕开保护。

最终分别报告：发现入口、明确目标、消费领取、正式尝试、原始执行保存、加工成功、采集待审、实际 QC 通过、按策略接纳、发布与缺额；没有合格结果时，不计算“每合格样本成本”。搜索/模型/Codex 核对的计量缺口保持 UNKNOWN，不把已知部分费率估算写成总费用。

## 9. 文档与变更边界

不自动迁移真实池、不修改历史失败或审核结论、不重签旧规则、不重建 manifest、不回收编号，不提交本地原件、请求、SQLite、凭据或 ZIP。源码实现、真实运行、发布和提交分别依用户范围执行。
