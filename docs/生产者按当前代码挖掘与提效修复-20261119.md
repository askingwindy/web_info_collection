## 哪些东西跟随当前代码

| 工作状态 | 下一次运行的行为 |
| --- | --- |
| 新批；旧批中尚未派发的工作 | 使用启动时工程内的当前实现、提示词、工具与筛选规则，不检出指定 Git 提交，也不要求旧提示词文本相同。旧的未派发输入保留作记录，不作为新调用的参数。无需升级候选版本。 |
| 已派发且有结果 | 检索规划、首页分类、入口选择用原 job ID 读取结果，不按当前提示重造请求。页面业务判断可以重用已结算的结构化事实，必须映射到当前核验的原件并重新通过当前规则；缺必填项或引文不匹配不放行。 |
| 请求已派发但无可用结果 | 保留原 `UNKNOWN`、`reserved`、确定拒绝或隔离记录；不重发，不换批绕过。同页已派发而可核验的用途缓存缺失时也保守暂挂；不以推测补结论。 |

旧批授权的站点范围、目标、上限及原账身份仍核对。模型账号与预算授权绑定不解除；来源、原图、DOM 和请求正文摘要用于核验原件，候选标识、已领取快照与原批次行号不变。这些都不是源码 SHA 门禁。“当前”指本机实际启动的代码，不会自动拉取远端或热替换已运行的进程。

## 付费前的四项优化

1. **先判语言。** 从成功、匿名、第一方 GET 的原始渲染正文判简体；有繁体或中文材料不足时，不组装页面业务判断请求。发布仍复核实际落地与语言；不翻译、不补抓来凑条件。
2. **去重分两步。** 观察前查已发布的候选及已知落地；知道实际落地后，在模型前再查。复用现有站点、入口／目标及路由身份。同机多进程对同一身份互斥；另一方稍后有原账可读，不靠重复派发获取结果。不同目标和独立 hash 路由不因同站而一并去掉。新的派发索引只属于生产者请求账。
3. **缩短模型输入和输出。** 筛完才给本次真正送模的页面连续编号 `p1…pn`，模型只看站点主类，不需要抄站点决策摘要。每页只回业务判断、当页引文编号、内容类别、公开可访问性四项；不替消费者猜任务或步骤。宿主保留页码、URI 与证据映射，逐页核验；多余键留痕，缺项不补猜、不重发，可独立核验的其他页不受牵连。
4. **栏目按产出排序。** 站内扩展取近期已结算的 `NEW`、重复和拒绝结果，不把未决当失败。样本达到 3 个才按平滑净新增率排序；有待探索栏目时，每 5 个位置保留 1 个，多个主机轮流取页。不改变站点发布上限。
