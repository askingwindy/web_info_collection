## 2. 统一判断责任与阻断边界

| 事项 | 主责任 | 工程如何处理 | 是否阻断正式保存待审 |
| --- | --- | --- | --- |
| 目标是否完成、回答是否对应原问题、下一步业务意义 | Agent | 保存原目标、结论、未完成部分及证据；不使用固定措辞、关键词数量或计划长度替代语义判断 | Agent 明确未完成不得改签完整目标成功；已有片段规则保持原义 |
| 答案准确性、充分性、表达质量 | Agent 先判断，独立 QC 后审核 | 语义疑点记入已有待审信息，不追加保存前独立审核模型 | 单纯工程语义启发式不阻断；不伪造 QC PASS |
| 动作派发、实际效果、观察与引用来源 | 工程 | 核对同 attempt 的原观察、动作记录、可证明效果和引用绑定 | 未执行、伪造引用、错任务/错观察、实际效果 UNKNOWN 等事实问题仍阻断相应成功样本 |
| 页面身份 | Agent 判断结合工程来源证据 | 同文档、标题/页面来源及相关正文证据相互支持；导航补全、滚动、目录变化、可接受动态区域和布局移动不单独否决 | 有明确错页、正文替换或来源冲突时阻断；不能只因整屏不相等拒绝 |
| 有效步数、short_flow、编号、哈希、文件和账本 | 工程 | 根据最终保存范围生成和验证；0 不成样本，1–4 短流程，≥5 普通流程 | 缺原件、编号冲突、账本绑定错误、不可确定派发等仍阻断 |
| 独立内容检查、完整 QC、人工、发布与客户验收 | 各自审核/交付流程 | 分别记录，保存待审不授予其他状态 | 不新增本轮保存前置；正式发布仍受原交付规则约束 |

“工程判断为辅助”不等于无条件相信模型。工程有可复核事实矛盾时必须指出；工程无法凭启发式认定语义错误时，应保留 Agent 结论并待审。确实无法绑定来源或无法确定执行效果时，保留原件待核，不伪装为普通可交付样本。

不得将所有工程错误降为 warning，也不得把所有 ValueError 统一吞掉后保存。明确区分业务未完成、证据冲突、工程加工失败和质量待审，优先映射现有状态/原因字段，不另建泛化状态框架。

## 4. 消费者 Agent 的 goal、prompt 与 tools

**Goal：**固定已接受的原问题与参数。Agent 主导理解、路径选择和完成判断，明确已完成、未完成及依据。不能因工程故障换题或缩小范围；自然完成就结束，不为短流程比例或步数补操作。

**Prompt：**保留当前决定真正需要的协议、原目标/checks、最新观察、相关已读正文和已执行动作。可以删重复解释，不能删模型实际需要的字段结构，也不能让模型参照并未发送的 schema。明确 continue 执行原剩余步骤，改变路线须 replan；完成回答无需先单独 cite。继续保留单独 cite 的兼容入口，不强制每个样本减少到固定调用数。

**模型可见 tools/schema：**首轮原生工具与普通 JSON 分支都使用当前合法契约；正文摘录、已读节点列表、可省继承字段、检查项顺序等确定等价输出得到同义处理。缺失必要执行参数或业务意图冲突时，给具体反馈，不猜目标和动作效果。

**宿主实现：**只在一个共享归一化路径整理语义等价的表达，各层复用；允许后置独立核验原件，但不再以不同规则解释同一字段。原始回答、归一化结果与证据来源的对应关系保留。

模型、GLM provider、推理档位和推理图片质量保持现有正常入口配置；原 PNG 保留。不新增模型摘要调用。短流程及原因、实际计步、编号等工程字段不交给 Agent 申报。

验收分开报告工程代码变化与消费者 Agent 的 goal/prompt/tools 变化；生产者职责和库存本轮不改。

2. 核对原 attempt、终态、原始收据、有效动作、隔离目录、派生文件与原账事件。不只依据“原进程退出”就把全部在途工作判定为失败；不删除租约字段或手写成功状态绕过条件。
3. 在本轮恢复逻辑完成并集成通过后，优先从 R03 已封存原件派生及保存，不重开浏览器、不新增模型请求、不另建 attempt、不换账。使用原预留身份和新增恢复/派生收据；原文件不覆盖，旧失败保持。
4. 通过正常提交入口形成保存收据、原账终结状态及回读结果。若既有入口缺少处理该已知部分完成状态的能力，本轮只补齐该实际断点，不直接 SQL 改成成功。
5. 如果原件缺失、冲突、未决事实阻止恢复，记录具体失败并停止。不得以新采样代替原账恢复，也不得使用零执行结算函数处理 R03。

恢复后只可达到 `collected_pending_review`；研发复用保留 `production_counted=false`/原有 effective 口径，不把恢复样本和历史样本重复计为生产新增。若实施前该 attempt 已被合法恢复，核对其有效收据并复用，不重复恢复或改签。

## 6. 一次集中实现与验证顺序

**顺序固定：读取当前状态和必要证据 → 校验职责清单与必要设计 → 集中完成代码、Agent 接入及文档 → 一次本轮整链集成 → R03 原件恢复 → 新 Vue 短流程真实 GLM → 常规流程真实 GLM → 报告。**

本轮统一改动需要一次新的、针对本轮功能的集成；不重跑 R01 已通过的旧集成，不运行历史 77/332 项全量套件，不每改一处就反复测试或冻结。

集成集中覆盖下列行为，尽量复用现有夹具、R02 失败回包和 R03 原件只读投影：

| 覆盖项 | 要求 |
| --- | --- |
| 模型实际收到的协议 | 首轮/分支各自必要字段真的出现在出站消息；不能只测宿主持有的 schema |
| 输出等价与歧义 | 别名、继承字段、乱序 checks、连续摘录、唯一节点引用、非业务完成标记贯通；冲突动作、错观察、错来源不静默执行 |
| Agent 完成到保存 | 同轮引用＋继续/重规划、直接回答带引用进入正常保存回读；不用正文关键词或布局等同性再次审批完成 |
| 页面身份正反例 | 同文档导航补全、目录新增、正文布局移动可接受；同 URL 正文被替换、错文章、错源等明确反例仍拒绝 |
| 最终范围计步 | 0/1/2/4/5/8 动作边界、计划长实际短/反向、空摘要及错误模型标签；非业务动作不计步。至少有短/常规两个受控保存结果贯通导出与回读 |
| 加工失败与恢复 | 原件密封后模拟保存错误；重复收尾核验同绑定、冲突不覆盖，账本可结算；修复后从原件恢复，浏览器/模型新增调用均为 0 |
| 最终一致性 | 原始轨迹、派生动作、标签、保存收据、客户导出和 QC 待审交接一致；不运行独立 AI QC、不伪造人工审核 |

独立事实反例的预期拒绝不等于集成失败。单次正常模型会话内部的既有合法反馈和有限纠正照常运行，不把每条拒绝都当最终失败，也不另开会话绕过。

**停止规则：**本轮集成、R03 恢复或任一真实试跑最终失败，就停止后续验证，保留日志、首要错误和清理错误并直接报告。不得自动修复再跑、换候选/目标、新开 attempt 或继续常规流程。集成前的正常实现和静态检查不按“失败后重试”解释。
