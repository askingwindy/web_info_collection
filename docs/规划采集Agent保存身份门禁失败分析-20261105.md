升级（提交 `586470f`）后的规划采集 Agent 模型侧链路已经跑通：r03 真实会话完成首轮规划、分支引用、2 个有效业务动作（同页目录定位「指令」「组件」）、目标取证与 finish 依据，r02 暴露的模型格式拒绝已被 `normalize_branch` 归一化修复消化（离线契约回放 + r03 真实分支全接受）。

## 根因：锚点快照与水合竞态

锚点来源：[candidate_consumer.py:144](../projects/code/webcollect/candidate_consumer.py#L144) 在会话入口把首帧状态冻结为 `first-state.json`，随后既作 `pilot_identity.task_page.anchor`，也作应用证据。`capture_readiness` 只等 `document_ready=complete` + 字体 + 图片，对客户端水合的 SPA（VitePress）不充分。

对同一 document、同一 URL 的两次快照对比（实测）：

| 快照 | 元素数 | visible_text | 内容特征 |
|---|---:|---:|---|
| 锚点 `first-state.json` | 39 | 446 字符 | 只有「本页目录」（19 项，缺「具名插槽」「选项式 API」）+ 首段；**整站页头缺失**（Vue.js/搜索/文档/演练场/生态系统/关于/支持） |
| 模型首轮观测 observation-001（含水合后） | 70 | 514 字符 | 页头、完整目录均在 |

即：**门禁的锚点从一开始就不匹配本会话自己看到的第一个状态**，后续状态更不可能匹配。归一化（去空白、数字/URI 替换）后：锚点 392 字符与观测的公共前缀为 0——页头 21 字符被**插在锚点文本之前**，2 个目录项被**插在锚点目录序列中间**（「宏 (macro)」与「术语表」之间）。锚点正文在观测中确实存在（偏移 21 处可找到），但不是连续子串。

| 路径 | 位置 | 结果 | 失败原因 |

| c. action_stability reading_projection（锚点唯一可见 main=e_22） | [L158-170](../projects/code/webcollect/production_identity.py#L158) | 失败（3 个观测投影均不等） | 锚点 main 是水合前残缺正文；且用锚点元素 id 对后续快照取投影，元素编号漂移直接不可比 |
| d. dynamic_regions 投影 | [L138-145](../projects/code/webcollect/production_identity.py#L138) | 失败 | 锚点水合前未探测到任何区域（`regions: []`），投影退化为原样、等价路径 a 再失败一次；另见下条 URL 缺陷 |

路径 c、d 的设计意图是宽容**观测侧**变化，但都隐式假设**锚点侧**完整——锚点本身残缺时两条宽容路径名存实亡。

## 代码问题清单

1. **根因：入口锚点截取无水合稳定等待**（[candidate_consumer.py:144](../projects/code/webcollect/candidate_consumer.py#L144) 一带）。锚点冻结的是会话内从未真正存在过的中间态。
2. **路径 d 用裸 URL 精确相等**（[production_identity.py:142-143](../projects/code/webcollect/production_identity.py#L142)，`row.get('url')==state.get('url')`）：比较含 fragment，与全文件统一的 `page_url()` 去 fragment 别名模型自相矛盾。目录锚点跳转（`#directive`/`#component`）产生的状态在该路径下永远不可能命中。
3. **路径 b 包含语义过窄**（[L149-157](../projects/code/webcollect/production_identity.py#L149)）：只容忍尾部增长，不覆盖水合/导航栏注入的前插与中插。
4. 路径 c、d 对锚点时序的隐式依赖（见上表）。
5. 非问题项：未提交的 `projects/code/tests/test_branch_wire_contract.py` 4 项全过，对 r02 两条真实坏回复的回放归一化正确；`586470f` 的分支线修复有效。

## 修复方向与取舍（规划，未实施）

- **A（推荐，根因）**：入口锚点冻结前增加水合稳定等待——在现有 `capture_readiness` 之后，要求连续两次快照的元素集与可见文本稳定才冻结锚点；等待有界，超时如实记录并沿用当时快照。一处改动同时改善锚点与模型首观察。代价：入口多一次快照开销（本地浏览器内，无模型成本）。
- **B（顺带修，明确缺陷）**：路径 d 的 URL 比较改用 `page_url()` 归一，与全文件别名模型一致。
- **C（不做，过度设计）**：为路径 b 增加词集/错位包含等宽容语义。它掩盖的是"锚点残缺"这一上游事实；A 修复后该需求不成立，且宽容语义会削弱"实际页面佐证原锚点"的门禁强度。

## 验收口径（修复后适用）

1. 离线：用本轮真实数据（`first-state.json` 与 observation-001 的状态）作夹具复现"水合中锚点 + 水合后观测"，断言修复后 `validate_identity` 通过、路径 d 对 `#fragment` 状态可命中；`test_branch_wire_contract.py` 保持 PASS。
