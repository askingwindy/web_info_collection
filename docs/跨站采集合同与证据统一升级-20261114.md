# 跨站采集合同与证据统一升级（2026-11-14）

目标：通过统一业务合同、执行事实和完成证据支撑不同站点；不继续逐站、逐 selector 或逐
错误文案打补丁。直接修改当前实现，无新增代际版本、legacy 执行器或兼容分派；历史
claim/attempt/UNKNOWN/费用/失败分类/原始证据不改写。本文记录规格映射、模块收敛与验证边界；
离线证据见 `verify_results/cross-site-contract-20261114-r01/`。

## 一、规格 → 实现映射

### A 业务合同与执行预测分离
- `submit_plan` schema：`evidence_route`、`source_type`、`observation_steps`、
  `final_presentation_step`、`answers.observed_result` 均不再必填；`evidence_scope` 必填显式
  （`screenshot_plan.requirement_schema`）。封存重放（`verify_first_evidence_routes`）不追认
  新校验：历史计划省略 `evidence_scope` 时按旧语义 current 校验，仅新会话强制显式
  （`collection_contract.evidence_route_gaps(require_explicit_scope=)`）。
- 宿主编译：`collection_contract.compile_contract` 在首轮接受后生成执行预测并逐字段记录来源
  （`screenshot-contract-compiled` 事件 + `screenshot-plan.contract_derivation`）：
  - `source_type` 按 kind 推导（content 含推导义务→`derived_check`）；
  - `result_kind` 不可确定时保持 `None`（未知按普通页面结果核验，绝不默认 calculation）；
  - `observation_steps` 缺省锚定到结束展示帧；
  - `final_presentation_step` 缺省取末步。
- `depends_on` 集中检查引用、自身引用与**传递环**（`_dependency_cycles`）。
- 弹窗关闭/聚焦/滚动定位不自动成为正文交付事项（沿用 `_presentation_repair_permitted` 白名单）；
  首轮只检查确定的结构与业务矛盾（`first_plan_admission` 全家检查迁移至 `collection_contract`）。

### B 完成证据采用引用
- `answers` 只需 `requirement_id` + `evidence` 引用；宿主从原始捕获生成规范
  `observed_result`（check 记 `observed_result_source: host_capture|model_declared`，
  `observed_visible_text` 为引用节点原文）。模型誊写文本仍走逐字+实质校验；quote 仍是
  无唯一 region/control 时的受限定位（≥8 字符、区域内包含）。
- 覆盖谓词集中在 `collection_evidence.coverage_gaps`：比较/替换两端必须有各自证据
  （`COMPARISON_COVERAGE_INCOMPLETE`）；有界正文/清单/表格事项要求区域整体按序覆盖或
  合同「」列举项逐项覆盖（`CONTENT_COVERAGE_INCOMPLETE` 列缺项）；**分母只来自合同**
  （区域全文或列举项），删除“单节点全文命中即完整”的替代规则；content 证明跨帧跨条目累积。
- 共同完成谓词 `distinct_result_gaps`：不同输出事项复制同一位置同一答案被拒；同节点不同
  字段声明、不同节点同值事实保留。
- 时效/隐藏值/阶段：`_result_superseded`、可见性门禁、三份记录
  （model_has_seen / provided_observations / host_input_proofs）不变，均为唯一实现迁移。

### C 唯一事实与上下文
- 携带必要历史关键帧的请求是**纯证据登记请求**：choices 收敛为 `complete/give_up`，wire 工具
  无 `remaining_plan`/`continue`（多图与单图两种模式一致）；单图配置下该请求只携带历史图，
  随后的动作决策重新使用当前图；`(事项,帧)` 配对成功消费，不重复提供
  （`history_supplement_keys` 语义不变）。
- 请求上下文、去重（`_checkpoint_requests`，键含证据指纹——覆盖增长可刷新）与停滞核算不变。

### D 统一执行恢复
- 保留既有恢复分支（零派发有限重编译≤2/45s、已派发只补观察、已知无效果修订、UNKNOWN 有界
  结束不自动重发），未新增万能重试；能力投影与派发共用判据不变。

### E 导航范围
- `candidate_navigation` 成为唯一许可判定入口：`destination_allowed`（首帧/派发前/落地后/封存
  共用成员规则；精确导航关系不授予目的地域名权限）、`check_url`（`collect_runtime.url_check`
  委托）、`admit_landing`（非候选落地收账，替代 session_core 内联主机检查）。
- 派发前反馈：`_navigation_destination_gap` 对确定不允许的目的地（含运行范围排除文章）返回
  `NAVIGATION_DESTINATION_NOT_PERMITTED` 检查点反馈，交回规划器修订；无范围内路径则 give_up，
  不重试同一路径。范围拒绝/来源未知/工程错误仍按原失败分类分别记账。
- `application_identity` 仍只裁应用身份；生产者种子证据与候选四字段协议未改。

### F gateway、配置与预算
- 错误分别处理：`finish_reason=length` → `output_exhausted`（settle `failure_diagnostic.source`
  记录；唯一允许纠正是同一观察的**紧凑重提**；第二笔仍有界结束，无第三笔；不执行截断参数、
  不原条件通用重发）；refusal → `refused` 有界结束不重发；schema/工具/传输/本地异常路径不变；
  UNKNOWN 永不进纠正。
- 会话实际模型 HTTP 请求上限 40（`SessionGLMCallLimit`），**消费者会话同样生效**；
  会话软时限 1800s + 收尾宽限 120s：`session_limits` 纳入一次解析的有效配置
  （`batch_core.validate_config`），`entry_session` 构造 `host_limits` 贯通
  session（`ENDING_POLICY` 不再丢弃）→ boundary.json；`_dispatch_deadline` 由会话下发、
  chooser 透传、网关对消费者执行（软时限后不再发起新模型请求）；`collect_runtime` watchdog
  在硬截止 `cancel('consumer_session_hard_deadline')`，未决请求保留 UNKNOWN。
- 协调器不自动重启非零退出 worker（原有行为保持）。

## 二、模块职责收敛
- 新增 `collection_contract.py`（合同编译/业务语义/矛盾检查）与 `collection_evidence.py`
  （引用解析/覆盖/时效/共同完成谓词），均为唯一实现；`screenshot_plan.py` 只保留线协议
  （schema/normalizer/工具/chooser）并转发；`postprocess` 改引新模块。在线核验与封存复算
  共用同一套函数（`validate_ending_marker` 重放与在线一致，隔离链已验证）。
- 受影响调用点：`screenshot_session`（合同冻结/证据登记请求/派发前导航反馈/deadline）、
  `session_core`（host_limits 保留/统一落地入口）、`model_gateway`（分类/上限/deadline）、
  `batch_core`（上限 40/session_limits 校验）、`candidate_navigation`（唯一许可入口）、
  `collect_runtime`（url_check 委托/watchdog）、`candidate_consumer`（host_limits 构造贯通）。
