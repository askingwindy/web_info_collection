Agent 与工程确有未对齐之处，集中在首轮工具、后续分支路由和输出整理；不能把全部失败都归于模型能力。上一轮真实 10 条为零有效动作、零保存，47 次请求中 46 次协议失败；另一次离线集成的八个失败须按夹具与产品区分，不能合并成真实失败率。

## Agent 与工程的共同边界

模型直接填写必要业务计划，首轮 JSON 数组/对象保持结构；无需填写宿主能确定的 attempt/observation 等事实字段。首轮普通完整路径必须自然需要 5–10 个有效动作；无自然五步路径就说明原因停止，不改变已冻结目标或凑步。剩余计划只解决未完成部分，可以不足五步。Wiki 继续依据实际页面自由定位与阅读，完成回答从已观察正文 evidence_id 选择，目录与标题不当正文证据。

实际普通候选仍须 5–10 个有效动作、原目标完整、正式保存。`controlled_exception` 不交付、不补数；真实 1–4 步如实 short_flow，内部失败与可信片段保留。原 UNKNOWN 不通过新 Key、作业或编号重放。采集待审、独立 QC、人工、发布与客户验收分别统计。

## 本轮真实验证范围

沿原 `candidate-project-baselines-deep-20261109-r01/scope.json` 绑定的 Table2、manifest、作业账与 RuntimeStore，从 pending、从未领取的生产候选中固定 Muxtly/Wiki 各五条。按创建时间与候选 ID 排序，冻结版本、来源与证据哈希；不是复用旧失败请求。目标为空时只在可信首帧选定一次，因此这轮不能作为同目标 A/B 的完成率结论。

[固定名单](../verify_results/consumer-protocol-alignment-20261110-r01/baseline/roster.json)一人一条，全部同时启动，各自 `--limit 1`，无候选替换、失败补位或自动续采。真实 GLM 保持原 high/high 配置，Codex 调度与修复子会话全部 low。仅总控进行一次每 Key 轻量探测并单列用量。十个消费者结束即停；无进展明确失败按原始账记载。源码冻结后不边采边修。

本轮没有运行单元、集成、回放或编译测试。只做源码审查、差异格式检查和这一次真实验证；静态检查不是测试 PASS。独立 AI QC、人工、发布和客户验收不在本轮范围。

总控及十个消费者全部自然退出，停止原因 `FIXED_COHORT_EXHAUSTED`。父会话再次核对进程均不存在，470 个冻结源码/测试文件前后摘要一致。运行原件见[真实报告](../verify_results/consumer-protocol-alignment-20261110-r01/validation-r01/report.md)、[逐条结构化分析](../verify_results/consumer-protocol-alignment-20261110-r01/validation-r01/analysis-summary.json)及[父会话核对](../verify_results/consumer-protocol-alignment-20261110-r01/parent-final-audit.json)。
