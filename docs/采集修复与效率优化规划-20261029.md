## 轨迹选择与必要操作

新任务优先选择自然完成需要5至8个有效操作、目标明确、结果能在原始截图中核验的流程。5步即可满足必要操作数量门槛，不要求接近10步。`wait`和`complete`继续不计有效步数。

5至8步是规划偏好，现有5至10步校验与已冻结任务继续按原绑定核验。确有必要的9至10步任务保留其真实动作，列为低优先并说明无法省略的原因；不会因超过理想范围直接改签失败。不得删除必要动作或压缩真实动作记录来迎合步数。

规划时遵循以下顺序：

1. 根据实际初值确定必须修改的字段；满足目标的默认选项保持原样，避免为了增加操作而更改无关条件。
2. 优先选择交互紧凑、必要输入较少、结果可直接查看的功能；确实需要滚动或展开的操作仍完整记录。
3. 有原值需要替换时，真实点击、全选和输入分别记录。每个动作是否必要由实际页面和任务目标决定，不能把三次执行伪装成一次，也不主动拆分本可自然完成的动作凑数。
4. 达到至少5步且任务目标已经完成、可见终态满足要求时结束；不为凑到8或10步再添加操作。自然不足5步的任务不靠等待、完成确认、重复点击或无关导航补数。
5. 继续要求不同任务在目标、路径、页面状态或结果判定上具有实质差异；缩短流程不授予参数变体独立性，最终仍进入累计QC。

本轮日期样本已是7个有效动作加1个不计数的complete，说明当前门槛允许自然的5至8步轨迹。随机数的三字段替换形成10步，后续新任务规划应优先检查目标是否真的需要修改全部字段；原失败任务和停止站点不因这种新偏好自动重试。

## 优化次序与验收

1. **先减少误拒绝与返工。**优先完成C01/C02/C03/C04/C11/C12/C16/C18：失败责任分离、配置前置检查、来源多图协议、加载状态前进、完整失败诊断及有界重新取证。保留完整原图与关键状态保护，按统一方案验证局部绘制容差，不能靠删除必要检查或修改原图提速。
2. **补齐累计结果与恢复。**完成C05/C06，避免已保存样本漏入比较总体、未派发草稿反复触发不清晰错误。恢复只补缺失状态，不重采成功数据或重发UNKNOWN。
3. **接通GLM规划，新任务优先自然5至8步。**按C17将真实页面工作流提案接入既有编译器和待采队列，将必要操作数、可见终态、输入修改数和必要滚动纳入规划排序，核查5步自然完成案例、9至10步必要例外，以及无关操作凑步拒绝。Codex承担程序开发与异常分析，不再作为每个新功能必经的专门工作流编写环节；该目标尚待实现和验证。
4. **落实批量后置QC。**后续批量流程为先采集并保存待审证据，再冻结实际批次，统一运行全量机械/累计去重、显式样本抽检及按批资料审核。首关独立累计QC的例外单列，不把现有单条入口写死的AI100%推广到整个批量。模块已支持可配置比例，样本AI覆盖可以降低；具体新比例与风险扩检规则尚未冻结，原100%收据不改写。单条分母1即使设20%仍ceil为1，必须先合批。资料AI按现有政策覆盖实际批次资料；只复用原件、规则及比较绑定仍有效的结果，变化的资料或全局比较照实重验。未抽中按显式抽检策略记录NOT_SELECTED，不宣称逐条AI通过，必要未决仍待审。批次化实际节省须实测，详见统一清单C15。
5. **依据计时优化取证与等待。**分别记录页面访问、capture、动作前重验、动作执行、固定等待、保存/交接和QC请求耗时。评估用目标状态就绪的有界等待替代不必要固定等待，保留真实加载/遮挡/坐标检查；先在局部夹具和有界真实任务比较成功率、错误率与耗时，不扩大并发或缩小原图掩盖开销。

新增性能验证应报告每条采集耗时与每条最终合格数据的端到端耗时，区分首次准备、共享开销、失败返工和稳定运行；数量足够后再给中位数及高分位。失败、待审、重复、合格、发布分别计数，不以跳过审核或将并发执行时长相加来制造提速。
