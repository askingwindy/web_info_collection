## 4. 工程代码优化

### E1：固定等待变成有界就绪等待

位置：`discovery_tools.DiscoveryBrowser._read()`；尽量用一个小的生产者专用辅助模块承载就绪判定和计时，不复用或改动消费者采集逻辑。

1. 保留已有 body 可见等待和总访问超时。在原第一个 1200ms 窗口内，对主内容、可见控件和首帧图片进行短间隔观察；存在可读内容且连续观察稳定时提前结束。无主内容、仍有首帧图片未加载或尚不稳定时继续等待，最多原窗口长度。不要用全页 network-idle、广告/公告变化或主区文字长度作为新的准入门禁。
2. 图片覆盖判断的第二次观察仍真实执行。首帧完整清单已明确不满足图片排除条件，且没有仍待加载的可见图片时，省去第二个 1200ms 延时，直接做第二次实际观察；不得复制第一份结果伪装二次观察。
3. 首帧可能触发图片排除时，保留原第二段等待和二次几何核验，避免把暂时加载图片误判成无需消费。阈值与动态区域的既有处理口径不变。
4. 保存实际等待时间、提前结束原因及是否执行图片延时复查。就绪结果只控制等待，不授予业务资格或采集成功。

验收：静态正文/工具页减少等待；延迟加载正文和图片仍获得正确证据；达到/未达到 95% 阈值、动态图片和未知清单的结论与原规则相容；PNG、DOM、HTTP、URI、匿名访问身份继续完整绑定。

### E2：明确 HTTP 失败提前结束

位置：`DiscoveryBrowser._read()` 和 `page_consumption.screen()`。

1. 浏览器 `goto` 返回真实 HTTP 4xx/5xx 且没有导航未决时，在正文等待、截图和完整 DOM 提取之前收束。保存版本化 `producer-http-failure-1` 收据：原 URI、响应/落地 URI、HTTP 状态、method、job/visit/tool request、时间、策略及原因。
2. 同一个原 visit 结算为 failed，原工具请求保存明确失败，job 记录确定的完成结果；后续筛查读取失败收据，不重新派发。同源其他页面仍可继续。
3. 导航超时、连接异常和没有确定 HTTP 响应的情况继续 UNKNOWN，不借提前失败路径把未知变成已知失败或零费用。
4. 明确入口 403 按该页面废弃处理，不入 Table2、不再派发；HTTP 521 等失败保留页级失败事实，不扩大为整站禁用。
5. 成功观察的证据结构不削减。失败新路径允许没有 PNG/DOM，但必须是可核验的明确 HTTP 失败收据；不能产生成功/可消费记录。

验收：受控 403/404/521 零固定延时、零成功证据、零用途模型派发；原状态正确结算、恢复零新增 I/O；相邻 200 页面仍完成正常筛查。历史完整失败证据保持原字节。

### E3：为 Agent 汇总失败事实（工具宿主实现）

用现有 SQLite 只读查询获取同工程最近有界的 `site-discovery-page` 访问，按 host 汇总成功、HTTP 失败、导航 UNKNOWN、明确状态码及导航错误码。保留统计窗口、分母与原 visit/job ID，保存不可覆盖的摘要收据，模型输入仅放紧凑摘要和摘要身份。

最多读取最近 200 次访问，最多展示 8 个 host，每 host 最多 3 类错误；完整选中行的身份保留在本地收据。不把 HTTP 成功称为有效候选，不把 UNKNOWN 当 confirmed failed。成功与失败并列，避免只给负面信息。不得做永久黑名单、写回站点停用状态或修改已冻结 prepared 列表。

验收：不同错误原因分别计数、UNKNOWN 保持原义；反馈与原账可回算；旧请求/旧缓存/旧 query input 原样复读；只读汇总零浏览器/零模型派发。

## 5. 站点挖掘 Agent 优化（goal、prompt、tool）

只调整找站拟词 Agent 的输入目标说明和反馈上下文：结合可见的近期失败事实，优先寻找其他有公开业务内容的来源或换检索表达；不得宣称某域永久不可用，不得返回 URL、站点资格判断或消费者任务。继续使用现有 `PLAN_SCHEMA`，不让 Agent 写候选状态或改原账。

输入版本、prompt、payload、模型作业身份、checkpoint 和结果收据一起接入。失败摘要是辅助上下文，不是新的发布门禁。页面用途模型的 prompt/tool/schema、V13 `assess()` 和部分原回包逐页校验均不改。

验收：真实 GLM 请求里实际出现新摘要与指令，输出符合原查询词 schema，宿主正常解析、留存和恢复；不能用夹具输出冒充模型验收，不能把一次查询词变化宣称为稳定吞吐提升。
