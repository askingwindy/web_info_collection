# 消费者持续消费拦截点与改造记录

## 用户决定与本轮范围

2026-11-09：用户同意取消消费者旧限制，要求启动批量消费后持续工作；指定站点和消费者数量，只有主动停止或显式目标达到才结束。探索结果先保存在本文，后续继续讨论。客户输出改为 `delivery/yyyyMMddHHmm/需求交付的格式`，时间使用 Asia/Shanghai，分钟目录下直接放标准客户包结构，不再嵌套“时间戳-样本编号”的完整包。目录名按启动时间固定，连续追加该次启动的样本。

本轮只修改代码和文档，不启动消费者、生产者、模型、QC，不运行集成测试或回归。所有原账、原候选、原请求、失败、费用和原始证据保留。去掉工程配额不把失败或待审改成审核通过；同一 UNKNOWN 请求不重发，其他独立候选不受其阻塞。

## 探索时的实际问题

- 原 8 消费者曾在首次模型请求前等待：同账户同模型的旧 `reserved` 被当作占用，查询不看作业状态和租约；等待只续当前作业心跳。
- 后续只读时，原 4 个请求已为 `unknown`，另有 2 个 `reserved` 对应 `review_required` 作业。数量是当时快照，不作为后续运行状态。
- 发现过 URL 与空目标碰撞 `TASKED_URL_DUPLICATE`、计划档位拒绝 `PLAN_DIFFERS_FROM_HOST_LOCKED_BAND`、跳转缺少真实触发动作、模型结构解析失败。
- 旧导出进程曾出现 SQLite 连接未关闭问题。它是运行故障，不是模型配额。

## 拦截点清单

| 层级 | 现有条件 | 原影响 | 改造方向 |
| --- | --- | --- | --- |
| 模型并发 | 同账户同模型任何 reserved | 阻塞其他独立消费者 | 删除跨请求占位门禁 |
| 模型节流 | 全账至少 1 秒 | 限制并发派发 | 消费者删除固定间隔 |
| 授权/账户 | 历史 401/403 全账挂起、账户健康挂起 | 旧失败影响新候选 | 原请求记账；取消跨候选挂起 |
| 模型次数 | 每会话 25 次及 dispatch_max_requests | 强制终止 | 删除消费者派发次数上限 |
| 会话时长 | soft 720 / hard 900 秒 | 停模型、停动作、取消会话 | 删除总时限 |
| 动作数 | 普通 8 / 长流程 12 | 规划、派发和保存一起截断 | 新执行协议不设步数上限，按实际完成结束 |
| 计划档位 | 固定 five/long、剩余步数 | 拒绝改路 | 档位仅描述，取消配额校验 |
| 重规划 | 绑定失败 3 轮、资格无进展 3 轮、选项纠正 1 次 | 强制收尾 | 删除次数门禁，按当前证据继续规划 |
| 看图 | 同帧情境一次，旧分支无进展 2 次 | 拒绝或停止 | 不以重复次数截停 |
| 模型纠错 | 格式最多 2 次、超时追加 3 次 | 请求结束 | 明确计量的格式错误持续纠错；实际超时保留 UNKNOWN 后换独立候选，不循环重发原请求 |
| 调度 | 拥塞最多 120 秒、同 job 最多领取 1 次 | 消费者退出 | 连续等待可执行工作，不设次数上限 |
| 同域节流 | 导航 3 秒、任务 1 秒 | 限制同站吞吐 | 取消消费者固定节流 |
| 请求载荷 | 24 图、16384 输出 token、schema 字段长度 | 单请求容量限制 | 与批量配额区分；沿模型能力组装请求，不让单请求失败结束整个消费者 |
| I/O / 租约 | 请求和页面超时、claim/attempt 续租 | 单条中断 | 保留可取消的 I/O 和独占所有权；失败记原条，批量循环继续 |
| 候选 | pending / disposition / 原页排除 | 跳过不可消费项 | 原生产者契约保持；库存空则等待 |
| 重复任务 | URL + requested_goal（可能为空） | 规划前拦截 | 空目标不当作已规划目标；实际任务/样本去重仍据证据 |
| 原账冲突 | 同候选原请求/attempt 未决 | 原条不可继续 | 保留原条待对账，继续不同候选 |
| 执行故障 | 程序/计量异常暂停 scope | 可传播退出 | 保存原失败并继续外层消费 |
| 消费循环 | EMPTY、BudgetStop、导出/回写抛错 | worker 结束 | 等待库存、隔离单条错误、持续领取 |
| 协调器 | worker 只启动一次 | 并发数逐渐下降 | 用户停止前维持指定消费者数量 |
| 导出锁 | 持全局锁重建完整客户包 | 领取及其他输出等待 | 重用已保存客户样本，短锁发布目录与索引 |
| 旧累计容量 | 默认每应用 500 | 后续容量检查失败 | 去掉站点数量配额，20 万只是目标 |

作业/Runtime 并发已由启动的消费者数量控制，旧配置的 3 不再是本轮有效上限。累计费用、token、页数和工时只记账。旧 ReAct 的 10 轮等预算、旧页面 64 个、旧站点失败 3 次属于历史路径，不应重新带回消费者。源码保留历史收据字段时只用于识别原证据，不用于新消费配额。

## 工程与 Agent 同步改造

- 工程：移除消费者跨账户占位和配额；消费循环持续运行；逐条输出；保留 SQLite 原子独占、请求唯一身份、真实结果和保存收据。
- Agent：不再提示固定五步、八步、十二步；任务自然完成就结束，1–4 个有效业务动作为 short_flow；同站仅复用结构、控件语义和动作能力，不能复用完整动作链。滚动后点击依当前观察重新绑定，必要时重规划剩余路径。
- 取消步数上限必须同步 prompt、schema、宿主校验、收尾标记和客户 annotation 的解析，避免执行放行而保存拒绝。
- 输出：一个启动分钟目录直接包含 README、metadata.csv、site-list.json、samples、ground_truth 等合同要求内容；每条完整保存后增量发布对应样本并更新索引。运行日志、费用、错误及内部收据保存在原执行/运行目录中，全部位于客户包之外。
- 手动停止与显式 target 保留。供应商错误、磁盘故障、无库存均报告真实状态，不能写假成功。

## 实施与验证状态

已完成代码修改，尚未运行集成、回归、真实模型、采集或 QC。实际效果待下一轮实采观察，不把代码修改写成吞吐或产量证明。

- 新消费者使用 `webcollect-continuous-attempt-ending-4`，动作上限为 null，prompt、首轮/分支 schema、执行、原始终态及客户 annotation 同步接通；旧 V2/V3 收据仍可解析，历史原件不改。
- 删除当前消费者的跨请求账户占位、历史账户挂起、25 次调用、总时限、固定节流、档位配额、重复绑定/看图/重规划次数停止。只核对原候选/请求自身未决，其他独立候选继续。
- `candidate_consumer run` 不再默认只取 1 条；空库存持续等待，异常写原运行日志后继续。协调器维持指定站点的消费者数量，重启进程使用新 worker/request 前缀，只领取独立 pending。
- 标准导出完成后立即进入持久队列，总控逐条追加 `delivery/yyyyMMddHHmm/`。新 PNG/树只复制本条；元数据、站点表、说明和 SHA 清单随条更新。发布锁独立于领取锁。
- 显式 target 是停止新消费的触发条件，不丢弃已经并发保存的样本。达到目标立即关派发并停止消费者，然后处理已保存的导出队列；实际导出可能多于 target，须如实报告。导出失败仍留原队列和错误，不阻止其他可导出项，不重跑浏览器。`publish_pending(campaign_path, pool)` 可只恢复原队列导出。
- 累计集合和容量默认取消单站 500；20 万不是硬上限。原 manifest 的旧策略标签保留为 source_policy。
- QC 解析接受 V4；终态语义规则版本为 `truthful-fragment-continuous-ending-7`。没有启动任何 QC，也没有重签旧审核。
