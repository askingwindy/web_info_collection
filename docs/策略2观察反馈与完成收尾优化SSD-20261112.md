### A. 以哪一个结果判定完成

当前首要目标是下列完整链条通过，而不是某个函数返回成功：

`Table2 独占领取 → 首屏目标与路线 → 真实动作及证据登记 → 完成与末帧核验 → annotation/图片派生 → RuntimeStore 正式提交 → 候选结果回写 → 既有 delivery 导出`

| 检查点 | 必须能查到的事实 | 不能替代它的结果 |
| --- | --- | --- |
| 执行合格 | 原目标逐项核验，实际有效动作≥5，当前末帧满足既定展示要求 | 首轮计划≥5、模型说 complete、进程退出0 |
| 文件生成 | 完整 `annotation.json`、逐步图片和 `saved_sample.json`，引用与哈希有效 | 叙述函数非空、单独 `derived_saved` |
| 正式落盘 | RuntimeStore attempt 为 `collected_pending_review`；`verified_saved` 能按正常规则读回同一样本 | 手写成功收据、仅在隔离回放目录生成文件 |
| 消费结果 | 正常 `finish_or_reconcile` 写回 claim 与 candidate result，sample ID、路径、哈希一致 | 只在报告中记录“完成” |
| 客户目录 | 通过既有导出入口生成包和收据，逐项复核没有漏输出；仍如实标待审 | 计划中的 delivery 路径、把导出称为审核通过 |

本次只读复核没有发现可以确认的 SQLite 正常提交或候选结果回写新缺陷，不预先重写这些模块。应把它们接入验证，而不是再造保存接口。

## 1 目标与范围

目标是让策略2在关键结果实际出现时及时观察、登记和反馈；滚动后继续使用有效证据；原目标完成后停在能展示结果的真实末态；输出的每步叙述及 complete 各自对应真实事实。

核心选择：**默认提供带来源的累计上下文；关键证据尚未给模型看过或存在歧义时，补对应历史关键帧，同时保留当前帧。** 不机械补每一次滚动前的图，也不把未经验证的文字摘要当成模型已经看过图片。先修及时反馈，再补遗漏证据，避免依靠最后一次请求挽救整段轨迹。

范围为 `screenshot_plan` 的 Agent 协议、宿主执行、证据回放及首次标注生成。复用现有观察记录、证据路线、进度事件和研究重跑接口，不增加数据库、记忆服务、实现代际或兼容分支。策略1业务行为保持原约定。

普通首轮仍须有至少五个自然必要业务动作的完整规划；实际保存仍须原目标成功、真实有效动作不少于五步及正式保存收据。取消“尽量超过五步”的长度偏好，不为长度、动作种类或用满预算补动作；无累计八步、十步或十二步上限。首轮路线完整，不代表可以预知后续页面内容或闭眼执行整段计划。

### 2.2 与滚动有关的原实施前代码缺口（历史）

### 2.3 标注不是单纯措辞问题

旧样本中，计算结果叙述漏袋数；滚动的预期声称展开；展开公式的结果写成无关表格；上滚依据声称当前不可见的字段实际已经可见；complete.user_goal 拼接整体 final_result，complete.rationale 与 completion_judgement 相同，并泄漏内部字段。原截图与 raw 对应，不能用“导出错图”解释。

这些是旧样本事实，不表示当前代码所有修复都无效。本轮必须核对当前首次生成链，不重做已经正确的实现，也不修改旧样本来制造通过。

## 3 设计决策

### 3.1 全局目标与取证路线保留，执行在不确定处反馈

首轮列清输入条件、需要读到的结果或正文，以及必要的独立推导。已知输入编辑可连续执行；涉及滚动后未知控件、展开后新正文或导航后新页面时，安排观察点，再按真实新帧绑定后续动作。未来目标使用语义描述，不预填编号、坐标、公式或答案。

优先修改现有 prompt 与路线接线，不另造双层规划框架。保留首轮五个必要业务动作准入，revise 仅修剩余路线、不再要求补满五步；自然不足的任务如实报告资格，不虚构动作。计划中的取证步号表示“该步执行后的观察”，完成不是执行完所有预排动作。

`evidence_route.observation_steps` 接入实际检查点调度。步骤规范化、执行游标和 revise 必须使用可追溯映射，避免把计划局部步号当作轨迹全局步号。revise 更新未完成事项的取证位置及结束展示位置，保留原始计划和已经执行的证据，不改冻结目标；优先复用现有 plan/decision 事件记录映射。

### 3.2 关键观察当场反馈并登记

在下一动作可能遮蔽或离开证据前，满足下列任一条件即进入检查点：

1. 到达当前生效路线声明的结果、正文或推导来源取证步。
2. 提交产生目标相关新结果，或出现需要重新观察的异常、弹窗、导航。
3. 滚动、展开等使待取证区域进入视口，或后续动作依赖尚未在新帧确认的控件／内容。

同一步命中多个条件只发一次请求。稳定且已绑定的输入操作不逐键询问；不能仅以“发生 scroll”无条件增加调用，也不能只凭全页文字变化识别业务进展。取证点已到但内容未出现时，如实反馈未找到，不能预填完成。

检查点先展示已有可信进度和当前待核验事项。模型已看到且能支持目标的结果／正文，应在本次 decision 中提交对应 answers，随后再选择 continue、revise 或 complete。宿主按现有来源和因果规则验证并增量合并；拒绝项返回具体缺口，不清空其他已验证项。已完整达成原目标时直接进入完成核验，不再为了执行旧尾部而滚动。

### 3.3 上下文是常规路径，历史关键图是有条件的补证

| 情况 | 提供给模型的内容 | 理由 |
| --- | --- | --- |
| 已看图且已验证 | 当前帧＋有效证据的精确引用、值与状态 | 避免重复传图和返回页面补证 |
| 已看图但尚未登记 | 当前帧＋该观察的精确候选、缺失事项；有歧义时补原图 | 提醒登记，不把“看过”冒充“已验证” |
| 已可信捕获、模型未看过 | 当前帧＋相关历史关键帧及其来源 | 文本摘要不能补足未发生的视觉观察 |
| 结果已失效 | 当前帧＋失效原因与受影响事项 | 旧图不能证明编辑或新提交后的结果 |

累计条目复用现有事实结构，至少能够追溯 requirement、observation、document、control／region、逐字 quote／显示值、关联动作或提交、是否实际给模型看过、验证结果及失效原因。补齐所缺来源字段，不强制把这些全建成新数据模型。候选事实与 verified 事实分开，host input proof 与模型视觉证据分开。

历史图选择依据是“哪个事项缺哪个证据”，不是固定选择最近一张或滚动前一张。默认优先当前清晰帧，图片额度允许时补最相关的一张历史关键帧；不发送整段历史、不拼长图绕过限制。复用模型现有 `max_images`，多张历史证据可分次补入；若连当前帧与一张必要历史图都无法同时容纳，则明确报告补图能力限制，不隐式提高上限或声称已经补证。及时观察与已验证上下文仍可正常使用。

历史图沿用原 observation、原 PNG／裁切、哈希和 source rect；`_images`、`visual_evidence`、可引用 observation 枚举、`provided_observations` 和封存回放同步接通。只有请求正常返回后才按既有规则登记“已提供”，UNKNOWN 不据此伪造已看图。补图不操作浏览器，不增加业务步数。

**当前动作只能绑定当前观察。** 历史图上的控件编号和坐标只能用于证据引用，不能直接 click/type；需要操作时必须从当前帧重新获取。不得通过放开所有 observation 校验来实现补图。

### 3.4 证据保留与失效

滚动、焦点变化、控件移出视口不自动撤销已经成立的业务证据。相关输入改变、结果被新提交替代、原引用失去因果依据时，只失效受影响事项。新提交不能无条件复用上一次的数值。

阅读任务按冻结问题累计不同位置的正文，离开某段不等于没读过；跨页来源必须明确。当前可操作控件与历史阅读事实各自维护。已有宿主输入证明继续从可信捕获确定性复算，不扩展成“任意 DOM 文本均可替代模型观察”。

### 3.5 明确“页面计算结果”与“独立验算”

“调用页面计算器得到并确认结果”使用 `page_result`；原目标明确要求独立公式复算、换算过程或交叉验证时，使用 `derived_check` 并保留来源及 calculations 校验。不能因为阅读正文出现“数量”，或简单确认结果出现“核对”，就默认附加全部结果的独立算术。

prompt、requirements、路线检查、`_requires_arithmetic`、`verify_completion` 的 coverage 兜底和封存回放必须使用一致义务。不能仅删掉兜底关键词而允许模型漏掉原目标确实要求的推导，也不能只把全部结果设为 derived_check 来规避语义判断。固定目标的义务在规划接受时确定，后续只能改取证方法，不能在失败后降标。

Muxtly 历史目标原文含“并核对结果”，本次新执行按讨论口径理解为确认页面输出与目标输入对应，不自动追加独立手算；原目标文件原样保留。若既有冻结执行契约已经明确列出独立推导义务，必须履行，不能迁移或改写历史契约。旧样本、旧核验结论保持原含义。

### 3.6 及时结束与真实末帧

完成分别检查：累计原目标证据、当前结束展示、真实有效步与保存资格。模型提出 complete 后沿用现有 fresh capture，再复核累计证据与当前结果；不把先前截图替换成末帧，不以旧截图时间充当完成时间。

计算任务末帧保留主要数值结果；历史输入与公式不要求同时挤在末帧。阅读任务末帧显示支持当前结论的相关正文，其他已核验材料可以来自历史。只有结束展示缺失时才做必要的定位，不能重新核验所有输入或重走整个流程。

目标已经完成但实际不足五步时按现有 short_flow／不交付规则记录，不再为资格补动作。实现不承诺每个任务固定十二步内结束；衡量的是有没有无目标用途的后续动作。

### 3.7 首次标注生成与执行事实一致

按“实际动作＋动作前画面＋可信动作后变化＋已核验证据”生成，避免模板无条件覆盖已经有依据的目的与预期。逐字引文必须确实在对应观察可见，不把未来预期写成当前事实。

| 字段／动作 | 应表达的含义 |
| --- | --- |
| 普通步 user_goal／预期 | 此步对原目标的具体用途、预期效果；不复制整个任务结论 |
| rationale | 动作前的真实状态为何支持这个动作，或明确的计划前提 |
| observed_result | 实际动作后发生的变化，计算包含目标所需各项输出，展开引用新展开内容 |
| scroll | 视口移动及新进入视口的相关内容，不声称“点击／展开” |
| complete.user_goal | 简短表达结束此次任务，如“确认结果并结束任务” |
| complete.rationale | 当前结果可核验、剩余事项已完成，为什么现在可以停止 |
| complete 的预期／结果 | 结束且保留当前结果画面；complete 不虚构网页状态变化 |
| final_result | 对用户原目标的明确答案，并说明结束画面实际展示的结果 |
| completion_judgement | 原目标为何达成，必要时分列当前与历史证据及其用途 |

字段可共享必要事实，但不能整段机械复制；验收语义职责，不要求字符串强制不同。用户文本不出现 requirement ID、`calculations数组`、内部 enum 等实现词。机器证据继续保留准确标识。只修新样本的首次生成链，本轮不批量订正旧交付。

## 5 原实施轮验证与验收（历史）

### 5.1 最小核心行为

优先调整已有 `test_strategy2_completion_core.py`、`test_strategy2_visual_core.py`、`test_strategy2_save_core.py` 及相关核心用例；以下是验收行为，不是要求新增等量测试。测试保持短小，不把大批独立场景塞成一条来绕过五十条上限。

- 滚动后还有普通点击／输入时，已声明的关键取证帧会在后续动作前进入检查点；重复触发只调用一次。
- 当次结果被提交并验证后，下一分支的 confirmed／missing 与之同步；仅有捕获不等于模型已看见或事项完成。
- 原图未提供时可以按需补图，可信历史引用可验证；历史控件仍不能用于当前派发；图片上限保留。
- revise 后取证步号正确，滚动不撤销有效证据；相关输入变化或新提交使旧结果按范围失效。
- 页面结果确认与显式独立推导分别执行相应义务；内容中的数量不误触发算术；线上与封存复算一致。
- 累计目标完成但末帧缺结果时不能保存成功；结果清晰、目标已满足时不再执行无用尾部；complete 及逐步标注各司其职。

离线集成贯通“计划→关键观察→登记→一次视口变化→累计上下文／必要补图→complete fresh capture→封存回放→新 annotation→保存收据”。使用隔离输出及现有正常入口；夹具通过只说明工程链可运行，不宣称真实模型通过。

### 5.2 双站真实验证范围

本节授权已经结束，保留以解释历史尝试；不是本次或下一次启动指令。后续安排见文首当前收口计划 D。

交给下一 Agent 的授权为：**Muxtly 最多五次、Wiki 最多五次新尝试，分别计数，合计最多十次。** 沿用前轮“最多五次调试尝试”含义，各站达到完整验收条件即可停止，不要求把额度耗尽；不是每站五条成功，也不是一次调用可隐藏五次重跑。失败修复后的新启动也占该站一次，不互相借额度。

每站先固定一个已发布有效 Table2 候选和一个目标，不因失败换容易目标。Muxtly 用原混凝土基线，Wiki 优先用现有搜索入口完成“搜索月食→回答具体问题”的固定阅读目标，详见执行 Prompt。旧 Wiki 月食尝试缺少可直接复用的冻结 session objective，不给旧 claim 事后补写目标。

真实执行使用策略2、既有 GLM 配置和 first-plan／branch `high/high`。先用已有 API 完成路径与目标绑定检查，再启动；不得复制旧一次性启动标记或硬编码过期 original_claim_id。UNKNOWN 保留原账，仅按已有精确授权机制创建独立新尝试，不能复发原请求、换账绕过或解除整站隔离。不能合法继续时停该站，报告剩余额度；另一站独立推进。

每次启动前登记站点、序号、候选、目标哈希、源码摘要、配置引用及新 request 身份。启动后即使零业务动作也计本轮一次启动尝试，同时另报正式 attempt／模型请求数。未启动的只读检查不计次数。一次原会话内部原有的有界协议纠错独立记模型请求，不另偷开会话。

单个站点验收包括：

1. 固定原目标全部有可信证据；有效动作和保存资格真实成立。
2. 关键证据出现后及时进入模型上下文并登记；无为重取已验证事项而出现的冗余往返。
3. 真实末帧可展示结论；最终 annotation 的步骤、图像、输入输出、complete 和最终说明一致。
4. 原始 raw、封存复核及实际保存收据相互绑定。research 保存单列，不能冒充新增生产有效条数。

每站逐次记录有效动作数、首次关键结果 observation、首次模型接收与登记位置、其后动作及原因、revise／模型请求数、图片数、UNKNOWN、结束原因、正式保存状态和标注核对结果。不把零退出码、单次 complete 或一个 AI PASS 当作完成。真实观察未覆盖的补图／失效分支只能报告离线覆盖。
