## 实际入口

- `webcollect.task_generation generate --generator workflow-model`：与原generate相同的config、ledger、catalog、history-registry、history-set、output参数。新增分支调用既有ModelGateway，以原PNG、完整能力库存、状态树及锚点引用提出通用工作流；继续用 `workflow_proposal.compile_workflow` 编译。没有新增采集期模型请求。
- 来源新快照的 `capture_controls` 保存控件ID和实际selector绑定。通用模型规划必须有这些证据；旧来源缺字段时拒绝，不会未经授权访问页面补齐。显式旧工作流保持原绑定校验。
- generate输出增加 `queue_job_id`。`frozen-plan` 作业保存plan路径、SHA、历史范围和mode。草稿在生成索引中，冻结后才入队；原生产RuntimeStore继续保存派发、失败、待审、逐条审核、发布状态。队列done表示一次派发编排结束，不表示样本合格。
- `python -m webcollect.plan_queue --help`：显式派发一个冻结计划，参数为config、ledger、job-id、catalog、output、registry、policy，可指定site-pool。调用原execute入口，沿用manifest、生产账、编号、整站hold及预算。它是**真实执行入口，本轮没有运行**。已派发、已完成或需复核的项不再次派发；租约过期保留待复核。
- `python -m webcollect.batch_qc --dataset ... --history-set ... --output ... --policy ...`：只消费已保存的多样本候选包，先验证原尝试/保存收据，运行全量机械与累计四路判重，再冻结抽检。不会运行模型worker。机械失败保留报告和分母，停止冻结。
- `webcollect.batch_qc.queue_reviews(ledger, batch_receipt, output, ...)`：调用原delivery_pipeline.prepare，为入选样本和整批资料准备作业；不发请求。资料模式默认ai，也可显式human。后继run/status/finalize仍用原delivery_pipeline，各门禁保持。

## 稳定性规则细节

原PNG不编辑、不裁切、不覆盖。旧v1收据按原v1复算，新收据记录v2和是否启用边框规则。首次capture候选禁用边框容差，失败重取证后才可能启用；动作前遇到变化只刷新未执行候选，正式帧写入之后的最后一次重验失败仍停止，不能动作后补图。

新边框范围必须是完整观察证明的非任务、非焦点、非勾选、非禁用普通控件的整数坐标1 CSS像素实线边框，不能与文本、目标/断言/保护区域或未知重叠绘制相交。颜色差上限采用通道范围1/16、通道差近似中性，变化面积不超过已证明边框周长1/64；这是局部实验规则，不是从历史1或9像素推导的通用数量阈值。完整语义状态相同才会进入该像素检查。任何内侧字符/数值像素、目标移动、控件状态、焦点、遮挡、结果变化均不因面积小获豁免。未能证明安全的页面继续拒绝。

该规则需要后继真实正反例继续检验；不能据离线正例宣布网页绘制问题普遍解决。
