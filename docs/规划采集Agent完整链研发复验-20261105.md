# 规划采集 Agent 完整链研发复验

2026-11-05，用户明确授权只处理维基「月食」和 Muxtly 12.5×8.5 英尺两个原候选、原版本和原目标，完成工程修复、真实执行与同样本独立 QC。生产者和八页扩量不在本轮。原账 UNKNOWN 仅核账，所有新证据另存。

## 工程与 Agent 协议

- 首轮和剩余路线复用同一规划 schema。focused 明确填写可见标签；仅已唯一绑定的可见节点可派生缺失语义，原回包保留。反馈报告具体字段路径，禁止额外 plan.stop。
- 点击后同文档原搜索节点消失且唯一同语义输入真实聚焦时，记录前后身份与观察，后继步骤重新取证绑定新节点。派发前替换不享有此转换。
- 新显式 `webcollect-search-submit-link-stability-3` 保留 V1/V2 原义。首击与输入仍产生 V2 证明；Enter 提交保护唯一真实焦点与全部输入值，链接保护实际 href、原节点、几何和目标原图像素；正文滚动仅在已证站内检索打开正文后，保护唯一 main 子树、全部值、几何及可见区域像素。完整 PNG/DOM 不裁切、不覆写。
- 原动作前捕获与最终派发校验使用相同证明。零派发且原目标完全未变时，只在总时限内有限重取；已派发未知不重发。
- 保存时对相邻原图/树重算下一动作的局部证明，作为显式连续性依据。新 V3 内容身份可用原同文档唯一 main 的完整一致性佐证，避免把框外公告当成页面身份。
- 搜索提交直接进入正文时，核查真实输入、同表单按钮或唯一焦点 Enter、同站新文档、唯一主题标题和正文；不猜地址与答案。首屏引文保留，但目标原文明确要求“往下阅读”时必须再有真实向下滚动和可见新正文；要求绑定原目标文件及匹配原文，普通未要求滚动的阅读目标不加此义务。目标达成与六步门槛分开。
- Muxtly R12 暴露冻结路径在第七步出现计算按钮后仍自动执行第八步滚动：新增通用分支，当计算目标仍缺结果、刚滚动露出此前未见按钮且剩余计划仍是滚动，把当前控件和余量交模型选择；宿主不指定按钮或数值。计算提示明确为实际提交预留原八步额度。已证输入滚动后仅标签被遮挡时，可继续用同文档、原节点及选择器和值核验，仍要求本次新具名结果。

## 同候选研发复验

`CandidatePool.claim_research` 使用原工程短事务与候选独占约束，冻结原版本、原目标文件、原成功 claim 和授权引用。旧 effective=1 结果与旧 claim 不变；新研发结果 effective=0，消费者统计单列研发尝试和保存，不增加生产产量。失败、租约过期、UNKNOWN 及后续 QC 均按新 claim 原账处理。普通 retry 对保存待审候选的拒绝保持。

历史过期 reconcile 只有在同工程原账证明零正式 attempt、零模型请求、已完成页面访问、未派发 frozen-plan，且早于原成功执行时，才能作为保留原状态的已知历史阻断处理；真实未知仍拒绝。旧 QC UNKNOWN 不转换，不重发。

研发入口携带的原目标和授权是任务输入，验证文件哈希、候选与版本后不将其误当作新观察；其他引用继续受当前工程证据根目录约束。同目标研发与原样本的精确图片冲突完整记录，只有冻结 claim、原池 `research_claimed` 事件、同注册库和原有效样本全部绑定时，允许该原样本的重复图片作为研发证据保存。生产路径、第三样本冲突仍拒绝；原图片索引保留，新研发图片也入索引。此例外不授予生产去重合格、发布或客户验收。

`current_chain_results` 保留研发保存底表行，默认生产历史投影经原池身份核验后单列 `research_results_refs/research_samples`，不计入 `customer_samples`。独立 QC 仍绑定显式新样本，并保留与原有效样本的适用比较；历史投影修复不能改变已执行冻结版的原始记录。

宿主休眠导致的取消与实际动作未知分开审计：`cancelled_dispatch_audit` 核对封存全集、每个派发意图、原子动作、前后观察及最终计数；原 UNKNOWN 终态仍不允许交付。只有原浏览器/进程已关闭、原模型请求均结算、原租约已过期且原 claim/任务/样本/注册库逐项一致，`reconcile_sealed_rejection` 才追加取消审计并结算宿主失败。审计不拼接轨迹，不重发请求，不修改原失败或 raw。零正式 attempt 的确定研发入口失败通过 `settle_unstarted_research` 单独结算，保留原有效结果。

## 动作后观察与研发内容审核后继

V4 在原操作绑定下证明动作后的实际搜索焦点/值，或同站已渲染主正文；它只授予观察可信度，不授予重派动作权限。原完整 PNG/DOM 均保留，输入值、业务正文、相关几何与保护区像素仍严格一致。持续框外漂移本地全入口见 `post-drift-r01`：聚焦、输入、提交、条目打开、两次向下阅读、终态共六个有效动作，保存/导出/交接通过。

`rejected_focus_dispatch_audit` 只核对一个实际已执行的搜索聚焦动作，要求原封存全量、单一意图/原子动作/失败以及同源唯一焦点的完整 PNG/DOM pair。诊断图不转换为原捕获 PASS 或交付帧。已关闭 rejected attempt 仅追加审计引用和事件，原状态、失败类型、root cause、完成时间全部保留；只有严格原账绑定及全部模型已结算后，后继 retry 才能区分该已知首击与实际未决动作。

独立 QC 的 `research_handoff` 显式参数重验原保存、Runtime、原池 research 授权和原有效样本，只允许该研发重复样本进入内容质量审核。普通 prepare 仍拒机械重复；完整历史比较、机械 FAIL 和生产不接纳均保留。研究差异请求逐对查询原账未决请求，完整有序图像向量相同即保留原 UNKNOWN、不再派发；样本编号、叙述和图像分段变化不能绕过。其余比较继续，未决 pair 不产生已看图或完整 QC PASS。

R13原失败字段保持后，`accounted_rejected_focus` 集中重验原Runtime审计事件、原封存诊断、原claim/注册库与全部已结算模型请求。站点未知事实仍留原计数和原引用，只将这一有证首击从任务阻断投影排除；候选前置guard和retry共用同一判别。没有审计事件、原请求未决、原件改变或身份不一致仍拒绝。QC handoff 的核心manifest scope逐项核验，额外历史计数与引用投影不冒充不可变身份字段。

规划采集启动前的 `agent_feedback.site_context` 同样使用集中原账判别；历史失败继续进入execution feedback，但已经严格核对的首击不再进入unresolved派发阻断。验证覆盖该实际ReAct入口，而非止于候选领取。

独立差异审核的显式 `resume_unreviewed_pairs` 仅续审同原job/payload/account中尚可派发的其他pair。原UNKNOWN请求、用途与编号、已结算pair全部保留；原pair完整有序图像向量未决则整对跳过，不能借分段重发。已有pair检查点直接复用；并发/未结束lease或reserved请求拒绝接管，重复同授权幂等。全部可审pair结束后仍有UNKNOWN时，job保持review_required，明确应审/已审/未知/未派发数，不建立完整QC PASS。

R16 的动作后新文档加载瞬态不再由 `reading_scope` 的 ValueError 提前丢弃已取得的图树：V4 返回明确不合格证明，原有八次/八秒只读观察预算不变，所有三快照/双PNG原件保留，加载齐全才可通过；没有重复原业务动作。预期条件缺少 text 时按原 kind 描述，不再把搜索/导航误写为滚动。原 R16 诊断图不是正式同步图树，原 UNKNOWN 保留。

显式同 job 差异续审的授权只给予该原 job 下一次唯一 claim 的额度，不改配置中的 max_job_attempts 或原 attempts；需要原授权文件、事件、payload 与未派发 pair 绑定。普通任务仍受原重试限制，UNKNOWN pair 守卫保持。
