此前规划有三个实质缺陷：

1. **把引用来源成立当成整个目标完成。** R02 的原目标同时包含起源、增强、纪录及具体操作，只读到形成过程就触发 finish。分支菜单缺少“继续原计划”，三个核对项仍待完成。`goal_evidence=VERIFIED` 当时不能代表目标已正确完成。[原件复盘](../verify_results/dual-baseline-astra-parent-20261105-r01/direct-r02-premature-finish-review.json)
2. **模型可见规则与宿主校验脱节。** R03、R04 都在格式纠正后，被另一个确定性校验直接终止。逐条增加事后拒绝没有建立 Agent 的自我纠错能力。R04 原提案还包含跳转后滚动，说明目标、工具约束与未来步骤之间也需要一致的反馈。
3. **没有完整执行已明确的动态内容规则。** 公告、广告、动态图片的变化本来就可接受，旧实现却先要求整页稳定，再针对主区外公告或个别浮动图片增加例外。这使同一种变化在预检、动作前后、连续性或保存时重复触发拒绝。单纯增加抓图重试不能解决持续变化，轮播文字也不能被算作新阅读或有效操作。

本轮修复因此同时处理宿主实现和模型可见协议。完整计划语义是否正确仍需要真实执行及独立 QC，不能由更严格的字段校验代替。

Vue 的后继实采进一步证实：重复失败主要来自工程接入对有效输出的处理不一致，包括明确 choice 之外的草稿字段、缺省 reading 索引、只给剩余步骤的重规划、无文字锚点、连续原文摘录及动作引用。目标已经完成后，终态派生说明还因夹带整屏代码示例而被格式检查拒绝。这些问题需要贯通解析、执行、保存三个阶段，不能靠提示模型换一种写法逐个绕过。本轮累计 85 次消费请求中有 28 次 invalid_response，代价说明前期集成覆盖不足；后续先复用已保存原回复贯通相关链路，再进行一次真实基线试跑，不为纯工程格式问题重复付费采集。

## 4. 规划采集 Agent 的 goal、prompt 与 tool

**Goal：** 首轮依据真实词条选择一个适度、具体的阅读问题，至少有一个实质阅读核对项。该会话接受后的 goal/checks 冻结，后续只调整剩余路线。未知信息写成问题，最终由实际读到的正文回答。

**Prompt：** 明确原词条的取证范围，目录和正文链接都可使用；已知离开原词条的链接后，下一业务动作必须 back。可选路径不自动变成必须动作，不规划依赖在关联页继续滚动才能完成的目标。未来控件只按已知语义规划，不猜节点编号、地址或答案。

**模型可见 Tool：** `cite` 可单独记录引用，`continue_plan` 继续原计划，`finish_reading` 明确提交完成答复；完整答复可以直接携带引用，不强制先多调用一次 `cite`。结束答复按原核对项提供答案及可绑定的来源。阅读事实引用真实正文，必要操作绑定真实操作 ID 与次序，不把目录标签当正文，也不强迫动作项再引用正文段落。

首轮、分支/replan 与原生 ReAct 均收到同一动态区域规则和紧凑目录。区域中的内容仍可读、可点击；公告轮换、广告或图片自身变化不能替代任务目标、阅读进度或点击效果。QC 同时取得原目标、核对项、真实动作、完成回答及动态区域证据目录。

**宿主边界：** 原文和动作绑定通过，最多说明证据来源与执行关系成立；答复的语义状态仍是 `MODEL_REPORTED_REQUIRES_INDEPENDENT_QC`。采集模型的自报不能充当独立审核，也不能充当人工审核。

详见[具体词条契约](具体词条直接阅读本地契约-20261105.md)及[工程说明](工程说明.md)。
