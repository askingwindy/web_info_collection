# 生产者、消费者与 QC：优化共识及下一步规划

日期：2026-11-04，上海时间。

本文汇总本次讨论，并结合生产者 V11 的新 100 页报告、消费者 R09 双基线真实结案及 QC 改造报告更新优先级。本文为分析与后续方案，不表示已修改运行代码、调整冻结验收条件或恢复生产。其他会话正在做 R09 原账分析，本文不启动重试或并行修复。

## 1. 直接结论：独立验收是不是必须的

**不需要把本轮生产者“两阶段、四角色、全量 100 页”的独立验收设为每批生产的固定前置条件。** 本轮用户明确要求独立验收业务价值和自然任务质量，因此开展这次实验有依据；四角色全量方案是工程实验设计，不是客户规定的日常成本。

应当分清三个层次：

| 层次 | 作用 | 后续安排 |
| --- | --- | --- |
| 生产者程序检查 | 核对来源、第一方实际落地、GET 2xx、去重、证据绑定、发布与领取约束 | 保留适用的全量程序检查 |
| 生产者独立语义实验 | 评估某次选页规则、模型判断或新方案的质量 | 改为变更时的定向实验和稳定阶段的适量抽样，不默认四角色全量跑 |
| 消费者交付 QC | 检查实际保存轨迹的图、树、动作、叙述、重复关系及适用交付要求 | 按生效策略保留；不能用规划模型自评或网页入池结果替代 |

“可以减少生产者实验验收”不意味着“取消轨迹交付 QC”。生产者网页验收回答供给是否有价值；消费者 QC 回答实际交付材料是否可信，二者检查对象不同。

现有已明确的 QC 方案是：程序检查 100%；稳定质量单元基础 AI 随机抽检 10%，叠加启动首批、新组和风险必审，发现问题按规则扩至 30% 或 100%。客户人工验收另行执行。该策略不能简单等价为将运行参数改成 10%；使用前仍须核对实现、冻结总体、分组、扩检、接纳及收据绑定是否完整。

R09 属于固定双基线研发验收，原约定要求同样本独立 AI 通过。不能在本轮出现 UNKNOWN 后，改成抽检或删除某项要求来宣布 2/2。

## 2. 生产者本轮成本意味着什么

来源：[V11 新 100 页完成报告](../verify_results/producer-v11-new100-20261104-r01/完成报告.md)。

| 阶段 | 真实模型请求 | 已知 token | 自然耗时 |
| --- | ---: | ---: | ---: |
| 生产 | 28 | 245,919 | 17.92 分钟 |
| 生产者独立实验验收 | 40 | 1,028,029 | 21.48 分钟 |
| token 合计 | 68 | 1,273,948 | 两阶段耗时分别报告 |

独立实验验收占总 token 约 80.70%，是生产阶段的约 4.18 倍。原账基线至计量封存为 42.54 分钟，不能只把两项阶段耗时相加充当完整端到端耗时。币种费用仍为 UNKNOWN。

成本高的直接原因是同批材料经历两份业务／任务空间盲验，再经历两份任务提示复核。独立会话能够减少直接沿用生产标签的影响，但同模型族判断仍存在相关性，也没有证明消费者真实可执行。

从客户交付目标看，四角色全量评价生产者任务提示的投入偏重。既然最新共识是生产者不再生成消费者任务提示和预编排，对这些提示继续生成和复核也就失去主要收益。后续应取消这条新增工作链，保留本轮历史提示、报告、失败和成本。

若未来不再运行这套实验，当前生产阶段实测成本仍是 245,919 token，不能直接承诺新版本也一定达到该数值；新批也不能沿用本轮独立验收比例声称自身质量已获确认。

## 3. 为什么高 token 与大量用途 UNKNOWN 可以同时出现

本轮 100 页用途中，98 页为 UNKNOWN，但没有独立用途分类请求。主要模型任务已经转为业务价值和自然活动判断，token 不等于专门用于补齐用途分类的成本。

此前原回包分析发现，辅助用途的提示和 schema 允许类型、引用分别省略，宿主却要求类型有合法引用才采信。这会出现模型给出类型倾向、最终入账仍为 UNKNOWN 的情况。用途 UNKNOWN 不能统一归因于模型完全不理解页面，也不能与请求超时 UNKNOWN 混为一谈。

本轮用途 UNKNOWN 的 98 页中，独立实验确认业务价值 93 页、自然任务质量 84 页、二者同时确认 82 页。用途分类缺失不是消费阻断的充分理由；这些结果同样不证明轨迹已经采集成功。

后续用途字段保留为辅助信息，允许 UNKNOWN，不为补齐分类重复开页或额外调用模型。若保留类型与引用，应在同次响应内明确它们的配对关系，并区分未填写、缺引用、引用无效和确实不可判定；不增加单独分类流程。

R09 原冻结验收结果为 0/2；正式保存待审 1，终审合格 0，发布 0，客户验收无通过证据。不能继续描述为“没有保存任何真实样本”，也不能把保存 1 条描述为完整验收通过。

两条失败分别位于执行前取证和保存后 QC，不足以归因于生产者没有提供更多任务规划：

- 维基首个动作零派发，取证阶段用完约 45 秒预算。后续分析会话初步定位：搜索框身份、位置和命中点未变，变化发生在其下方公告区；局部稳定预检与派发前更大范围的状态复查口径没有贯通。此为进行中的诊断，最终修复须以原件与定向验证为准。
- Muxtly 已完成 8 个有效动作，达到同目标可见结果，并有正式保存收据。视觉作业完成，语言、隐私、终态语义及视觉对齐已有 PASS，但实质差异检查未完成。最后一笔请求 UNKNOWN，随后出现作业租约失效，完整样本仍为 PENDING。
- QC 运行器异常分支曾丢失作业归属，使原完成报告显示零用量。后续报告按原队列补充归属；这证明错误报告也需要修复，不能把账务归因失败误当作没有发生模型调用。

| R09 阶段 | HTTP 请求 | 已知 token | 未知用量 | 已记录耗时 |
| --- | ---: | ---: | ---: | --- |
| 消费者规划 | 4 | 29,155 | 0 笔 | 请求耗时合计 64.431 秒 |
| 独立轨迹 QC | 4 | 108,457 | 1 笔 UNKNOWN | 本样本请求区间约 2,444.41 秒 |

QC 已知 token 已是规划已知 token 的约 3.72 倍，另有一笔未知用量。UNKNOWN 请求耗时约 2,188.04 秒。两阶段已知 token 合计 137,612，是已知部分，不是完整总成本；合格样本分母为 0，不能计算每条合格成本。

后续诊断初步指出，冻结 QC 调用只有 socket 超时，缺乏 HTTP 墙钟总时限，阻塞期间不续租。应核对并修复超时、租约和结算路径，而不是靠放宽质量判定解决等待问题。不能把一次 UNKNOWN 当作质量 FAIL，也不能当作 PASS。

QC 前一轮 178 项离线检查通过，证明其覆盖的契约与封包反例得到验证；没有覆盖并证明此次真实 HTTP、长阻塞、租约及报告异常链路。离线 PASS 与真实运行失败并不矛盾，需要补足与实际故障对应的用例。

## 5. 统一职责：生产者供给页面，消费者规划和执行

### 生产者

生产者负责发现并维护 Table1 站点、Table2 网页候选，证明来源、访问结果及基本业务价值，去重并排除明确无需消费的入口。用途仅为辅助信息。

生产者不再新增消费者完整推理、任务提示、预编排步骤或预期业务答案的生成与审核工作。既有历史字段和旧协议按原版本保留；后续精简不能破坏 candidate ID／版本、独占领取及结果回写。

首帧图片覆盖率达到既定 95% 阈值时，沿用无需消费规则；不另建“地图、图表、图片工具”整类排除逻辑。无法可靠测得时保留未知，不能假装命中阈值。

### 消费者

消费者从原 Table2 已发布有效候选进入，在实际页面上自主形成和修订工作目标。固定基线仍使用原冻结目标，不因新规则热改。

模型负责选择行动和处理观察冲突；宿主负责页面／控件身份、动作派发、同帧取证、预算、保存和原账。失败反馈应短而具体，提供当前观察、已完成动作、剩余额度及可恢复原因，避免重复传整段历史或重复打开同一页面。

### QC

QC 面向实际保存片段及其客户描述，独立判断事实是否一致，不评价生产者推理是否写得完整。程序检查、AI 实际审核、批次接纳、发布和客户验收分列。有效证据与对应语义规则未变时复用原审核，不因路径、封包或无关配置变化自动重做全部 AI 审核。

## 6. 交付片段与任务描述怎样对齐

本次讨论选择“至少 6 个有效操作”作为后续普通片段保存方案的实施目标。它不自动改写历史合同中的 5 步口径，也不改变 R09 已冻结的原目标验收条件。

达到步数只是条件之一。若已有至少 6 个连续、真实、有效的操作，并有完整动作、原图、同步树和可信边界证据，后续失败不应自动抹掉该片段的交付价值。

后处理可以生成新的派生 JSON 和自然任务描述，使描述严格对应所选连续区间：

| 实际证据 | 可以表达 | 不能表达 |
| --- | --- | --- |
| 只完成输入与设置，未看到计算结果 | 设置参数、填写表单或调整选项等实际完成内容 | 已计算并读取结果 |
| 计算结果已在历史末帧出现，随后复制失败 | 完成计算并查看有据结果 | 已复制或导出结果 |
| 已打开正文并完成有据阅读，随后额外动作失败 | 对应正文范围内的阅读活动 | 未出现的结论、未访问的内容 |

不能只改描述就绕过其他字段、动作有效性和 QC。保留原 requested_goal、原计划和原执行；派生描述不追改历史意图，不伪造模型当时推理。客户 JSON 遵守原 schema；来源执行 ID、操作区间和边界引用可放在已有宿主收据或派生来源清单中。

对于“前 8 步有效、第 9 步失败或 UNKNOWN”：若第 8 步后的历史边界已独立封存并可验证，可按该边界评估前缀；不能要求它必须等于第 9 步之后的当前页面。若未知影响使前缀边界也无法证明，则只封存原件待核。第 9 步和原 attempt 的 UNKNOWN 均保留，不能重发来洗掉状态。

不强制恰好第 6 步停止，不机械地每 6 步切一条，不拼接不同中断执行，不把 wait、complete 或纯取证记作有效业务动作。单一已有片段保存仍不自动等于终审通过或可发布。

## 7. 工程与 Agent 优化方案

| 优先级／方向 | 工程实现 | Agent 协议与行为 | 验收口径 |
| --- | --- | --- | --- |
| P0：执行前误阻断 | 贯通局部稳定证明与派发前复查；保留目标身份、遮挡、命中及派发一次约束 | 只在确需决策时接收具体反馈，不因无关公告变化重做计划 | 原维基失败对应的动态页面反例贯穿实际派发入口；目标真实变化仍拒绝 |
| P0：QC 超时与原账 | 建立真实墙钟期限；协调请求期限、租约和心跳；保留原异常及 job／request 归属 | 审核模型不承担租约恢复和异常结算 | 慢响应、持续读入、租约临界、未知请求均有定向用例；不重发 UNKNOWN |
| P0：保存可交付前缀 | 按连续源区间和历史边界生成派生样本，原执行与尾部失败保留 | 任务描述只覆盖已证动作和结果；可恢复则在原 attempt 内修订剩余动作 | 覆盖 8 步有效后尾部未派发失败、已派发失败和 UNKNOWN；缺前缀证据必须拒绝 |
| P1：消费者上下文 | 复用当前会话／页面，压缩观察和历史摘要；保存完整原件 | 首轮明确目标和工具，有限重规划，不重复前缀、不为凑步行动 | 固定原候选／目标对照模型次数、有效动作、保存与失败位置 |
| P1：生产者精简 | 同次取证复用、正文去重、缩短 schema；保持原双表协议 | 去除新增任务提示和预编排；用途 UNKNOWN 不触发补分类 | 来源／落地／唯一性不退化；比较实际消费可用率及生产 token |
| P1：验收降本 | 生产者新规则定向实验，稳定阶段抽样；QC 差异候选先用确定性证据筛选，必要项再送模型 | 独立审核关注真实图／动作和待决关系，减少重复上下文 | 不漏必审关系、不变更质量语义；按有效审核及有效接纳计成本 |
| P2：扩大验证 | 修复冻结并通过原故障验证后，再按另行授权做有界真实批次 | 从成功与失败分类归纳通用策略，不写死站点答案 | 保存率、完整审核率、批次接纳率、每条成本及跨站适用范围分别报告 |

“放宽检查”只适用于已有证据证明是误阻断的实现条件。不能整体放宽同帧、真实派发、动作效果、来源和重复等事实检查。模型运行时不自行关闭宿主校验。

差异 QC 可先通过索引和确定性相似度筛选需要模型裁决的关系，避免无差别重复发送历史材料；这只是待验证的工程方向。不能简单删除历史比较、减少必审项，或直接断言某个 token 节省比例。

## 8. 实施顺序、协作与验收目标

1. 由现有消费者会话完成 R09 原账诊断。只读对账，不重发已有 UNKNOWN，不追加实采；本会话仅整理文档，避免并发修改同一执行链。
2. 分开落实工程修复和 Agent 优化：优先执行前稳定性、QC 请求期限／租约／异常归属、可信前缀保存与派生叙述。每项都用对应原故障补验证，不能只增加正常流程夹具。
3. 通过离线验证后冻结实际执行版本。保留原工程、原账和原失败，真实验证按后续明确范围执行；不能借新账绕过原未决请求。
4. 精简生产者及其实验验收，不再为用途分类或消费者预编排增加成本。其余机械门禁和交付 QC 按适用策略执行。
5. 形成稳定的“网页候选 → 实际规划执行 → 可信片段保存 → 独立 QC／批次接纳”闭环，再扩大供给与消费规模。

整体目标是提高单位时间、单位 token 能形成的真实有效交付片段数量。它不是用途字段填满、生产者页面数增加、单个模型返回成功或离线用例数量增加。

下一阶段至少分别统计：原尝试数、零派发失败、有效操作分布、正式保存片段、程序失败、AI 应审与已审、PASS／FAIL／UNKNOWN、有效批次接纳、发布和客户验收。生产、规划、取证、后处理及 QC 的 token／耗时分开，保留未知费用；每条正式保存成本和每条有效接纳成本使用不同分母。分母为零时写未定义。
