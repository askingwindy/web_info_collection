# 两条样例

已交付的真实样本，中文站点、带完整界面树，是产出格式的目标形态。

| 样本 | 站点 | 步数 | 动作构成 |
|---|---|---:|---|
| `Web_sample_000017` | 中国外汇交易中心 | 8 | click×4 / scroll×2 / type×1 / complete×1 |
| `Web_sample_000018` | CSDN | 9 | scroll×5 / click×2 / type×1 / complete×1 |

每条的结构：`annotation.json` 加 `images/step_NNN.png`（第 NNN 步操作前的界面，末步截图同时是终态图）加 `ui_tree/step_NNN.json`（与同名截图同一时刻、同一像素坐标系）。

看四处：

1. 顶层的 `task_instruction` 写得多具体；`final_result` 描述最终界面，`completion_judgement` 写凭界面上的什么判定任务完成。
2. 任一步的 `action`：`coordinate` 落在 `target_bbox` 内，`target_element_id` 指向同步界面树里的元素，`target_text` 是界面原文。
3. `precondition`、`expected_result`、`step_result`、`next_step_rationale` 的粒度——具体到页面上的元素和文字，但不引用界面上看不到的东西。人工核对读的就是这几个字段。
4. 对着 `images/` 把 `step_N.png` 和 `step_N+1.png` 看一遍，确认该步动作确实能解释两张图的差异。

两处别照抄：

- `task_type` 是空数组，需求书 §4 要求必填 1–3 个枚举值。
- `trajectory_source.source_type` 是 `human`（这两条来自人工操作的网页数据）。浏览器自动化产出的要如实写 `agent`（配方由人工设计的写 `human_agent_hybrid`），`data_type` 用属于这条线的新编号，并按需求书 §3 交《合成方式说明》。
