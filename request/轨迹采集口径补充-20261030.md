## 1. 采集单位

主要采集单位是连续、真实、可理解的5–8个有效操作组成的轨迹或轨迹片段，不强制每条完成一个完整业务流程。可记录更长的原始连续执行，再按有效操作切成多个样本；10个有效操作可分为两个各5操作的片段。

同一页面可以产生多条符合本口径的轨迹或片段，不再以“每个实际任务页面最多一条”直接限制供给。页面、站点、任务、原始连续执行和交付片段分别标识；同页不等于同样本。

原先“20万条至少需要20万个任务页”的推算撤回。站点容量要按实际可生成的操作序列、可切段数量和全局重复指标测量。

## 2. 哪些操作可以组成轨迹

| 用户例子 | 更新后的理解 |
| --- | --- |
| 工具从首页进入、选择菜单、输入、点击、继续输入和点击 | 导航和菜单操作可以纳入；一条可以含多轮操作，不要求只记录最后的计算按钮 |
| 已出结果后清空、再次输入、再操作 | 属于可采的后续实际操作，不能仅因第一轮已有结果就截断，也不能因复用同一控件自动判作凑步 |
| 汇丰汇率“中国到韩国”“韩国到美国”分别5步 | 不同货币对/业务参数的实际切换可构成候选轨迹，不因同属汇率转换就预先一律排除 |
| 购物页面滑动与浏览，另一页面采用相近方式浏览 | 是允许的任务类型；相似路径是否超标按全局重复指标核算，不要求每条都是全新业务 |
| 百科点击目录、浏览、滑动、再点击与滑动 | 是允许的内容浏览轨迹，不要求存在输入表单或数值业务终态 |
| 小游戏、计算器等 | 按真实有效操作和页面状态采集，可作为5–8步片段；不强制完成整局游戏或整个计算流程 |

参数更换可产生真实操作和页面状态变化。输入、清空、切换选项等实际操作可被记录；是否重复由实际数据和约定指标判断。不能仅凭参数变化、动作骨架相同或任务族相同否决整批候选，新增操作仍须有实际记录。

## 3. 有效步数：用户已明确按实际动作计

用户明确选择“按实际点击、滚动等动作计步”。

- 点击、输入、清空对应的真实按键、选择、滚动等按实际执行记录计数。
- “浏览/阅读”描述任务内容或点击/滚动后的页面状态；没有页面操作的静态停留不额外计为一个有效动作。
- 等待和样本结束确认不增加有效步数；不能把同一动作的叙述、截图或静态阅读另算一步。
- 多轮真实操作允许出现相同控件和相似动作。是否应保留要看实际顺序与状态，不能把整段序列压成一次“初值到最终值”而丢掉用户允许的中间过程。

## 4. 不强制完整业务，但记录实际片段末状态

业务目标与片段结束状态分开。片段末帧仍须保存真实、同步、可辨认的页面状态；未完成整个业务时据实标明，不能把“第5步片段结束”写成整个业务成功。

前段可以在业务中间状态结束，后段可以从这一实际状态继续；不要求每段都重新从首页开始。后段需说明初始状态来自哪次连续执行、哪个边界，以及必要的上下文/重现方式。现有complete、completion_status、final_result等字段应在后续协议中明确表达片段结束，不能借用旧完整任务语义伪称已完成全部业务。

这改变了“只能在出现业务结果后结束”“必须有具体数值结果才能采”“第一次结果出现后立即停止”等旧规划/编译解释；这些旧检查需要逐项对齐，不能据旧限制推断站点没有容量。

## 5. 连续切段及共享边界：用户已确认单独统计

一个连续原执行有10个有效动作、11个对应页面状态时，可分为：

- 片段A：动作1–5，状态0–5。
- 片段B：动作6–10，状态5–10。
- 状态5是A的末状态，也是B的起始状态；其同一张原始PNG及同步树可以被两段引用。

用户明确选择“切段共享帧单独统计”。只有可证明来自同一原始连续执行、切段点相同的边界共享属于该例外；应记录原执行ID、原动作区间、片段序号、边界状态ID和原件摘要，单列共享帧数量与关联片段。不把这类已识别边界共享计成普通跨样本截图重复。

其他独立执行、非边界的相同截图，以及其他重复判定仍按更新后冻结的指标统计；不能仅凭图片一样就声称是切段边界。共享原件保持原字节，不改图来规避重复检查。切段来自同一连续真实记录，不拼接多个失败/中断执行，也不拿历史失败补造新完整轨迹。

一次原始执行切成两个样本，不得变成两次真实浏览器尝试；两个片段是否计为有效交付样本由其各自QC及全局指标决定。编号、生产原尝试到片段的一对多映射、来源收据、共享池和QC回写都需要表达这一关系。

## 6. 重复度是集合指标

用户保留“低于我们的重复度指标即可”，本补充不更改原约定的近重复上限0.1%、总体类目限制或客户验收目标。对相似购物浏览、货币对切换、同工具多轮操作等，记录实际候选与检测结果，按明确的总体口径计算，不预设必须每条全新业务或所有相似度命中都立即淘汰。

普通近重复、已确认切段共享边界、未裁决项分别报告；不能把样本重复比例和样本对比例混用。新增边界例外只作用于有来源证明的边界共享，不取消其他重复检测，也不把所有共享页面静态状态一概豁免。

任务/作业完全相同的重复派发和同一原件重复计数仍需拦截；这一幂等要求不等于“同页只能一条”。

## 8. 规划判据与阿里云例子（用户进一步明确）

每一步的动作定义直接使用[附件B：动作空间与坐标系](web操作采集需求/附件B-动作空间与坐标系.md)中的Web动作及参数合同，不由规划器另造一套有效动作要求。按已确认口径，实际点击、滚动、输入、选择、返回、打开网址等记录动作计步；wait、complete及无操作的静态阅读不额外计步。

单页面或跨页面规划的核心判据为：

1. 每个动作属于需求允许的Web动作，作用于实际页面并符合该动作的参数/目标要求。
2. 满足5步要求，主要以5–8个实际操作形成片段；更长的连续执行可按前述规则分段。
3. 实际候选/产物的重复度低于约定指标，切段共享边界单列。

不增加“每一步对某个唯一业务目标不可替代”“必须出现数值结果”“单页面规划必须完整”或“一个业务只能生成一条”的规划门槛。动作说明可以解释当前操作，不承担证明业务必要性的额外审批职责。业务尚未完成不构成重规划或拒绝片段的理由。

阿里云官方页面用于说明这种规划方式：产品、介绍/文档、配置选择、购买入口等不同页面与控件，可以形成多种实际点击、滚动、选择和输入的路径组合。GLM根据真实观察列出路径候选，工程核对动作合法性、执行并按5–8步组织片段，QC核算实际质量与重复度。这里记录的是用户提出的组合方向；本轮没有访问阿里云，不宣称已验证其具体页面、控件或产量。

规划判据与交付文件检查分别执行。原始截图/树、字段、坐标、语言、来源及其他未被本补充修改的交付要求继续按需求检查；不能把这些检查扩张为新增的完整业务终态要求。当前P0代码中业务必要性、首次结果后停止及同类路径拦截等限制，需按后继规则对齐，本次仍只修改文档。
