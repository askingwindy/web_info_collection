## 按站点统计与多进程启动（2026-11-11）

新增 `webcollect.site_inventory` 与 `webcollect.site_workers`，不拆每站 SQLite，不改 Table1／Table2 结构或消费者 claim/snapshot 契约。站点选择器接受稳定的 `applications.id`、主 host 或已登记 alias host；内部派发始终使用 `applications.id`，不是交付展示编号 `S000001`。

```sh
export PYTHONPATH=projects/code:projects/site-planner:projects/quality-inspector
PY=projects/code/.venv/bin/python

# 只读统计全部站点，也可重复加 --site 限定站点。
$PY -B -m webcollect.site_inventory --scope database/sqllite/prod/scope.json

# 两个已确认站点各累计 1000 条 NEW，共 50 个生产者进程：每站 25 个。
$PY -B -m webcollect.site_workers producer \
  --scope database/sqllite/prod/scope.json \
  --site muxtly.com --site zh.wikipedia.org \
  --pages-per-site 1000 --workers 50 --launch

# 领取一个站点的全部当前 pending，共 100 个消费者进程。
$PY -B -m webcollect.site_workers consumer \
  --scope database/sqllite/prod/scope.json --site muxtly.com \
  --workers 100 --all-pending --launch

# 两个站点共 30 个消费者进程：每站 15 个。
$PY -B -m webcollect.site_workers consumer \
  --scope database/sqllite/prod/scope.json \
  --site muxtly.com --site zh.wikipedia.org \
  --workers 30 --all-pending --launch
```

WebCollect 是中文网页操作轨迹的采集、审核和交付工程。它用 Playwright 执行真实页面操作，保存原始截图、同步界面树、动作与终态证据，再由独立质检器检查实际交付文件，输出可追溯的客户数据包。

仓库包含三个 Python 程序：`site_planner` 负责来源发现与页面能力库存，`webcollect` 负责任务规划、采集和导出，`quality_inspector` 负责独立质检、AI/人工审核接入及交付门禁。

## 主流程

```mermaid
flowchart LR
    A[生产者发现入口] --> B[GET 最终 2xx]
    B --> C[本地 SQLite 候选池]
    C --> D[消费者独占领取并新建页面会话]
    D --> E[同页 ReAct 执行、原始证据和待审保存]
    E --> F[按 QC 策略冻结交接收据和抽样计划]
    F --> K[独立 QC 入队和全量机械检查]
    K --> H[累计有效集合与跨包检查]
    H --> G[显式AI和人工抽检]
    G --> I[payload检查与final封包复验]
    I --> J[ZIP及校验文件]
```

`webcollect.task_generation.execute()` 编排预检、发布、采集、候选导出；传入显式 `qc_policy` 时冻结后续 QC 输入。`quality_inspector.delivery_pipeline` 承接审核与封包。采集入口只保存 `collected_pending_review`；审核通过、正式发布和客户验收分别记录。默认 `quality_inspector check` 要求完整语义证据，抽检必须显式传入冻结计划。

`generate --workflow-specs` 可消费绑定原始PNG/树的显式DOM工作流提案，覆盖已观察控件的导航查询、非form工具与DOM交互；无需先执行完整流程。它与表单策略共用 `execute`，不支持的动态目标/画布游戏仍显式拒绝。终态滚动可用 `webcollect-live-completion-view-1` 在本次实际截断结果上核验必要性；旧准入绑定仍按原协议验证。两者均不授予质量通过。
