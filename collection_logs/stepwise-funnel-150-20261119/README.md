# Wiki、Muxtly、故宫策略 3 复采

本轮固定三站各 50 个有原始 GET 证据的入口，使用 20 个消费者进程。名单排除了上一批全部 150 个候选及其实际落地，也排除了已有 claim 或历史处置的候选。原批第三段收尾时共有 117 页已领、110 次正式尝试、3 份保存待审，另有 33 页未领。

## 本轮修改

- 决策发出浏览器动作前，按当前原帧检查页面名、前置条件及上一步结果中的引文。回写可读取末帧原文及标点，最多修正一次。独立判定保留一次，仍要求目标具体、任务完成、证据支持且轨迹没有冗余和错配。
- 阅读时拦截在同一业务视图重复的同向滚动及回顶部动作。短任务缺少可自然延伸的事实时收口留证。工资计算器可正常进入，支付、结算页面仍然拦截。
- 按原 attempt 与作业身份查询模型用量，原会话的请求上限、账户绑定和未决记录继续生效。固定轮遇到重复的页级程序故障会停领并让在途页收尾。按原请求结算取消时已在途的响应，并封存已执行步骤。只读 DOM 观察窗口调整为 30 秒。
- 漏斗独立记录完成声明、回写、独立判定和正式保存。缺少终态的中断样本仅统计可与派发原件逐项核对的动作下限。

本地六链和真实历史原件回放见 [验证数据](verification.json)。固定名单见 [选页记录](selection.json)。本轮使用原消费者入口和共享账本，原图、完整模型请求、数据库及账号信息保存在本机。

首段发现首帧决策被拒后，即使浏览器尚未执行动作，宿主也会要求填写上一步结果。20 个进程均完成手头页并以 0 退出。4 个样本的 40 次错误驳回在原始决策回放中均获修正。接续条件改为确有一笔实际动作等待回填，并向模型明确提示当前状态。原来已领取的页面保持原结果。[修复回执](boundary-repair.json)
