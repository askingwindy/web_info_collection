# M1 字段、动作与工程规则

规则版本：1.0.0；适用范围：WebCollect 浏览器自动化轨迹。需求依据依次为需求澄清记录、需求书及附件、原始样例。原始样例不是可直接照抄的合格基线。

## 数据与版本

机器定义位于 `projects/code/webcollect/schemas/`：annotation、ui_tree、metadata-row、manifest 四份 JSON Schema。新增 manifest 仅用于批次追踪，不放入单个样本目录。所有对象的交付字段类型以附件为准；annotation、动作、工具调用及界面树禁止未知字段，防止混入选择器和调试状态。批次清单允许保留扩展的追踪信息。

- `terminal_type=Web`，`app_info.ui_language=zh`。task_type 为需求书规定的 14 类，1–3 项且不重复。
- `source_type` 如实写 agent 或 human_agent_hybrid。`action_space=unified_gui_v4`。`data_type=webcollect_agent_v1` 是本项目内部编号，尚未取得外部确认，不冒用参考样例的 T6。
- 允许未知值为空的字段：device_model、os_name、os_version、app_version、timestamp、无控件动作的目标字段，以及无输入动作的 input_text。error 在成功时为 `""`，无异常时 exception_evidence 为 `[]`。
- 叙述字段必须为非空且非纯空白字符串。Web 每步必须有界面树，不能套用通用附件中其他来源允许空树的例外。
- 所有坐标及 step_id 必须为 JSON 整数，布尔值和 `200.0` 不接受为整数。像素点使用 `0 <= x < width`、`0 <= y < height`；框使用 `[left, top, right, bottom]`，右下边界不包含在框内，允许框的 right/bottom 等于图像宽高。
- 元素类型暂不封闭枚举，以兼容真实 DOM/无障碍角色；state 使用附件规定枚举。元素须可见，框裁剪至视口，父引用存在且无环。

## 动作约定

| 动作 | 工具参数 | action 对应约束 |
|---|---|---|
| click / double_click / right_click | x, y | coordinate 与参数一致；引用控件；提供目标框且触点在框内 |
| type | text | coordinate=[]；引用可输入控件；input_text=text；不隐含点击聚焦 |
| hotkey | keys，非空且不重复的字符串数组 | coordinate=[]；不引用控件；target_text 写按键名；input_text 用 + 连接 keys |
| scroll | x, y, direction | coordinate 与参数一致；direction 为 up/down/left/right；不引用控件 |
| drag | x, y, end_x, end_y | 引用起点控件；起点在目标框内；end_coordinate 与终点参数一致且在视口内 |
| back | 无参数，{} | coordinate=[]；不引用控件 |
| open_url | url，HTTP(S) 地址 | coordinate=[]；不引用控件；初始导航如发生在轨迹中也必须显式记录 |
| select | x, y, option | 引用下拉控件；提供目标框和触点；option 为非空字符串 |
| wait | 无参数，{} | coordinate=[]；不引用控件；不计有效步 |
| complete | status | 仅末步使用，交付格式要求 status=success；coordinate=[]；不引用控件；不计有效步 |

控件动作必须提供 target_element_id、target_bbox，target_text 与同步树中的 text 一致；控件本身没有名称时允许空字符串，但是否适合交付须语义核验。target_control_type 可省略；提供时须与树一致。非控件动作 target_element_id、target_text 为空且省略 target_bbox、target_control_type；hotkey 的按键名例外如表。只有 drag 可以提供 end_coordinate。输入按键之外的动作 input_text 为空。

工具参数不能增加 duration、selector、XPath 等字段。适配层的滚动距离、等待上限等执行设置由 M2 在原始证据与合成方式说明记录，不修改统一动作参数。timestamp 未取得时留空，提供时必须为带时区 ISO 8601。

总步骤数等于 steps 长度；有效步数排除 wait、complete，其余 Web 显式动作计入。有效步数不足 5 时必须 `short_flow=true` 并提供非空 short_flow_reason；达到 5 步不能错误标为短流程。短流程 2% 限制在正式全集统计执行。

completion_status 允许 success、controlled_exception，failed 不交付；每步 tool_result 必须成功且 error 为空。有后继截图时必须记录 screen_changed。controlled_exception 是否符合任务，由任务规划和实际终态证据判断，不能仅凭标签通过；其 complete 仍遵循需求书 status=success 的交付格式，存在矛盾或无法完成的样本不得靠改标签交付。

## 编号、路径与追踪

- site_id：S000001；sample_id：S000001_sample_000001；batch_id：B20261021_001。样本序号按站点跨批递增，超过六位时扩展样本序号位数；站点编号不超过六位。
- SQLite 注册表维护精确 URI 到站点编号的映射、类目、样本性质、下一样本号及已分配批次/样本。不同 URI 可独立编号；不自动去除 query 或合并 URI，不因此豁免去重。
- 使用事务和唯一键避免并发重复。失败分配不回收，保留空号；样本内 step_id 和图片命名仍须连续。禁止手工删除注册表记录来复用编号。
- 所有同一生产线的批次必须指定同一注册表。CLI 默认使用输出父目录的 registry.sqlite3；跨父目录时必须显式传 --registry。联调与正式生产分开保存注册表，正式全局唯一性在后续全量检查再确认。
- 批次清单记录 batch_id、sample_kind、program_version、rule_version、samples、sites；站点映射含 site_id、uri、site_category。程序版本优先记录 Git 提交号，脏工作区加 +dirty；首次提交前记录版本号 +uncommitted，不伪造提交号。
- 样本目录仅含 annotation.json、images/step_NNN.png、ui_tree/step_NNN.json。step_NNN 为本步操作前状态；末步 complete 的截图就是 final_state_image。禁止路径穿越及通过符号链接访问样本外文件。
- 样本生成、metadata 和报告均拒绝覆盖。生成中途失败保留现场，清理时先确认目录来源，重新生成使用新目录和新编号。

## 联调、检查与后续接口

scaffold 只生成合成联调样本：清单 sample_kind=integration，任务文本含联调标识，图片带 SYNTHETIC / NOT FOR DELIVERY 水印。合成图片与树仅用于接口检查，不声称语义一致；在任何统计中都不计入真实合格量。

检查报告输出 structural_pass、delivery_ready、issues、pending_checks、total_steps、effective_steps、rule_version。issues 每项含 code、path、message。M1 的 delivery_ready 固定 false；通过结构检查仍须语义及人工核验。integration 数据、标记为联调的任务和 integration 目录路径不能通过 delivery 模式；真实声明本身不证明真实性。

metadata.csv 列顺序严格为：sample_id, site_id, site_category, app_name, task_type, task_instruction, steps, screen_resolution, completion_status, actions, bytes。task_type、screen_resolution、actions 使用 JSON 数组字符串；actions 按步骤保留动作序列（含 wait/complete），steps 是总步数。bytes 为该样本所有文件字节数之和，不包含批次文件。CSV 使用 UTF-8，遵循标准引号和换行转义。

M3/M4 后续检查输出延续 code/path/message 和规则版本，不在 M1 生成虚假的通过结果：

| 检查 | 输入与输出约定 |
|---|---|
| 语义审查 | 样本及同步采集证据 → sample_id、step_id、判定、图/树引用、原因、审查者或模型/提示词版本 |
| 去重候选 | 跨批样本索引 → sample_id_a、sample_id_b、route、score、阈值、decision、evidence、规则版本；未裁决数必须为 0 |
| 全集分布 | 通过质检及去重的保留清单 → 总量、站点、类目、任务类型、有效步数、短流程和视口分布及违规项 |

四路阈值沿用需求：任意跨样本截图 SHA-256 相同；完整“动作类型、控件文字、页面名”序列哈希相同；首末帧 dHash 距离同时 <=4；任务 SimHash 距离 <=3。M4 实现时固定具体编码和图像处理参数并记录规则版本，M1 不声称已完成去重算法。

正式全集目标：20 万条；单类目 <=20%；短流程 <=2%；视口规格 <=3；已知重复剔除且未裁决候选为 0。试验联调批次不适用正式分布验收。语义中的中文占比 >=70%、导航控件中文、标注简体中文与真实终态均不能由“含中文字符”替代。
