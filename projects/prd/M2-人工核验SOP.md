## 2. 每条任务只做三件事

### 第一步：读上方任务

先看“这条任务要做什么”和“完成时应该看到”。这两项说明本条目标及完成标准，逐步看图和最终判断时都能看到。需要完整字段时点击“完整任务标注”。

首次打开网页可能是任务建立前的环境准备；不能只因为步骤里没有首次导航就判跳步。任务请求入口、登记URI和实际首帧URL也可能不同，按真实来源记录核对。

### 第二步：逐步核对前后图

左图是动作前，右图是动作后；最后一步只展示最终页面。动作栏用中文说明本步点击、输入或滚动。看控件文字、目标红框、触点和前后变化是否说得通：本步动作能解释下一张图吗？有没有漏记点击、焦点切换、导航、关闭弹窗或滚动？

- **这步正常，继续**：本人确认这一步没有发现问题后点击；页面进入下一步。最后一张使用“末图符合预期”。
- **发现问题**：记录具体步骤和实际看到的错误，点击“保存问题并继续”。例如“第3步红框指向另一按钮，右图也没有预期变化”。
- **看不清 / 不确定**：说明缺少什么或哪里看不清，保存后可继续；不需要猜答案。

可以点击图片看原尺寸，用上方步骤编号、“上一步”或键盘左右键往返。仅切换图片不等于确认该步正常。红框和红点只辅助定位，不能代替看实际控件是否可见、是否被遮住；可关闭叠加查看原图。

当前截图为1280×720原图空间，缩放后的屏幕坐标不能直接比较。需要细查时展开“查看控件、同步树和原始记录”，核对树中目标文字、边界、触点和工具参数。`type`等动作可合法没有触点，滚动、等待、返回和完成可无控件目标；不能把合法空值判缺失。

最后一张要逐项核对真实数值、单位、精度、选项、文章或章节是否满足任务，不能只认“成功”文字或脚本断言。有效动作排除`wait`和`complete`，并检查有没有无关滚动、反复输入或完成后的多余动作凑步。当前20条每条至少5个有效操作，无短流程。

### 第三步：回答五个中文问题

看完后进入“给本条结论”，分别回答：

| 页面问题 | 判断重点 |
|---|---|
| 图、控件和动作是否对应？ | 图树、控件原文、目标、触点与相邻状态一致，无漏记操作 |
| 最后真的完成任务了吗？ | 必要步骤连续，最终页面符合完整目标，无凑步或虚构历史 |
| 页面和说明是否符合中文要求？ | 叙述为完整简体中文，控件名符合原文，实际可见中文至少70% |
| 是否符合来源和隐私要求？ | 实际来源、测试输入及个人/账户内容符合声明 |
| 与其他任务有实质区别吗？ | 目标和路径有实质差异，不只是换关键词、数值或网址 |

每项选“符合”“有问题”或“不确定 / 待核对”。点击“符合”是本人的明确确认，系统会记录对应步骤和判断说明；可补充实际依据。发现问题时写清第几步、看见什么、哪里不符合。页面提供“对比本批其他任务”，可辅助判断任务差异。

全部步骤尚未明确核对时，页面会提醒返回看图；仍可先保存已经发现的问题。可见中文的DOM比例只是初筛，图片/画布和简繁判断要看实际图像。看不清就保留待核对，不编造百分比。

最后点击“保存本条，下一条”。左侧进度表示已保存完整判断的任务数量，包含明确发现问题的任务，**不是合格数**。待核对项、问题和未完成部分都会保留。

## 3. 自动保存、备份和恢复

页面会将逐步判断、五项回答、问题说明和当前位置保存在当前浏览器，右上角显示“已自动保存”和时间。再次使用同一浏览器打开相同审核包时恢复进度。

自动保存属于浏览器本地存储，不是写回候选原件。换浏览器、清理网站数据或本地存储不可用时，不能依赖它恢复；若显示“无法自动保存，请导出备份”，应及时点击右上角“导出审核记录”。

导出文件名为`qc-human-review-<时间>.json`，兼作审核记录和可恢复备份；未完成项仍保持待核对。建议每完成一组任务就导出一次，并保留不同时间的文件。

继续审核时点击“恢复备份”，选择之前导出的JSON。审核台核对当前包、样本、标注和图树的绑定身份；不同版本、旧三项核验记录、AI或其他来源记录不能直接套用。不要手工改JSON中的姓名、来源、SHA或状态来绕过校验。

当前包的单人标识由页面配置为`hemiao`、来源为人工；这用于记录实际操作者，不是身份认证。自动保存、打开图片和导出成功都不证明本人已经认真核对，只有实际执行的判断才可作为人工记录。

## 4. 最后核对交付资料

点击左下角“最后核对交付资料”。新版已提供独立页面和原文档链接，**不需要手工编辑JSON**。打开资料，核对两项：

1. **交付资料是否完整、与实际内容一致？** 阅读README、字段/来源/合成说明、候选清单及各批`manifest/metadata/qc_report`，核对数量、去重、拒收、分布、实际AI与人工覆盖和未执行项。
2. **站点与类目归属是否真实、一致？** 对照真实来源、完整URI及站点ID，检查类目使用一致业务大类，没有重复编号或人为拆标签来降低占比。

分别选择符合、有问题或待核对，并记录依据。打开链接只说明进入过资料，不等于已经读完或通过。资料版本警告、内容缺失或尚未检查时保持待核对。

包审核和20条样本审核分别统计，不能互相代替。资料未完成时仍能导出当前样本进度；导出会如实保留`package_review`的待核对状态。

## 5. 导出后重新检查

审核结束或阶段性保存后，将导出文件路径交给项目负责人。按`projects/quality-inspector/README.md`将记录通过`--reviews`输入独立质检，输出到新的包外报告目录。审核记录仍使用`qc-review-1`及`qc-package-review-1`，保留原baseline/profile、标注、图树与包文件SHA。

图树或标注有修改、问题修复或重采后，应重新审核受影响证据。原PASS不会因为曾导入成功就自动成为新文件的结论；明确FAIL与疑点必须保留定位并闭环。
