## 3. 每条样本按此顺序检查

### 3.1 先读任务与初态

记下`sample_id`。在候选目录找到`<批次>/samples/<sample_id>/annotation.json`，阅读`task_instruction`、`task_type`、`final_result`、`completion_judgement`及完整步骤。当前页面展示逐步动作和结果，未提供完整任务标注的直接入口，需同时打开这份文件。

确认目标具体、能从结果判断完成，第一张图对应实际初态。首次导航可以作为任务建立前的环境准备单独存档，不能仅因steps里没有最初打开网页就判跳步。登记`site_uri`、任务请求入口与实际首帧URL可能不同，按`docs/实际入口与标注来源.json`核对真实记录，不能虚构中间导航。

当前20条由B4新采10条和历史复审10条组成；历史部分有已披露的四处AI离线字段修订。审核当前标注并查看修订来源，不能把历史捕获写成当前程序重采。

### 3.2 逐张核对“操作前图 → 本步动作 → 下一张图”

在页面展开每个“步骤”，看真实PNG、动作JSON和`step_result`；点击“打开同步界面树”核对树。每张截图是本步操作前状态，第N步结果通常在第N+1张核对。

点击、输入、选择、按键、滚动、返回是否能解释下一张的变化？有没有漏掉点击、焦点切换、导航、关闭弹窗或滚动？输入文字、选择值和真实后继状态是否一致？不要把无关广告变化当成任务成功，也不要因无关广告变化单独判失败。

自定义下拉和日历按实际展开及选择动作检查；原生select按已声明的原语映射核查，不额外要求操作系统菜单截图。透明单选框可由真实可见的关联label操作，须核对关联状态。

### 3.3 核对图、树、目标与坐标

对控件动作，按`action.target_element_id`在同步树中找到对象，核对原文、类型、`bbox`、可见和可用状态是否对应截图里的控件；文字可来自真实关联label，不能编造。

当前页面没有目标框或触点叠加按钮。将动作JSON的`target_bbox`、`coordinate`与原图和树比较；图片可能缩放，坐标使用原图1280×720空间，不能拿屏幕缩放后的坐标直接比较。

- 点击等有触点动作：触点应在视口内、落在正确可见控件内，与真实工具参数对应。
- `type`等无触点动作允许`coordinate=[]`；输入文字应与工具参数及下一状态一致。
- `scroll/wait/back/open_url/complete`等动作按规则可无控件目标，按键动作按其例外处理。不要把合法空值判缺失。
- 控件被遮罩或固定页头遮住、引用错位、截图和树不对应时写明定位；证据不足仍待审。

需要原始工具参数、截图同步或断言证据时，由负责人按`selection-provenance.json`和原捕获来源定位原批次`evidence/<sample_id>/step_NNN.json`。当前页面没有断言直达按钮，当前候选目录也不等于完整原始采集证据目录。

### 3.4 检查必要操作与终态

有效步排除`wait`和`complete`。当前20条每条至少5个有效操作、无短流程；仍需检查是否通过无关滚动、反复输入或目标已满足后的动作凑步。往返、比较和设置可能是任务本身要求，应按完整目标判断。

最后一步应为`complete`，`final_state_image`指向该步截图。逐项核对任务、末图、终态说明及必要原始断言：数值、单位、精度、页面、章节和可读正文是否满足？不能只看“成功”、脚本`passed=true`或旧AI PASS。完成叙述不能声称实际未发生的导航或操作。

当前包有正文准备和广告预检来源；须看真实图证及发生的动作，不能用`body_ready`或预检路线字段自证正文可读、广告识别准确。新增准备动作与计划复用动作不能重复计数。

### 3.5 检查语言、隐私和任务实质差异

任务与叙述应为简体中文、完整且符合可见事实；控件和专名按原文引用，不伪造翻译。叙述不应暴露元素编号、选择器或采集过程话术；合法动作和树中的编号不属于禁止范围。

可见中文比例至少70%，导航和控件为中文；可见DOM初筛不能覆盖图片、画布或简繁判断。临界或无法判断时写清缺少什么证据，不编造精确比例。

对照来源和账号声明检查截图是否包含未说明的个人或账户信息；当前使用公开页面、隔离上下文及测试输入。也需与其他候选比较目标和操作路径，不能仅换关键词、URI或数值就认定任务实质不同。四路190对零候选是程序筛查结果，不能替代语义判断。

## 4. 填写页面实际提供的五项结论

每条“视觉与语义审核”有五个下拉框与理由框：

| 页面字段 | 人工应确认的内容 |
|---|---|
| `visual_alignment` | 图、树、控件原文、引用、坐标、动作与相邻状态一致，轨迹连续 |
| `terminal_semantics` | 任务、必要动作、逐步结果和完整终态一致，无凑步或虚构历史 |
| `language` | 简体叙述、可见中文比例、导航控件及文本完整性符合要求 |
| `privacy` | 来源、测试输入和账号声明与实际图证一致，信息处理符合要求 |
| `substantive_difference` | 与其他候选相比，目标和路径存在实质差异 |

每项选择`PASS`、`FAIL`或`REVIEW_REQUIRED`。PASS和FAIL均须写具体截图/步骤和理由；没有看完、材料打不开或证据不足则保持REVIEW_REQUIRED。页面没有“三项全勾”或整条通过按钮。整条人工完成须五项都实际判断且有依据；发现FAIL后仍保留问题，不能靠其他PASS抵消。

理由建议写法：`样本；步骤及相邻步骤；字段；实际图/树所见；任务或规则依据；结论；需要修正或补充的内容`。不要只写“没问题”或“不对”，也不要把本SOP当作真实审核结论。

## 5. 导出与保存

1. 每条填写后切换样本，页面会把当前五项写入页面内存；导出前也会保存当前项。
2. 点击“导出质检审核记录”，下载默认名为`qc-review.json`。记录实际路径；浏览器可能添加序号。
3. 导出包含全部20条，未完成的项保持待审。可以分批导出，每轮保留独立原文件并说明本轮覆盖范围。
4. **页面只保存在内存，不自动落盘；刷新、关闭或重新打开都会丢失尚未导出的填写。页面没有导入或恢复按钮。** 分批审核后需由负责人合并实际记录并核对，不能声称重新打开能续接。
5. 将导出文件路径、当前候选路径、实际审核者、覆盖范围及待处理问题交回项目负责人。无需重新访问网站或重放任务；需求澄清已经取消验收时的网站重跑要求。

导出为`schema_version=qc-review-1`；样本记录含基准、标注、全部图树SHA、真实`reviewer/provenance`和五项状态理由。当前页面不记录逐步访问计数或逐条审核时间，不能用导出成功证明已看完137帧。

## 6. 包内文档与站点类目审核

样本五项之外，导出还含`package_review`，其schema为`qc-package-review-1`，绑定当前完整包文件SHA、baseline及profile。**当前页面没有文档审核表单，导出会保留这一部分的空白审核者和默认待审；页面上20条填完不等于包内文档已审核。**

文档审核由实际人员另行完成：

1. 阅读候选`README.md`、`candidate_manifest.json`、各批次`metadata.csv/manifest.json/qc_report.md`及`docs/`中的字段、合成、来源合规、实际入口与标注来源说明。核对样本、帧、站点、类目、视口、短流程、去重、拒收和AI/人工覆盖的实际分母。README中的输入QC状态属于回填来源，最终本地结论以包外当前QC为准，不能要求回写候选造成循环。
2. 对照实际来源和轨迹判断类目是否属于一致的业务大类、站点ID与完整URI是否对应，是否人为拆标签降低单类占比。需要时核对原捕获manifest和来源映射。
3. 在**导出记录的工作副本**中，仅填写`package_review.reviewer.kind="human"`、真实`name`、`provenance.description`及两个`checks`：`delivery_documentation`和`site_category_attribution`的状态与具体理由。可由负责人协助录入，但内容须来自实际人工并由本人确认。不要修改原导出，也不要改schema、样本ID或任何SHA字段。
4. 未完成的文档项保留`REVIEW_REQUIRED`并写清缺项；实际文档审核者及过程也须如实填写。若本人只做样本审核，直接交回默认文档待审的导出，负责人另行安排文档审核，不能把该文件当作完整包验收记录。
5. 保留最初页面导出与完成文档审核后的工作副本。既有AI文档结论仍保持AI来源，不能复制后改成人工。

`package_review`两项都PASS只说明实际文档和类目审核完成，不证明20条样本已审，也不代替客户程序或全集验收。

## 7. 负责人接收、退回与收尾

负责人按`projects/quality-inspector/README.md`及当前profile流程，将实际审核记录通过`--reviews`输入独立质检，并写入**新的包外报告目录**。核对baseline、profile、样本标注、全部图树和包文件SHA及逐项状态理由；过期、缺证据或文件变化时不能沿用旧结论。导入验证不认证核验人身份，也不证明人实际认真检查。

当前流程是五项`qc-review-1`及`package_review`，不使用旧三项`M2-human-review.json`的对账命令。部分人工结果、独立文档审核或多人记录如何组合，由负责人保留每份真实来源处理，不覆盖成一份虚假的全量人工记录。

对FAIL和疑点保留原证据及定位，由采集方修复或重采并形成新的可追溯版本；人工复核修改步骤、前后链路及完整终态。图树或标注SHA变化后，原PASS不自动继承。实际人工记录可核对、20条完整人工审核及退回项闭环后，负责人再按执行书确认M2状态。

本SOP的更新不改变任何原候选、AI记录、测试证据、M2人工计数或交付状态。
