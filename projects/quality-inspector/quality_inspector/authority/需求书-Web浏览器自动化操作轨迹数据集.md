# Web 浏览器自动化操作轨迹数据集 需求书

| | |
|---|---|
| 交付量 | 20 万组，1 组 = 1 条完整操作轨迹 |
| 采集方式 | 浏览器自动化 |
| 站点 | 约 10,000 个中文网站，每站约 20 条 |
| 附件 | 附件A 字段说明 · 附件B 动作空间与坐标系 · `samples/` 两条真实样例 |
| 版本 | v3，2026-10-19。格式与验收以本书和附件为准 |

## 1. 用途与总则

训练多模态 GUI 智能体：模型每轮只看到一张当前界面截图加任务指令，输出下一个动作。所以每条数据是一串「截图 → 一个动作 → 界面上可核验的结果」。

三条总则，后面的细则都是它的展开：

- 每步截图是该步动作执行**前**的真实界面，不补拍、不合成。
- 动作要能解释界面变化：第 N 步的动作解释 `step_N.png` 到 `step_N+1.png` 的差异。
- 所有文字只引用交付物里看得见的内容（截图、动作、界面树）。选择器、URL 编码片段、DOM 节点数这类界面上看不到的东西不许出现。

## 2. 规模

| 项 | 要求 |
|---|---|
| 总量 | 20 万组 |
| 步数 | 每条 ≥5 个有效操作步。短流程标 `short_flow: true` 并写原因，这类不超过 2% |
| 站点 | 约 10,000 站、每站约 20 条。也可以大站多出一些轨迹，没有强制要求 |
| 语言 | 全部中文界面 |
| 分辨率 | 同一条样本内截图分辨率一致；全集不超过 3 种视口规格 |
| 重复率 | 近重复 ≤0.1%，见 §6 |

## 3. 交付物

```
<批次号>/
  samples/<site_id>_sample_000001/
    annotation.json
    images/step_001.png …          step_NNN.png 从 1 连续编号
    ui_tree/step_001.json …        与同名截图同一时刻、同一坐标系
  metadata.csv                     一行一条：sample_id, site_id, site_category, app_name,
                                   task_type, task_instruction, steps, screen_resolution,
                                   completion_status, actions, bytes
  qc_report.md                     本批自检报告，见 §7
  SHA256SUMS
```

`sample_id` 全集唯一；截图一律 PNG；目录里不放多余文件。

另交：

- README：内容、目录结构、分布统计（站点、类目、任务类型、步数）。
- 字段说明：可直接用附件A。
- 合成方式说明：动作怎么映射到附件B 的动作空间、坐标怎么取、界面变化怎么判定、文字字段是模板还是模型生成（模型生成的给提示词）。
- 来源与合规说明：站点清单与类目、采集方式、访问频率策略、账号与脱敏情况。
- 目标控件真值留档：每个作用于控件的步骤记 `{step_id, element_id, text, bbox}`，随批次交，不进 `samples/`。验收时用它对账标注。

## 4. 格式

字段定义见附件A，动作类型与坐标系见附件B。要点：

| 项 | 要求 |
|---|---|
| `step_N.png` | 第 N 步操作前的界面，也是第 N−1 步操作后的界面。末步截图同时是 `final_state_image` |
| 截图范围 | 当前**视口**的截图，不要整页长截图——长截图的坐标系与视口不是一套。要看页面下方内容，用 `scroll` 动作分步走 |
| 截图质量 | 文字、图标、按钮、输入框可辨认；不许有未渲染的方块字、未加载完的占位、大面积遮挡 |
| 坐标 | 截图像素整数，原点左上角。`coordinate` 必须落在 `target_bbox` 内，`target_bbox` 面积 >0 |
| `tool_call.tool_name` | 等于 `action.action_type`；`arguments` 按附件B，不塞选择器、XPath |
| `target_text` | 按界面原文写控件名。输入动作写承接输入的输入框名，按键动作写按键名，滚动/等待/返回/结束留空 |
| `task_type` | 1–3 个，取值：搜索查询、填写表单、修改设置、创建/编辑/保存文件、发送消息、预约日程、购买流程、筛选排序、上传下载、导入导出、权限配置、内容发布、数据查看、问题排查 |
| `completion_status` | `success` 或 `controlled_exception`；`failed` 的不交 |
| `tool_result.status` | 交付样本每步都是 `success` |
| 界面树 | 每步都要。元素框与可见文字必须是页面本身的真值，不许用视觉模型推断；只收视口内可见元素；`element_id` 被 `action.target_element_id` 引用 |

## 5. 站点

中文要求：

- 可见文本中文占比 ≥70%，且导航和控件名是中文。内容中文、按钮全英文的站不要——标注要引用控件原文，会做成中英混杂。
- 带多语言的站点要确保渲染的是中文版；出现英文界面的样本不交。

合规：

- 不做真实支付、转账、下单、交易。要用到这类流程只在演示环境里做。
- 需要登录的站点，用站点公开的演示账号或自己注册的测试账号。

类目覆盖要全。下面是建议，不强制按数字卡：百科与文档站、新闻资讯、企业后台与开源演示站、在线工具、开发者站与 API 文档、学习教育、政务与公共服务查询、图书影音榜单、电商浏览、交通出行查询、医疗健康科普、招聘房产分类信息、小游戏、金融股票交易等。单一类目不超过 20%。

## 6. 轨迹要求

- 每条围绕一个明确、具体、可执行、可判定的任务，不许是「浏览一下这个网站」这种。任务指令用简体中文，界面上的专有名词保留原文并用「」括起。
- 从起始页一步步真的做完，不缺关键步骤、页面跳转、弹窗处理。
- 末步是显式的最终确认步：`complete`（`status = success`），`user_goal` 写明确认最终页面，`final_result` 和 `completion_judgement` 要能对着末步截图核验。
- 不许有无效往返（两步之后界面回到原样），不许有任务完成后的多余步骤。
- 同一应用可以出多条，但任务目标、操作路径、页面状态、结果判定要有实质差异。只换关键词、只换裁切、只多几步无关操作，不算独立样本。

重复与相似控制（≤0.1%），四路判定，命中任一路算近重复：

| 路 | 判定 |
|---|---|
| 截图完全相同 | 两条样本里有 SHA-256 相同的截图。**同一个静态页面状态只许一条样本用** |
| 动作序列相同 | 逐步「动作类型 + 控件文字 + 页面名」的全序列哈希相同 |
| 首末帧相近 | 首帧与末帧的 dHash 同时 ≤4 |
| 任务文本相近 | 任务指令 SimHash 汉明距离 ≤3 |

每批给出四路的候选对数量，未裁决的必须为 0。

## 7. 验收

逐条自动检查，缺一项即不合格：

1. `annotation.json` 可解析，顶层与每步必填字段齐全非空
2. 截图数量与 `steps` 一致，命名连续，无多余文件
3. 每步 `image_path`、`ui_tree_path` 指向的文件存在
4. 同一样本截图分辨率一致，且与 `screen_resolution` 相符
5. `step_id` 从 1 连续
6. 步数 ≥5，或标了 `short_flow` 并给原因
7. 点击类动作 `coordinate` 落在 `target_bbox` 内，框面积 >0
8. `target_element_id` 在同步界面树里存在，`target_text` 与该元素文字一致
9. `tool_call.tool_name` 等于 `action_type`，参数名合规
10. 每步 `tool_result.status` 为 `success`，`completion_status` 不为 `failed`
11. 末步是 `complete`，`user_goal` 写明确认最终页面
12. `task_type` 1–3 个且在枚举内
13. 文字字段为简体中文、无截断、无裸露英文句子
14. 文字字段不出现元素编号、选择器、URL 编码片段、「DOM」「控件 N 个」
15. 文字字段不出现采集过程说法：红圈、蓝框、触点、按既定流程、回放、脚本
16. 动作能解释界面变化：相邻截图的差异与该步动作、`step_result` 对得上
17. 无真实个人信息

`qc_report.md` 含：样本数、上面 17 项的通过情况、四路候选对数、站点/类目/任务类型/步数分布、淘汰数与按原因的明细、人工抽检比例与结论。

我方验收方式：

- 全量跑我方独立实现的检查脚本，结果与你的自检不一致时以我方为准。
- 每批随机抽 2% 人工逐条看图核对，不合格率 >5% 整批退回。
- 随机抽 20 条按你的采集配置重跑，动作序列与控件定位要能复现（页面内容可因站点更新而变）。
- 按淘汰原因抽查你丢掉的样本各若干条，防止自检规则错杀。
